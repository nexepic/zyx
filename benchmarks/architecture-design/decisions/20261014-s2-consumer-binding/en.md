# S2.3 remaining consumers and imported read-side binding

The native bound program now accepts explicit caller-injected input names. It assigns independent sealed slots through nested operators, preserving aliases and scope boundaries. Mutation read-side execution refreshes input entities and invalidates stale caches before constructing its program against the current read snapshot. Expression-only calls used by procedures and mutations bind through a stack-owned SingleRow IR frame with the current immutable QueryContext. No AST clone, cached parameter value or second evaluator is introduced.

UNWIND, LOAD CSV URI evaluation and multi-row sorting now construct operator-local expression inputs and borrow a row only during expression evaluation. Static lists and directly borrowed parameters keep their existing no-copy UNWIND paths. Sort retains its single-row lazy-key rule. Borrow frames are released before expansion, downstream callbacks or stored-row movement. Parallel predicate tasks retain their own existing semantic path; mutable expression frames are not shared between tasks.

Join, OPTIONAL and UNION consume sealed child output declarations. The program retains the original output order and duplicates separately from unique slots, so runtime validation is not silently weakened. Output declaration count is bounded and charged. Native name copies reserve requested bytes before construction and account actual retained capacity. Native validation/intersection sets and shared-name pointer arrays use the query PMR resource, reference stable owning names and do not allocate duplicate strings. Existing bounded hash indexes, row buffers, DISTINCT keys, owning normalization, compatible cache merges and charged row transfers remain the explicit semantic adapters for these algorithms. Generic readers without authenticated identity keep their existing IR compatibility boundary. They are not granted native binding capabilities.

Graph traversal/path, optional expansion, local expression scopes and complex values use the existing charged semantic kernels under bound program membership and snapshot checks. This accepts their consumer integration, not a claim that every graph intermediate has become a factorized/typed value array. Full physical algorithm tuning, factorized graph intermediates, independent persistent schema epochs, process-global resources and spill remain with their original items. Procedure syntax is unchanged; supported native procedures and their existing parameter-view API are retained. Tests use supported SET/RETURN and native catalog procedure syntax; no grammar changes or new procedure families are implied.

Final current-source validation passed **591 selected tests**: 11 program/expression, eight actual native integrations, 222 runtime/selection/filter/aggregate and 350 UNWIND/sort/CSV/mutation/procedure-transaction cases. Actual native tests cover join/UNION multiplicity, OPTIONAL NULL rows, UNWIND and ordering, parameterized mutation expressions, fresh SET results, procedure result projections and parameterized CSV URI/fields. Earlier strict toy budgets, imported rows, ownership, cancellation, transaction/procedure failures and native fault contracts remain green. Fresh native correctness smoke passed 916 commands over 13 families, complete results and snapshots. Evidence is in proof.json and the matching local result directory. No full suite, comparative performance or blanket warnings-as-errors claim.

Accept S2.3. S2.4's full focused semantics matrix and S2.5 comparative gates remain pending. Public ABI and persistent format are unchanged.

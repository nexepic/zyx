# 共享 WRITE capability 表额度

原生可写文件在元数据发布前取得弱注册、同文件共享、最多 256 KiB 的 WRITE 预付额度。两种 outstanding 逻辑 ID 表及转移准备表采用相同 PMR 分配器，实际节点/头部请求消耗局部预付额度；节点转移不再分配。元数据存储保留 owner 直至表全部销毁，因此发布路径中逐节点删除不会销毁并退还进程额度。物理只读打开不预付这笔 WRITE 额度；未提供 owner 的嵌入式元数据调用仍使用永久 new/delete。

WRITE 128 MiB、数据库 256 MiB、进程 512 MiB 上限保持不变。新增空闲准入容量为每个可写文件 0.25 MiB，别名共享，不按事务或表重复预留。未用的预付容量继续计费，计数不等于 RSS。原有精确事务计费断言现在分别计算共享空闲额度与包装器/负载，包装器 16 KiB 上限不变。

当前源码 55 个受影响套件、1,419 项测试全部通过。新增测试验证别名共享、分类与生命周期、物理只读无 WRITE 额度，以及 capability 额度耗尽时在写入/代际变化/不确定结果标记前拒绝，释放后成功重试。163/4/169 个租约分配点与 4 项既有场景通过；同文件 32 轮真实崩溃恢复保持只读 SHA 不变及配额可复用，每轮恢复后文件均为 1,572,864 字节。只构建/运行选定模块，没有执行性能测试。

没有新增固定验收：22/34（64.7%）。嵌套 PropertyValue/字符串/向量、其他写入/COW/overlay 负载与工作区、维护/积压及分区算子仍待完成，没有宣称固定进度增长或对应提交/推送。

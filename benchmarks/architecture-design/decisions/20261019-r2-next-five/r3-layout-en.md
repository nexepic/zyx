# R3.1 bounded property subblock decision

This specifies one candidate before R3.2. Production keeps current ROW placement and its usable fallback. Reuse the A3 ownership/cost evidence in 20261014-a3-layout-contract; do not restore its rejected whole-container carrier. Existing row chunks, field staging, independent large-value codecs and accounting are prerequisites, not new accomplishments.

## Fixed parameters and byte layouts

Record bodies use little-endian integers; ordered B+Tree key prefixes use unsigned big endian so the existing lexicographic comparator preserves owner/group/token order. Reserved bytes are zero. Unknown modes/types, overflow, inconsistent sizes, duplicate/unsorted keys and contradictory membership fail closed. C++ sizeof/padding is never a wire encoding. Sizes below exclude existing authenticated/slotted-page framing. Allocate actual codec/page-kind/version IDs only after auditing the current registry, as part of the complete R3.2 format update before persisting any laboratory file.

| Parameter | Candidate decision |
|---|---|
| Logical group | Separate Node/Edge; B=64 consecutive IDs, group=1+(id−1)/64, slot=(id−1)%64. Labels do not control placement. One inherited candidate, no parameter sweep |
| Physical/update unit | Existing 4096-byte authenticated COW page; pack records into shared slotted pools, no dedicated page/segment per column |
| Compression | No new compression in the baseline. A column subblock is at most 64 primitive values; existing large-body compression remains independent |
| Column admission | Uniform non-NULL int64/double/bool, field present in at least 48 live slots. Mixed/sparse fields use extension/ROW. NULL is present, not missing |
| Conversion | Explicit, bounded; no automatic promotion after demotion. Type/occupancy violation demotes only the affected field, never the whole group |
| Work ceiling | Conversion ≤64 owners, ≤4096 actual owner/token memberships, ≤1 MiB planning/staging bytes, additionally capped by actual query/write account. Record including its header ≤4096 bytes and within the native slotted page usable-payload limit after framing; larger values use authenticated independent references |
| Sparse fallback | No empty column descriptor; remain ROW when total-cost admission fails or limits are exceeded. No reuse/compaction of logical IDs |

Column record: 64-byte header plus slot-indexed payload. Header offsets: magic u32 at 0; version u16 at 4; Node/Edge kind u8 at 6; scalar type u8 at 7; group ID u64 at 8; token u32 at 16; capacity u16 at 20 (=64); payload bytes u16 at 22; semantic generation u64 at 24; presence bitmap u64 at 32; NULL bitmap u64 at 40; live bitmap u64 at 48; reserved zero u64 at 56. Presence is a subset of live, NULL a subset of presence. Absent/NULL payload positions are zero. Int/double payload is 512 bytes, total 576; bool bit payload is 8 bytes, total 72. Reuse canonical scalar semantics, including exact int/double distinction and NaN rules. Authenticate group/token/kind plus page/slot generation.

Group header: 64 bytes. magic/version/kind/mode occupy 0..7, group ID 8..15, semantic generation 16..23, live bitmap 24..31, actual membership count u32 at 32, admitted column count u32 at 36, reserved zero 40..63. Never embed every possible token.

Use three shared ordered maps per Node/Edge namespace, not a tree per owner or field:

1. Owner enumeration: key (owner u64, token u32), value (source u8, reserved-zero[3]); 16 payload bytes per actual field before B+Tree framing/fill. Source COLUMN or EXTENSION is the sole ownership selector. ROW continues existing actual-key enumeration.
2. Column directory: key (group u64, token u32), value (stable PageId u64, slot u16, reserved u16, slot-generation u32); 28 payload bytes before tree framing. One locator per admitted field/group. Owner entries derive group/token and never duplicate that locator.
3. Extension: logical key (owner u64, token u32), physically mapped to the same 16-byte stable slot locator as the column directory. The pointed shared field-page record contains one canonical field payload or independently authenticated LargeValue reference, with the owner/token in its authenticated body. Obey the record/native usable-payload ceiling and existing large-field/media contract. No duplicate whole ROW is stored.

Physical map implementation decision (R3.2): reuse existing key-only B+Tree entries as ordered logical-key prefix followed by canonical value suffix. Owner selectors are 12+4 bytes, column and extension locators 12+16, group locators 8+16. These widths remain lower bounds before packed framing/restarts/internal separators/fill; value suffix bytes participate in compression and cost. Logical prefix uniqueness is additional to full native-key uniqueness: lookup reads the matching record and one lookahead, rejecting a second suffix for the same prefix, including across leaves. The owning typed map must enforce complete integrity and canonicalize final changes to one erase-old/insert-new replacement per prefix per transaction. Multiple unmerged replacements based on the same old snapshot are invalid. Ordinary internal B+Tree child layout stays U64; native compound mutation and fresh rebuild must explicitly retain EMPTY leaf layout. `FixedBTreeMap` only provides generic fixed-width encoding/lookup; it does not install a hybrid root, interpret locator targets or define the graph fence. The variable-size extension body lives in the shared field page, not the B+Tree key suffix. Its typed codec and page binding are separately required; the fixed-map helper does not complete them. Those shared-map tests use generic index namespaces; they do not install hybrid field routing or complete production conversion.

Map page framing is the existing B+Tree framing and must be measured; payload sizes are lower bounds, not allocated-space claims. The group-header directory is a fourth shared map per namespace, keyed by group u64 with the same 16-byte slot locator used by the column directory. Its O(G) cost is additional.

Choose an explicit new Superblock physical metadata root, hybrid_property_descriptor_root, included as an additional graph semantic fence member. It points to one authenticated 192-byte descriptor payload: magic u32 at 0, version u16 at 4, zero flags u16 at 6, semantic generation u64 at 8, database ID u64 at 16, reserved-zero bytes 24..63; eight B+Tree root references of stable PageId u64 + expected root generation u64 occupy offsets 64,80,96,112 (Node owner/column/extension/group-header) and 128,144,160,176 (Edge equivalents). Empty tree references are both zero; partially zero references are invalid. Descriptor generation must be visible in its Superblock. Per-group mode lives only in the group header. ROW routing continues the existing entity_property_directory_root, with no duplicate ROW root embedded in the descriptor.

R3.2 assigns the new Superblock field offset/format version and metadata-page kind atomically with readers, writers, relocation and integrity before encoding any file. Both initial conversion and later field changes replace the descriptor and advance its graph fence even when B+Tree PageIds stay stable and only physical mappings change. This intentionally preserves conservative conflicts; the former seven-root fence omitted this descriptor. The implementation now appends an eighth member and distinguishes default/experimental profiles in its format token.

Selector, column presence and extension existence must agree exactly. Missing selector means absent; stored NULL has a selector. No duplicate authoritative extension row. Point access validates the selected path; full integrity checks both directions for orphan/duplicate/wrong-owner/group/type members. Dynamic type does not become permanent schema.


R3.2 native descriptor-frame preparation: `HybridPropertyDescriptorCodec` uses a 32-byte physical header (ZYXH magic u32 at 0, version u16=1 at 4, header bytes u16=32 at 6, physical generation u64 at 8, committed LSN u64 at 16, payload CRC32 at 24, header CRC32 at 28), followed by the specified 192-byte payload (ZYXD magic, version 1). The remaining 4096-byte frame tail is zero. Payload CRC covers offset 32 through the frame end; header CRC covers the 32-byte header with its own field zeroed. Relocation physical generation is separate from property semantic generation: require semantic<=physical<=snapshot, visible committed LSN, and exact database/expected physical-root generation. Physical generation must fit the Superblock 59-bit packed reference. Nonempty namespace roots cannot alias PageIds; partial-zero roots fail closed. Their expected generations are shared-pool physical epochs, not semantic commit generations: no numeric ordering against descriptor/frame/snapshot generation is valid. Each eventual routed reader must instead match the selected namespace IndexId and pinned Index Root Directory entry, then authenticate the exact PageId and physical epoch of the actual B+Tree root. A frame checksum or paired positive root reference alone does not authenticate that tree. After the in-memory codec checkpoint, the isolated empty-descriptor metadata lifecycle below is connected. This still does not admit R3.2 or authorize nonempty hybrid property layouts.

Namespace IndexIds are now fixed by `HybridPropertyIndexIds.hpp`: ordinals 0..7 map to `0x8000000000000030`..`0x8000000000000037`. The range is disjoint from global adjacency, System Catalog, LargeValue, schema-definition IDs and vector mapping prefixes. All five ordinary graph scalar staging entry points reject it in every build. A nonzero descriptor-request IndexId must match its ordinal before data preparation; no ordinary Index or swapped Node/Edge/field role can substitute. This does not validate tree contents or authorize nonempty field routing. The storage specification records the default 5/31/336 and isolated 6/32/352 profile/Superblock/header matrix and unchanged rejection guards.

## Snapshot liveness and field transition contract

The group header is authoritative for current owner liveness. A retained column records the live mask at its own last encoding generation; that mask may differ from the current group only on absent cells. Require column presence to be a subset of both its encoded live mask and current group live; NULL remains a subset of presence. Thus birth/death of an owner absent from a field does not rewrite that unrelated column. Deleting an owner with a present column field must atomically remove that presence/selector; leaving a value for a dead owner is corruption. Do not require all column live masks or generations to equal the latest group header.

Validate `column semantic generation <= group generation <= descriptor semantic generation <= snapshot visible generation`, with positive identities and the selected namespace's owner/column/group roots present. Authenticate the expected owner/group/token and native PageId/slot-generation separately. An unchanged column retains its old semantic generation; every actual hybrid field/ownership change still replaces the descriptor and advances its additional graph fence. Native logical-ID limits remain unchanged: EntityPropertyKey currently permits positive IDs through 2^63−1; generic uint64 arithmetic in payload experiments does not expand that range.

A scalar SET/no-op/REMOVE transition touches the selected field. Same-type changes preserving >=48 present slots replace that column only; NULL is present and zeroes payload. Occupancy below 48 or a different non-NULL type demotes only this field into at most 64 actual cells. Never auto-promote extension/ROW state. An opaque incoming extension value stays caller-owned until the separately admitted native extension writer handles it; a marker is not a persisted large-value reference. No-op equality must match existing ROW `PropertyValue::operator==`: int/double remain distinct, double +0 equals -0, and NaN is unequal to itself. Changed double payloads preserve raw IEEE bits. Codec bit round-trip equality is not write no-op equality. Reserve fixed transition staging against the actual account before entering, and retain it through the result; record output must fit the native slotted usable limit and the 4096-byte ceiling. A failed plan changes no source, index or published root. Native reverse conversion, real extension ownership and complete global integrity remain required beyond this pure kernel.

## Access, update and full costs

Let F be actual fields, C admitted columns, G allocated groups, X exceptional fields and h shared-tree height. Storage is O(F+C+G+X), C≤F, X≤F; never O(E×K) absent membership entries.

| Operation | Required reads | Required COW/publication |
|---|---|---|
| One owner/field | Group/mode, selector, selected directory+column or extension, page/catalog routes and selected large body if needed | None; extra descents can hurt point latency and remain protected |
| Full owner | Owner-prefix range over actual keys, selected sources and requested large bodies; ROW uses current root | None; O(actual fields+pages), not global/group token scan |
| N owners, f fields | Batched group/membership routes, f subblocks per visited group plus matching extensions; restore original/duplicate ordinals | None; same R1 executor for ROW and candidate |
| Existing scalar SET | Selected source/selector, relevant indexes and page mappings | Changed data pages and necessary O(h) paths; unchanged selector/locator not rewritten when logical slot identity remains valid. Update semantic fence even if only physical mapping changes |
| Insert/REMOVE/type change | Selected source/selector; at most 64 values of that field if demotion needed | Affected selectors/source/directory, group counts, indexes, allocator and exact retire records; admission refusal leaves old graph intact |
| Complete map replacement | Actual old/new keys and changed indexes; apply existing transaction resource admission | Changed fields/routes; no whole-group container rewrite. No guarantee of accepting unlimited user input |
| Delete/reclaim | Actual owner fields/incident graph records, membership and bitmaps | Changed paths/counts/indexes, remove empty columns/groups, exact retirement; reuse waits for pins |

No-op compares canonical type/value and causes no property/index replacement. NULL↔missing, int↔double, merge versus replace are distinct. Unchanged indexes and unrelated large bodies are reused. Demotion touches one field per ordinary single-field write; if staging cannot fit, reject atomically. ROW fallback retains its existing limitations; it is not proof of universal fine-grained field updates.

Conversion gate: conservatively estimate complete native allocated bytes for candidate and ROW, including data pages rounded at actual fill, map framing/routes, enumeration, type/presence/live data, descriptors, catalog/allocator/Page Directory/metadata routes, large manifests/content index, affected query indexes, retire queue and retained old generation. Charge actual reserved 128 KiB pool capacity, including unfilled frames, not an imaginary fully occupied 31-frame pool. Cancel shared unchanged costs only with proof. Conversion scratch is charged separately.

Require candidate steady live allocation ≥10% below ROW and peak old+new retained allocation within unchanged resource/file caps. Unknown estimate rejects conversion. R3.2 compares actual allocations with estimate; underestimation invalidates the estimator. This is a byte eligibility rule, not R7 latency admission.

Example lower bound, 64 owners sharing one int field: 576 column +64×16 selectors +28 column locator +64 group header +24 group locator =1716 bytes before all framing/pages/native metadata. A singleton never gets a column. A3's 2224/4744 and 2296/4016 observations describe other encodings; do not compare them as complete allocated totals. Shared-tree membership can erase apparent savings; record that outcome without forcing column mode.

## Lifecycle and format obligations

Reuse transaction-local field staging. Compute exact ownership/index/reference changes; reserve IDs/capacity; build changed data and descriptor/routes/allocator/retire metadata. Publish with unchanged data fence → inactive A/B slot → superblock fence → acknowledgment. Validate semantic property fence and preserve overlays/read-your-writes/current conflict and blind-rebase scope. Never replay side-effecting statements.

Prepublication failure keeps old graph authoritative; uncertain acknowledgment requires reopen/root selection. Old pins retain complete old selectors/routes/large references. Retirement follows exact cross-owner reachability, not merely candidate missing-reference lists. Apply the same protocol to reverse conversion, field demotion, delete, relocation, physical reuse, long pins/backpressure and tail truncation.

R3.2 must update all reader/writer/descriptor/map/page-kind/version contracts, root validation, integrity, relocation, allocator reachability and retire handling together. Current new-file/old-version rejection policy applies; no sidecars or migration. An incomplete graph-attached lifecycle cannot enter R3.3. Keep an isolated ROW control under the same executor.

R3.2 matrix: 47/48/64 occupancy threshold; sparse/singleton; random interleaved shapes; multilabel; repeated type churn/demotion; post-delete sparsity; >4096 memberships; wide/large fields; unordered duplicate neighbor gather; no-op/NULL/merge/replace/remove; old/new snapshots/reopen; valid-checksum identity mismatch; each publication fence failure, quota refusal, relocation/reuse/retirement. Check exact IDs/types/values/multiplicity and full native costs. Candidate rejection may complete comparison R3.2, never production R3.3. R7 latency/write/resource/steady-state gates stay unchanged.

Isolated metadata prototype: `ZYX_EXPERIMENTAL_HYBRID_PROPERTY_FORMAT` defaults OFF. Default Superblock 31/header 336/profile 5 remains unchanged and cannot encode/publish a present descriptor root. The ON build is experimental: Superblock 32/header 352/profile 6, with the new physical root at 336..351 (slot u64 plus existing packed generation/frame u64), followed by the 32-byte emergency reserve at 352. Remaining reserved bytes are zero. The builds reject each other's files without migration. Current experimental write/read/open/integrity permits empty descriptors with all eight roots zero only. Nonempty roots reject before frame allocation; checksummed unsupported routing/wrong identities reject on open/read instead of falling through to ROW. Ordinary Node/Edge/ROW remains usable, but actual subblock conversion APIs are not installed.

The descriptor is a separate physical metadata-pool frame. It has no routed MetadataPageId, is outside the twelve logical bootstrap roots, and is not State/radix. Recovery, read-only discovery, reachability, old-pin protection and conservative directory cloning visit it explicitly. Local evacuation encountering this extra physical frame keeps the existing conservative fallback. Relocation replaces physical generation/LSN while retaining semantic generation. Clearing its root reclaims through existing pin/reachability rules, without a retirement sidecar. Both builds carry the eighth fence member (zero for default files), with distinct 31/32 format tokens. Changes cannot masquerade as ID-only reservation or blind adjacency rebase. ## Extension envelope preparation

The uninstalled R3.2 extension codec uses a 48-byte ZYHE (`0x4548595A`) envelope, version 1: magic u32 at 0, version u16 at 4, owner kind u8 at 6, mode u8 at 7 (1=inline, 2=LargeValue reference), native owner ID u64 at 8, token u32 at 16, body bytes u32 at 20, semantic generation u64 at 24, reserved-zero 32..47. Inline mode contains exactly one existing canonical PropertyValue; missing has no extension/selector, while NULL has the canonical NULL value. Authenticate outer owner/token and extension<=group<=descriptor<=snapshot; a referenced logical generation must not exceed extension generation.

Large mode reuses the existing LargeValueRefCodec and `application/vnd.zyx.entity-property-root` media, with the owner-neutral payload constrained to exactly one token/value. Both directory token and entry token must match the outer token; multiple fields, trailing data, wrong kind/media or future identity reject. Existing LargeValueStore must authenticate manifest, chunks and content hash before supplying bytes; this envelope decoder does not authenticate content by itself. Do not create a separate whole-row copy or treat an arbitrary same-media row as one field. Equal one-field payloads may share immutable contents across owners through existing deduplication and exact retirement rules.

The complete extension record must fit the actual destination limit and at most 3952 bytes (4032 owner payload minus 64 slotted header minus 16 slot bytes). The extension directory stores a fixed 12+16-byte prefix/locator key. Do not put a variable field body in that key: native internal separators retain the full key, so doing so duplicates potentially large field bytes and lowers fanout. The variable envelope stays in a shared slotted field page. This adds a locator and selected-page read that must be included in complete allocated costs and protected point latency; no performance admission is inferred. Charge the 48-byte envelope and any additional directory/value framing in total native costs. Destination and canonical encoding workspace use caller-owned PMR; reference media capacity and decoded value/directory allocations require separate retained reservations. The charged conversion plan can emit only actual inline-extension members, rejecting column-source members and oversized values. This codec does not install variable-map routing, allocate data IDs, publish large values or remove nonempty-root guards.

## Private field-page preparation

`HybridPropertyPageImage` prepares neutral native SlottedPage images, with one explicit allocation owner for page, record-copy and serialized buffers. It packs group, column and variable extension records behind stable PageId/slot/slot-generation references; fixed directories can share the existing canonical map writer. It is not an installed pool/format, does not allocate IDs, and must never be persisted as an ordinary ROW page. Metadata must assign the logical data IDs before map-key planning in the same eventual publication. No new generic variable B+Tree map is retained. A private variable-key experiment was not adopted: payload-bearing native separators create a mechanism/capacity cost, not a measured latency result.

Keep shared-pool physical generation separate from semantic commit generation: data pool reuse generations do not advance on every graph commit. A column at semantic generation 7 can validly live in a data pool of physical generation 1, provided its group/descriptor/snapshot semantic bounds are valid. The descriptor metadata-frame physical generation follows its separate metadata publication rules. Private clone/overwrite preserves stable slot identities; erase/reuse advances slot generation. These image checks do not replace native graph routing, final authority/integrity, resource scratch admission, allocation/retirement or R3.2 full lifecycle acceptance.

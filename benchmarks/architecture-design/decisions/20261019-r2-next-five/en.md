The R2 change exposes `readMetadataRadixUnresolvedView` and consumes it only in the existing location range cursor's root/internal-page reads. Cache hits share `const` decoded storage. Misses own the existing decoded image inline; zero budget and future/unpublished frames remain uncached. Directory kind, root/internal kind, route depth, visible generation/LSN, cycle, leaf ordinal and requested owner checks remain at their original sites.

Metadata cache key remains StorageIO-bound database snapshot + physical slot/frame/generation + codec type (+ logical route ID when applicable). Root and fence checks remain unchanged. No absence cache, new cache, larger quota, file-size-check removal or persistent-format change is introduced. Scope lookup synchronizes same-IO dataMutationEpoch; direct writes invalidate the cache. Other handles can publish new COW roots without modifying a pinned old image; new snapshots use their own contexts. Relocation and physical reuse retain stable page IDs and generation checks. A borrowed old decoded image remains immutable and alive through its shared owner even after lookup invalidation; subsequent reads must reload/authenticate. Arbitrary external mutation during a cache hit is not detected on every logical access; it is detected on a subsequent authenticated reload or full integrity traversal. That existing contract is unchanged.

## R2.3 measurement scope

`decoded_metadata_copy_fixed_bytes` counts sizeof(Page) for successful value-copy cache hits, including route-cache value copies. `decoded_metadata_borrow_fixed_bytes` counts sizeof(Page) represented by shared-view hits. Both are cumulative logical fixed-struct bytes, excluding nested vector allocations, return-value moves, route-frame copying and cache-miss codec copies; they are neither physical I/O nor RSS. Existing cache-hit/decode/page/file-size/checksum/I/O counters remain separate. The bounded PerfTrace page-pin facility counts generation/context-distinct page images where enabled; physical-offset uniqueness requires separate offset deduplication. Cache-hit counts are not unique pages. No sum of nested timers is presented as wall time.

This proves the mechanism and unit meanings, not full-size P50/P95 or a workload speedup. The ten-hit radix test separately compares copied and borrowed fixed bytes with zero new codec decodes. ## Cross-handle invalidation correction discovered by the required test

The first 103-case run had one failure (102 passed): opening a new read snapshot after a second writable handle grew the file could report "shared page-pool header disagrees with its Page Directory mapping". A staged assertion localized this to reading the new snapshot; the old pinned snapshot still returned its original values. Pool frame-allocation control records are mutable while the pool incarnation generation stays unchanged. The other handle's positioned write does not invalidate this handle's raw-page cache, so the old key (pool offset, pool generation) could return an authenticated but stale bitmap for newly allocated frames.

Both copying and pinned known-location reads now key the **control image** by (pool offset, snapshot publication generation). Cache identity is explicitly a parsing/visibility context here; decoded envelope/header generation is still checked against the actual catalog pool generation. Immutable data pages keep their existing (offset, actual physical generation) keys. Same-handle control writes already invalidate all cached images of that offset. New snapshots cannot reuse old control images after external publication; an old pinned image remains valid for its old mappings. No global cache discard, extra cache, file-size-check removal or weaker checksum/owner/allocated-frame check is used. The key does not make data mutable or permit reclaiming pinned frames.

This can retain more than one control image across generations within the unchanged buffer-pool bound and may add first-read work per new snapshot generation; R2.3/R7 must retain this resource/point-read protection. It is a correctness fix, not an unmeasured performance claim. Native tests cover two handles, actual file growth, old/new exact selected values and reopen; existing pinned-file-pressure/reuse and pool evacuation/failure modules protect lifecycle. Raw first failure is retained alongside final evidence.

For cross-snapshot diagnostics, PerfTrace's page-pin identity includes the supplied generation/context: different images of one physical offset are distinct. To report unique physical offsets, deduplicate offsets separately; do not label generation-distinct image counts as unique device pages.

# A1 节点列聚合扩展到 MIN/MAX

日期：2026-10-12。状态：无分组、非 DISTINCT 的直接属性 MIN/MAX 已接入原生节点列消费者；425 项相关模块测试通过。S1.1/S2.2 仍为部分实施，不增加完整验收项。

## 生产链路与语义

沿用既有 NodeColumnReceiver、索引优先选择、源列身份/形状认证与扫描顺序映射。MIN/MAX 可与同字段 COUNT 共享读取，字段名称与源序号仍在查询内绑定。复杂表达式、分组、DISTINCT 和其他聚合继续走旧消费者，不产生第二个独立的聚合语义实现。

同类型整数/浮点列调用 MinAccumulator/MaxAccumulator 新增的 updateInteger/updateDouble。比较保持原来的严格 < 或 >，相等时保留先遇到的值，因此 NaN、正负零和物理扫描顺序与原实现一致。跨批次类型变化时，若持有结果类型与当前类型不同，委托原 PropertyValue 比较；不引入隐式数字类型转换，不改变既有 variant 类型顺序。

字符串、布尔、集合及混合类型使用原 updateAdmitted。动态列仅借用当前源矩阵；新的极值副本由累加器独立拥有，不能逃逸源引用。无输入或者全部 missing/NULL 时，无分组聚合仍产生一行，MIN/MAX 为 NULL，COUNT(field) 为 0。

## 预算与生命周期

MIN/MAX 不同于 COUNT/SUM/AVG：它们保留结果载荷，不能将所有列聚合都当成零动态状态。原行路径和列路径现在共用 accountAccumulatorRetention，按实际保留字节变化增加或退还组状态预算。值变短不代表所有容器容量必然缩小；以实际保留容量为准。

动态极值的副本先通过 updateScratch 申请预算，原持有结果仍计费，因此旧结果与新副本的峰值同时被覆盖。复制成功后转为长期组状态计费；复制、guard 或分配失败传播，不发布部分聚合。最终 takeResult 仍将拥有化载荷交给原输出边界。

类型化转换前为可能首次持有整数/浮点结果的极值累加器保留标量空间，只计算超出现有计费结果的部分。可选转换不能把这部分额度全部占走；转换结束后交还预留，由实际更新正式计费。无足够空间时保留动态列消费，不因可选缓冲而强制溢出预算。

COUNT/SUM/AVG 仍走无变长载荷的直接分支，不新增逐值保留容量探测与深复制 guard。仅 MIN/MAX 需要复制准入和结果状态计费。所有源列和类型化数组持续按真实生命周期计费，不提前释放 source 的预算来掩盖峰值。

# A2 语句回滚按修改实体保存

日期：2026-10-14。状态：实现及限定模块验证完成，S3.1 仍在推进，未新增验收项。

显式事务覆盖层原来在每条非空语句执行前复制完整 `nodes_` 和 `edges_`。一个字段或标签修改也会复制此前所有暂存实体的属性，包括无关宽属性；异常恢复再次复制整个覆盖层。

现在每条语句使用局部 `StatementUndo`，在首次修改一个 Node 或 Edge 前保存其原状态；原先不存在的实体只记录空标记。同一目标多次修改只保存语句开始时的状态，Node 与 Edge 的同数值 ID 分别记录。创建、属性替换、标签替换、显式删除及 DETACH 的持久/新建关系均进入这一协议。备份分配失败发生在对应修改前，已有修改由同一 undo 恢复。

失败恢复使用已有 map 项与保存状态交换，删除语句新建/首次物化的 map 项，不重新分配或复制属性。生产代码通过 `is_nothrow_swappable` 静态检查约束两个状态类型。成功语句仍先 preview/apply，再由事务 stage，最后递增覆盖层 revision；失败语句不递增 revision。没有改变事务最终发布点、文件格式或 Driver ABI。

72 项覆盖层模块测试和 127 项原生属性/事务/索引模块测试通过，共 199 项、0 失败。新增五项回归验证重复修改的首状态、同 ID 不同实体类型、暂存失败恢复/创建身份重试、DETACH 上限失败及 stage 失败恢复。32 个 16 KiB owner 的场景连续八次只修改一个 Node，每语句 undo 诊断最大值为 1 个 Node、0 个 Edge，无关 Node/Edge 的宽属性读取仍正确。诊断表示备份目标数，不代表 RSS、分配字节或吞吐收益。

首次模块运行有一项新测试期待错误的异常类型：内存 fixture 的缺失关系由 `map::at` 抛出 `out_of_range`。核对源路径后修正测试期待，重新构建并运行 72 项，全部通过；没有修改生产错误语义。

证据位于 `benchmarks/architecture-design/results/20261014-a2-statement-owner-undo/`，包含源码 hash、构建/测试原始日志、模块链接命令与验证记录。只测试相关模块，没有全量测试或性能 benchmark；未验证 macOS/Windows 构建。

边界：修改目标仍保存完整实体状态；属性暂存、事务累计候选副本及提交时 base/final 差量适配仍待字段级迁移，共享预算仍未闭环。此修改不能验收完整 S3.1 或 S3.5。总体仍为 3/34（8.8%）；正式 optimization.mdx 不变。按照验收百分比增长时提交/推送的既有约定，本轮改动暂留工作树。

# A1 batch owner and incarnation validation

Date: 2026-10-14. Scope: S2.1 row-identity foundations and one real aggregate consumer. Complete envelopes, layout/data-snapshot identities, dynamic arenas, and remaining operator migration are pending. Accepted progress remains 5/34 (14.7%), with no new acceptance.

The private BatchIdentity component assigns nonreused uint64 owners shared across column types and uint64 incarnations. BatchRowId contains a uint32 row index plus owner/incarnation, without buffer or page pointers. Owner exhaustion fails explicitly. Incarnations never wrap: append checks exhaustion before changes; noexcept clear/release permanently disable descriptors on exhaustion, and subsequent append fails. Counter exhaustion was not stress-tested and is not claimed as measured coverage.

FixedWidthBatch rowId/cell validates owner, incarnation, and published row bounds before returning an owning fixed-type TypedCell. Missing/NULL/value, row order, and separate positions for duplicate values are preserved. Successful append, failed append that may have relocated earlier columns, clear, and release invalidate old descriptors. Row-limit rejection occurs before any column mutation and preserves valid descriptors. Rectangular rollback retains existing values and accounts for allocated capacity; callers can reacquire a current descriptor for preserved values. clear retains charged capacity, while release refunds it. Reconstruction at the same address rejects the previous owner's descriptors. Row limits are explicitly positive uint32 values.

PrimitiveNumericColumns uses the same identity protocol. Rows and descriptors are published only after guarded preparation succeeds; failure or cancellation does not publish them. release invalidates descriptors and frees conversion buffers. Repreparing the owner cannot reuse previous identities. Even an empty preparation has a published state and requires release before reuse. Descriptor-based update authenticates owner/incarnation/bounds before any accumulator effect. The previous size_t entry is an explicit adapter that obtains a descriptor and invokes the checked entry.

Production integration: LogicalPlanReadRuntime numeric-column aggregate calls consume numericColumns.rowId(ordinal). Existing typed/dynamic COUNT/SUM/AVG/MIN/MAX/STDEV/STDEVP algorithms remain intact. Releasing optional conversion buffers under budget pressure retains the existing per-field dynamic retry without replaying accumulated rows. COUNT(*) needs no numeric-column descriptor. Ordinary column/span access remains available with caller-managed borrow lifetimes; this component cannot authenticate arbitrary stale C++ spans. Program/layout/snapshot identity, dynamic values, bitmap association, and all-operator descriptor adoption remain pending; complete S2.1 is not claimed.

Verification adds seven FixedWidthBatch and three PrimitiveNumericColumns tests covering three-state ordered duplicate rows, successful/failed append, clear/release reuse, foreign/zero/out-of-range descriptors, owners across column types, reconstruction at the same address, preparation cancellation/retry, empty-batch publication, and rejection before accumulator effects. Component/Node aggregate modules passed 68 tests and related runtime modules passed 222 tests, with 26 overlaps: 264 distinct passing tests. Core and relevant test objects were rebuilt from current sources. Verification is Linux/C++20 only; no full suite, performance benchmark, or Kuzu comparison, and no throughput improvement or cross-platform measurement is claimed. Existing missing property_tokens initializer warnings remain.

The matching results directory contains build logs, module link commands, raw test logs, source SHA-256 hashes, and verification.json.

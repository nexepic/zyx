# 增量路由提交：候选实现与证明义务

P1 已验收，当前进度 25%。P2 尚未验收：元数据池所有权枚举和阈值触发的全图回收仍须增量化。用户已确认局部访问校验＋完整 integrity 合同。持久格式、COW/A-B 和同步顺序不变。

## 算法

1. 从当前批次取得最终、按 MetadataPageId 排序的变化集合。拒绝不是本批独占分配的目标，以及不同 ID 指向同一新物理 frame。
2. 从已发布的 bootstrap 路由根下探，只解码变化叶子及祖先。每个实际访问节点检查 CRC、目录类型、可见性、层级、范围和同父引用别名；变化叶的全部记录检查 ordinal。
3. 多个变化共用的祖先只生成一份计划图像。新增远端 ID 时用零前缀扩展根，将旧 ROOT 在私有图像中降为 INTERNAL；不原地修改旧页。未访问子树保留原物理引用。
4. 后序排列计划帧，空间数为变化 leaf/radix 帧加一个 bootstrap header。规划不分配持久 ID 或 frame。发布按同一后序分配并编码。
5. 容量预检与发布共用目录对象持有的有账户计划；来源 root、批次身份、变化集合或 StorageIO epoch 改变则重建。发布取得计划后从目录释放持有，确保 scratch 不成为跨事务缓存。
6. 根的逻辑 ID 从所需目录根页直接取得，再验证对应路由，而非从完整集合反向扫描。当前只有固定数量的根。
7. 强制 refresh、prune、初始迁移及显式全局检查保留原全量流程；它们不能成为普通更新的隐藏 fallback。

## 不变量

- 旧 pin：源树及其数据从不修改，旧 bootstrap 引用保留旧可见状态。
- 新目标所有权：本批分配器禁止复用该批已分配 frame；持 pin 的旧池不能复用。目标唯一性在变化集合内检查，bootstrap plumbing 随后从不同 frame 分配，因此新提交不引入目标别名。
- 旧图损坏：实际访问时校验；未访问分支后来发生的损坏不承诺由无关提交发现，完整收集/integrity 仍遍历验证全局别名、重复、错路由及损坏。
- 额度：计划帧向量、子计划向量、叶 payload、目标集合和共享控制块必须持有资源账户。没有额度时失败并退款，不悄悄退回全量重建。
- 失败：规划完成前没有任何路由发布页分配；物化失败由原 MetadataWriteBatch 回滚私有页，A/B 发布协议不变。
- 空间闭环：新增容量池可能修改 Catalog/Allocator 和 pending routes，因此预检后的变化必须使计划失效；现有有界闭环保留，但每轮不得扫描完整路由。

## 必要验证

固定一个变化，在 3/300/900 个叶子的树上记录读取与分配量；随高度而非总叶子数增长。覆盖共享祖先、根增长、重复目标、被修改叶损坏、未访问损坏首次访问/完整检查拒绝、旧快照和重开。计划复用测试检查 count/count/build 只规划一次；新 pending route 或 I/O 写入必须失效。生产 metadata store 测试覆盖 Catalog/Allocator/Location 发布、旧 pin 回收、故障与迁移。

共享计划与生产准备闭环已通过 183 项必要模块测试，包含路由、Metadata Store、Batch、故障与迁移。固定变化的三种规模机制记录见 `route-module-tests.json` 与 `acceptance.json`。没有全量单测，也未重跑候选性能窗口；本轮不声称达到 5 倍或 Kuzu 目标。

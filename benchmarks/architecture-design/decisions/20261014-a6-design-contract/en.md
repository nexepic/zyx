# A6 resource ownership and single-file spill design contract

Date: 2026-10-14. Scope: the complete S1.6 design decision. Runtime adoption, query spill, and S2/S5/O7 performance remain pending. Existing bulk scratch and an isolated component do not establish database-wide resource governance.

## Current behavior and integration points

LogicalPlanReadRuntime::ExecutionSharedState owns an execution-local MaterializedByteBudget, cache/final-result reservations, and PMR entity caches. Its materialization default is 64 MiB; it is not a thread-safe process budget. BudgetMemoryResource charges allocator requests, while manual reservations still include logical-payload/source-wire estimates. Neither their sum nor those estimates establish RSS or complete capacity coverage. Database's existing cacheSize also defaults to 64 MiB, without aggregating all instances. FixedWidthColumn, selections, binding tables, and PrimitiveNumericColumns have local admission. Dynamic PropertyValue, ordinary containers, complete decoders, fixed parent owners, and maintenance are not fully integrated.

NativeBulkRunStore already allocates/seals/retires SGK_BULK_SCRATCH inside the database file, using SegmentId/generation/transaction owner identities. Streaming writers bound fragments and manifest depth/fan-out. Allocation/release uses short metadata publications and monotonic checkpoint floors. reclaimUnpublishedOnOpen scans and reclaims sealed bulk scratch. It has no query active-owner registry, query-row codec, sort/hash spill operators, or independent query pins. Query scratch must not enter that cleanup category. RelocatableMetadataStore::beginWrite explicitly rejects physical read-only publication/reclamation.

## Hierarchy, configuration, and charging units

Use an explicit process resource owner → database domain → resource account → allocation leases. Database instances share the process owner; creating independent defaults to bypass the process cap is forbidden. Root/database/account admission and refund are checked/published together under one root mutex. No allocate-then-charge, or refund-and-readmit ownership transfer. Tasks/operators share their query account instead of duplicating its full allowance. split/absorb transfers only within the same account and cannot increase its quota.

Target defaults: 512 MiB chargeable process memory, 256 MiB per database domain, requested query limits retained (64 MiB default) subject to parents, and cacheSize retained subject to parents. Query/cache/write/maintenance/code category caps are upper bounds, not preallocation: database defaults are respectively 192/64/128/32/0 MiB; physical code caching initially stays disabled. Category caps may sum beyond the total, but every request must also satisfy that total. Process category defaults equal its total except code=0. Validate finite checked settings before work starts; explicit finite increases are permitted, implicit unbounded allowances are not. These options are not exposed by current constructors/ABI and are not yet effective. S5.1 must deliver compatible options and synchronized SDK documentation.

Protect progress with 16 MiB of the root total reserved as headroom for maintenance/abort/spill control. Ordinary query/cache/write/code growth cannot consume the unoccupied protected portion. This is inside the total, not an extra allocation or duplicate live-byte charge. At least one coordinated maintenance task can use it, with a bounded working set. Limit simultaneously live database budget domains and active queries per database to 64 each, including closed domains retained by results. Exceeding a slot limit fails explicitly. The foundation does not yet implement protected floors or slot admission.

Disk has separate uint64 counters: target query-scratch caps are 2 GiB per process, 1 GiB per database, and 128 MiB per query, additionally constrained by total file capacity and free space. Charge physical allocation extents after alignment, not just useful run bytes; current segments are 128 KiB. Reserved/writing/sealed/retired-but-unreclaimed extents all occupy quota. Refund only after safe allocator release. Report user-file capacity, retirement backlog, and scratch bytes separately from memory. Disk coordination remains unimplemented.

## Unique attribution and lifetimes

| Resource | Unique global account | Retention/transfer rules |
|---|---|---|
| Query compile/bind, input scratch, batch/selection/arena, operators/tasks, evaluator temporaries | query | Charge actual capacity, growth overlap, nested objects, decoding/transcoding buffers; distinct physical copies each count |
| Owned cache/page-cache buffers | cache | Borrowers do not charge payload again; query charges new handles/containers, with separate pin/retained-page limits |
| Private COW pages, overlays/staging/undo, constraint/index candidates | write | Candidates remain charged before publication; transferring the same buffer to cache changes attribution atomically without refund/readmit |
| Foreground/background reclamation, compaction, recovery/integrity workspace | maintenance | Bounded allocation and separate task caps; protected reserve serves only progress-critical work |
| Optional physical-program code cache | code | Initial cap=0; future enablement must include code, indexes, eviction metadata |
| Owned QueryResult/Driver ABI output | originating query/result | Charge survives operator completion and refunds only after the final output owner dies |
| Spill memory / physical extents | query memory / separate scratch disk | Real read/write buffers and merge cursors count as memory; disk release does not refund memory |

Output may outlive Database::close. Future runtime domains/output accounts therefore need strong keepalive ownership, never a destroyed Database or stack-budget pointer. Closing storage does not require destroying results; retained domains/accounts stay charged and limit reopening instances. The process has one bounded bootstrap control owner. Domain/query/control-block metadata is admitted before creation and constrained by slot caps; unlimited uncharged budget wrappers are forbidden. The foundation currently uses explicit process > database > account > lease reference lifetimes. Output integration must supply the unimplemented keepalive wrapper.

Separate global actual allocator bytes from existing local logical/encoded estimates. The coordinated allocator charges each actual request once globally. MaterializedByteBudget can retain conservative local semantic/source-work limits but must not charge the same estimate globally again. Report RSS, malloc metadata, stacks, mmap residency, and external-runtime overhead separately; this is not an absolute RSS hard limit. Every new chargeable internal allocation must admit before requesting memory. Unmigrated owners prevent S5.1 acceptance.

## Pressure, cancellation, and lock order

Each request follows: cancellation/work checks → atomically try all memory levels → outside resource mutex/metadata gates, release local optional conversion/cache → bounded eviction of unpinned database cache → spill only for supported operators/permissions with minimum IO/merge workspace already reserved → retry admission once → explicit quota/admission error. Do not swallow bad_alloc, source corruption, schema/binding conflicts, or evaluation errors. Never replay consumed aggregate rows or public callbacks.

Initial resource pressure does not block waiting for another query: no waiting while retaining query pins/write gates and no resource dependency cycles. The mutex protects counters only; no allocation, destruction, callbacks, logging, eviction, IO, cancellation checks, or metadata publication inside it. Release it before acquiring the single metadata write/publication gate; these locks never nest. Independent leases can run concurrently. One lease/PMR resource belongs to one task or is explicitly serialized by its owner, while the shared account has one aggregate limit. Existing non-thread-safe local budgets cannot be shared directly in O7 execution.

Check cancellation around every bounded codec chunk and run/partition/merge IO. Stop producers/tasks, destroy owned buffers/values, then refund and release pins. Failure cannot double-refund. Cleanup is idempotent, bounded, and uses retained cleanup headroom. Cleanup IO failure does not claim extents released: keep durable orphans charged/reported, preserve the original query error, and attach cleanup status. A crash need not restore query output; memory quotas disappear with the process, but disk orphans require authenticated recovery.

## Scratch permissions, identity, and publication

Distinguish logical read-only transactions from physical read-only files. Scratch writes require writable file + enabled query-scratch policy + backend-internal QueryScratchPermit. That permit grants no user mutation/graph-root privileges and is restricted to a scratch facade, not a general MetadataWriteGuard. Physical read-only files cannot allocate/publish/reclaim scratch. Use a supported memory-only path or fail explicitly; external temporary files cannot bypass the single-file constraint.

Choose a separate target namespace SGK_QUERY_SCRATCH with the existing enum-prefix convention, never the SGK_BULK_SCRATCH reopen-cleanup category. QueryScratchOwnerId is a persistent, nonreused uint64 lease within the database domain. Publish its high-water reservation atomically with allocator state. Addresses, thread IDs, and counters reset on restart cannot identify durable owners. Registration includes owner, state, manifest root/extent identity, and byte quota. Authenticate each page/manifest kind, owner, SegmentId/PageId, generation, length/version/checksum. Assign concrete enum values and query-row codec versions through A7 envelope/format records before S5.2; this iteration changes no disk format.

The state machine is registered → reserved/writing → sealed → retiring → reclaimed. Failure from the first four states can enter retiring; only reclaimed refunds disk quota. Durably reserve/register before writing a complete authenticated run, then publish its sealed manifest. Failed publication retains the registered owner for idempotent cleanup and never exposes half a run. User commit, scratch allocation/release, and maintenance share the short publication gate and rebuild updates from latest metadata/allocator state. Never overwrite another allocator publication with a stale candidate. Spill changes no user graph counts or existing write fences. Conservative metadata-related write conflicts belong to A5's later protocol.

Active query pins and durable ownership are distinct. Payload is reachable only through its owner manifest and explicit scratch capability, not user graph roots. Pins identify owner+extent generation. Integrity/recovery/background readers also require that pin domain. Reclaim payload only after all authorized scratch pins release; unrelated long graph snapshots should not retain private query payload. Shared catalog/allocator/metadata pages still obey MetadataSnapshotRegistry/Retirement. Query payload eligibility cannot retire shared metadata early. Keep current conservative reclamation until special query-kind walkers/retirement tests prove the new rule; lack of an observed pin is not sufficient proof.

Recovery runs under an exclusive writable startup gate before accepting queries. Shared handles must use the same backend owner/pin registry. Never sweep while another live handle has an active owner. Validate registration/manifests and allocator consistency, then reclaim only authenticated scratch of this database with no active startup owner. Wrong owner/generation, pointers to user data, and torn/corrupt registration cause error or quarantine, never guessed release. Read-only startup diagnoses without cleaning. Corrupt orphan lists must not free user pages.

## Algorithms, supported paths, and errors

Implement sort runs first. Precompute owned keys/rows once using the existing comparator, append checked uint64 input ordinals for stable ties, sort a bounded buffer, and emit immutable runs. Merge fan-in depends on available workspace, actual cursor/decoder capacity, and configured caps. At least two inputs plus one output must fit before starting; otherwise fail. Bound merge levels, run counts, and disk work. Persist values, logical entity IDs, layout identity, and needed ordinals, never C++ pointers/spans. Deferred EntityRef rereads retain the original query snapshot/pin. Discard scratch after crashes rather than restoring old C++ queries.

Then implement partitionable aggregation/hash join with existing canonical equality/hash rules. Equal keys share partitions; rereads preserve NULL/types/duplicates/relevant order. Repartition oversized partitions only to configured depth. Unsplitable/skewed keys fail explicitly instead of recursing indefinitely. Only merge accumulators with identical semantics. COLLECT, exact DISTINCT, order-sensitive functions, and functions whose existing floating accumulation order cannot be preserved remain nonspillable until their dedicated algorithms pass. Do not change SUM order or approximate deduplication to pass comparisons.

Initial exclusions: streaming-public-callback read-ahead, correlated subqueries/path owners, mutation planning, optional/grouped factorized layouts, and dynamic types without a qualified codec. Scan/filter/project can stream bounded memory; do not spill when unnecessary. Blocking operators expose output only after complete authenticated input/finalization. IO/disk-full/codec/cancellation errors cannot assert complete input or silently truncate. LOAD CSV does not permit host temporary spill files.

## Maintenance, observability, and acceptance gates

Report caps, actual admitted bytes, peaks, and denial scope for accounts/classes/databases/processes; local estimates remain separate. Also expose active query/domain slots, pinned cache, reserved/sealed/retiring scratch bytes, run/merge/depth/IO work, cleanup failures, user retirement backlog, and oldest snapshot. Default user retirement backlog is capped at 1 GiB per database. Foreground/background maintenance memory caps are 16/8 MiB, with at most 64 page-level IO/work steps per cycle and cancellation at each checkpoint/codec chunk. Permit at most one bounded foreground and one background task per database, subject to root protected-headroom admission. Long snapshots blocking reclaim lead to explicit pressure after finite retries, never unbounded growth, snapshot bypass, or permanent busy loops.

S5.1 requires allocator/ownership audits for compilation/execution/decoders, variable/nested values, fixed parents, retained outputs, cache, write-private pages, and maintenance. Validate concurrent queries/databases individually below local caps yet jointly denied by process caps, cancellation/failure/refund/transfers, results surviving close, slots/protected floors, and deadlock/pressure cases. S5.2/3 require complete value/duplicate/NULL/order/guard oracles for sort/partitions; physical/logical read-only permissions; disk exhaustion; faults at every publication/IO boundary; live handles/long graph snapshots/scratch pins; authenticated orphan/corrupt recovery; user-page protection; and allocator/user-commit interleavings. S5.4/5 and O7/O8 resource/performance acceptance remain pending. Kuzu comparisons occur only in the final window after all implementations.

Private ResourceCoordinator.hpp is an executable foundation for three-level totals/category caps, same-account lease transfers, and PMR request admission. Seven new tests verify shared-account quotas across leases, cross-database totals/categories, atomic denial, release/move, upstream bad_alloc refunds, old/new growth overlap, size_t boundaries, and two real threads simultaneously requesting the full process quota with exactly one admitted. There is no singleton/shared-DB registry, runtime adoption, protected floor/slots, keepalive, disk coordinator, or query spill. Do not enable a production total-governance feature flag. Combined with the A1 modules, 278 distinct selected tests pass; no full suite or performance result is claimed.

## Performance hypotheses and falsification

Root admission checks a fixed number of counters independent of database count, but a mutex per allocation may contend in O7. Actual-request PMR accounting does not imply throughput improvement. Future measured need for task-level quota blocks must keep unused grants charged, never lending them again based on live payload; do not initially duplicate thread-local allowances. Spill lowers memory peaks but adds IO/codec/merge work and does not prove a Kuzu advantage. Protect small queries, retained output, high cache hit rates, concurrent databases/writes/maintenance, long snapshots, and skewed partitions. The final window reports throughput/latency, admitted memory/RSS, disk IO/peak scratch, cancellation cleanup, and correctness gates together. If resource/semantic regressions or locking/copy costs erase gains, retain authenticated in-memory/bounded-failure paths and record the revision.

Continuation note: the private foundation now supports configured protected maintenance floors and finite database/query-account slots (default 64 each), retained by shared account leases. Production memory profiles, manager wiring and output owners are still pending under fixed-ledger S5.3; resource/scratch validation is S5.4. This does not change the historical design-stage acceptance.

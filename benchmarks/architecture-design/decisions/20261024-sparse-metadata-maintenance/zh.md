# 单池稀疏元数据维护检查点

S2 尚未验收，总进度仍为 15%。隔离 15/41 的 71 项、默认 5/31 的 18 项及已有混合 13/39 的 41 项相关模块用例通过。各配置分别链接自己的完整核心库，所选模块不是全量单元测试。本轮未运行查询性能测试，也未提交或推送。

私有构建器现在可以指定最高的已登记元数据池，按精确数据库、根代际和描述符围栏，每步最多迁移一个源池。它复用已有路由目标迁移、路由分支和 bootstrap 刷新逻辑；独立描述符通过专用物理迁移保持语义代际和全部字段/成员根不变。共处一池的纯路由分支与 bootstrap 头额外按完整物理帧覆盖验证后刷新，不调用全目录克隆回退。旧物理目录布局仍明确拒绝该优化，保持 BUILDING。

容量判断包含较低元数据池的空闲帧及分配器确认空闲、未被旧元数据池登记保护的完整段。只发现本步所需的容量。已存在的源池及上方槽位通过逐槽预留排除；未来尾部使用合法的临时后缀范围预留，包含超出 2 GiB 文件边界的哨兵槽。构建器目标本身已有硬文件上限，无法在低地址容量耗尽时投机扩展文件。范围回滚只针对初始尾部之后，避免把已有槽位错误当成临时尾部。

在旧快照回收器进入标准容器工作集合前，按已认证的已分配元数据帧数（每帧保守 1 KiB）及旧 pin 数量（每 pin 4 KiB）预付工作空间；后续路由收集也保留相应预付，类型化 COW 另外按实际账户分配。维护账户最多 7 MiB，与构建器 1 MiB 源账户合计最多 8 MiB。容量或布局不适用时不改变逻辑根，不授予完成资格；源池实际释放仍由后续单池回收和旧 pin 屏障决定。

新用例覆盖实际向下迁移、旧描述符及实体的读取、描述符语义内容保持不变、完整性、BUILDING、A/B 两类中断、取消和小预算 I/O 前拒绝，以及旧物理目录拒绝。初版漏算低地址已回收段，测试促成生产修正。随后定位出初始夹具使用旧物理目录，改用已有 initializeNewComplete 正式构造路由库；同时保留旧布局的拒绝测试。拓扑诊断中一次错误地把物理目录当作 bootstrap 解码，及一次编译失败后的旧二进制运行，均不计为验证；相关初始日志完整保留。

这不是真实 medium/holdout 的全库空间验收，也不证明任何查询性能提升。公开 15/41 后端仍拒绝打开；生产扫描证明和消费者、完整修改生命周期、超过 64 标签的通用回退及最终统一比较仍未完成。

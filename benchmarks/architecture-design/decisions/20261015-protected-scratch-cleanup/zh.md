# 受保护的文件内 scratch 清理

组件推进，不验收整项；仍为 22/34（64.7%）。

原生 scratch release/finish 在进入发布锁前，从同一数据库申请 MAINTENANCE 工作区，使用已有 maximum_reclaim_workspace_bytes（默认 8 MiB）。控制对象和页副本归该有限额度；顺序读取作用域绕过 CACHE 准入，保留脏页可见性。会话只保存 IO 的弱引用，不因保留已结束对象而延长文件生命周期。没有待清理片段的 finish 不申请工作区。准入失败发生在任何清理写入之前，不标记不确定结果；归还额度后可用原句柄重试。实际发布/IO 异常仍要求恢复，析构不能完成清理时继续保留孤儿磁盘计费。

42 项相关模块测试通过，包含两项原生排序集成、分区 DISTINCT、共享查询账户、异常/磁盘/只读/回收用例。新增用例证明 CACHE 额度被完全占用时 release/finish 不产生 CACHE 准入拒绝；MAINTENANCE 被占满时 release/finish 零写入失败，随后同一句柄可重试。工作区结束后归还维护额度，已有 finished 对象的 QUERY 句柄额度保持到对象销毁。

当前源码的 559 个子进程故障/恢复用例通过：553 个分配失败点（短路径穷举，长路径各采样 96 点）、四个终态用例、一个包含 16 种形状的堆探针，以及包含 32 轮真实崩溃/只读检查/恢复的流程。新 DISTINCT 路径正常执行 42,253 次分配，采样 96 点；成功必须得到全部 400 个有序唯一值，失败或恢复均保留用户图，查询账户归零，重开后同一磁盘配额可再次执行。断言成功结果在异常捕获之外，不能把错误的部分结果算作拒绝成功。完整记录见 proof.json/module-evidence.tar.gz。

未运行全量测试或新性能基准。嵌套 std 负载、其他私有/编译工作区、维护持久积压及完整阶段验收仍未完成；这些证据不等于所有平台的分配失败保证或所有堆分配均受预算约束。

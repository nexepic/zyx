# Procedure result growth and portable vector test contracts

The output vector previously demanded doubling even when a smaller growth fit the existing ceiling. A 300-row native entity-expression fixture on Linux failed at a peak of 262448 bytes against 262144 bytes: its 512-slot growth exceeded headroom by 304 bytes. The runtime now caps preferred growth at the affordable capacity and still rejects when even the next slot cannot fit. No production memory ceiling increases.

Eight other old failures were test assumptions about exact source-batch counts and fixed tiny byte allowances; their successful results or failure-at-growth behavior were reproduced with the previous procedure implementation. Container sizes/capacities and allocator growth differ across supported STLs. These tests are repaired explicitly rather than presented as eight production fixes. Metadata and scalar-copy tests bound gathers per successful execution while retaining low-memory rejection and value/shape checks. The cross-batch result case retains its 12000-byte denial and additionally verifies 600 exact outputs across multiple batches. Five Top-K fixtures now use 1000 candidates and a workspace derived from active type sizes; each has an inverse assertion that a complete sort of the same input fails under the same ceiling. Query-vector retention still has an independent low-headroom rejection. Default/native benchmark budgets are unchanged.

The previous 2493-line test file is split by boundary/Top-K/materialization category, sharing one named fixture. All 80 original test IDs remain exactly once. The affected selection passes 242/242 across 14 suites. This does not accept S5.3 or S6.1; procedure temporary payload ownership and the stage evidence gates remain open. No full suite or performance timing was run.

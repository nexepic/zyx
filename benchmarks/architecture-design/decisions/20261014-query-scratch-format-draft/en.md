# Query scratch registration — implementation draft

Status: storage and sort implementation in progress; S5.3/S5.4 are **not accepted**. Global resource ownership, partitionable hash execution, recovery/fault coverage and final comparisons remain gates. The authoritative ledger stays 22/34.

The development profile moves from envelope 4/Superblock 30 to envelope 5/Superblock 31, adding `SGK_QUERY_SCRATCH = 15`. Old files must be refused without writes, migration or A/B fallback into the old profile. Other local codecs retain their versions. Query data is registered only by authenticated sealed Catalog entries and never by public graph directories. A session owner consumes the existing durable Node-ID high-water allocator; unused IDs are permitted gaps, not live Nodes. Owners are therefore not reset/reused on reopen.

The internal LogicalQueryScratchProvider is independent of graph mutation permissions. A logically read-only query may obtain it only on a writable native file; a physical read-only file returns no capability. No host temporary path is exposed. Sessions share one backend-owned exclusive file scratch lease; foreign writable-open recovery skips live scratch, while physically read-only open does not reclaim. Ordinary bulk recovery selects kind 14 only; query recovery selects kind 15 and one owner at a time. Writable recovery authenticates envelope/Catalog identity and payload CRC before disposal.

Each opaque session handle is a newly allocated global SegmentId, mapped only inside its owning session to authenticated generation/owner. There are finite active-fragment and allocated-segment byte limits. Registration is reserved before IO, so a successful publication cannot lose its cleanup route to a later allocation failure. Reads return independent bytes and leave no private reader pin outside the call. Release requires quiesced private readers, checks owner/kind/generation and absence of public Page/Extent routes, and atomically marks Catalog obsolete and frees the allocator bit. Graph snapshot pins keep normal graph/metadata history but do not retain private query data slots. Ambiguous cleanup requires reopen; it never guesses that a user page is disposable. Close is refused while a scratch session is active.

Row v1: 24-byte header (`u64 magic`, `u64 input ordinal`, `u32 binding count`, `u32 sort-key count`), then ordered bindings (`u32 name bytes`, name, `u8 kind`). Kind 1 stores canonical PropertyValue bytes; kind 2 stores five u64 fields (entity ID, edge flag 0/1, endpoints, type token). Sort keys follow as self-delimiting canonical values. There are no pointers, physical locations, owner borrows or persisted row caches. Deferred entity/property reads use the original query snapshot. Unsupported complete entity/path owners remain in memory or fail under pressure. Hostile counts are checked against frame size before reserve.

Sort block v1: 16-byte header (`u64 magic`, `u32 record count`, zero u32), followed by `u32 record bytes` and the row v1 record. Outer native segment identity/checksum covers the payload. Qualified rows are at most 4 KiB encoded, with no NaN sort keys; unsupported rows never trigger source replay. Input ordinals preserve stable ties, NULL ordering uses the existing comparator, run cursors check width/order/cardinality, and merge is two-way with at most 12 levels. Row content, actual PMR vector capacity, route tables and a conservative codec/IO workspace are locally admitted. Publication checks are immediate; ordinary comparisons use the regular cooperative guard. The first/only row keeps lazy ORDER BY evaluation. Global memory/disk caps are not yet integrated and must not be inferred from these local bounds.

The existing bulk decoder also gains a wire-derived count bound before reserve: corrupted counts must produce a format error rather than allocating billions of entries. This is a correctness fix discovered by the selected bit-corruption test, independent of the new scratch profile.

Capacity audit note: the new external-sort buffer opts into actual PMR capacity and embedded-parent accounting. A blanket conversion of legacy generic buffers caused low-budget regressions; those existing paths currently retain payload accounting pending domain integration. This is an unfinished resource gate, not an accepted audit or a reason to raise benchmark budgets.

The query scratch policy is disabled by default while admission remains unfinished; native tests explicitly opt in. The provider exposes enablement, so default/native physically read-only paths retain the established in-memory Sort implementation. The per-query default disk allowance is 128 MiB/1024 fragments, matching the registered target.

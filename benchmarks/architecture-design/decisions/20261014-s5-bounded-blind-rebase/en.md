# S5.1 bounded conflict validation and latest-root rebuild

The native transaction has a bounded blind Node-property replacement path. It is eligible only if no read or Vector snapshot was exposed, the canonical final state has 1–64 persisted Node property owners, and there are no patches, creations/deletions, labels, Edge mutations or creation identities. Any other path retains the original whole-graph fence; accessing even an otherwise unused read snapshot permanently selects that fallback. This avoids accepting an incomplete read set or replaying a procedure/query callback.

The transaction retains one authenticated raw base pin while eligible. Validation uses a fixed 64-element stack array of optional Property Directory locations, including absence, and Node liveness. The existing `(PageId, slot, slot_generation)` identifies the owner version separately from the shared page generation: an unrelated owner can change on the same physical COW page without changing this owner identity; changed-then-restored values still advance the slot version. Relocation may conservatively conflict. No new persistent entity epoch or format is introduced. Absence reads from exposed snapshots retain the global fence; this is not general point-read or predicate dependency tracking.

Under the native publication gate, every attempt validates against latest metadata. The ordinary executor then builds from latest roots, reads the latest shared pages, and maintains/validates the current indexes and constraints. No old private page can overwrite a neighbor. The current graph fence is still enforced at actual publication. Three candidate builds at most; each attempt revalidates, and exhaustion is terminal conflict. Pins are released on exposed reads, commit, rollback and failure. Intersecting owner changes and deletion are terminal conflicts; latest unique-constraint failures remain definite rollback, and indeterminate durable outcomes retain reopen fencing.

214 selected adjacency, integrity, native transaction/fault, isolation and bound-read tests pass. Six new histories cover an actual shared page with two concurrent successful blind commits and reopen; owner modification/deletion/absent-to-present changes; exposed-read fallback; DDL added after staging plus latest unique conflict; changed-then-restored owner version; and over-64 fallback without dropping dependencies. Twenty fresh concurrent shared-page histories also pass. The previous conservative shared-page/race tests now explicitly expose their reads, preserving the tested read-dependent contract. No full suite or performance benchmark runs.

Accept S5.1's bounded initial production protocol with conservative fallback. Finer entity reads, predicate epochs, Edge/label operations, cross-owner publication and global resource ownership are not claimed. S5.3–S5.5 and final performance remain outstanding.

# V1 候选实施与退出记录

计划 scan-supply-20261026，V1 已按正确性与工作量证据验收，累计进度为 45%。本目录不是正式性能结果。

当前实现保留持久格式：类型段在输出前统一准入；扫描批窗口最多保留三个受预算约束的字段页面；固定宽度比较直接消费类型列，保留混合类型回退及 NULL/缺失/NaN 语义。取消检查保持有界，异常不得重放已交付前缀。具体源码随最终候选冻结。

## 已确认的工作与结果

- 新核心库已完成扫描格式 Release 编译。check-work.py 在 medium 持久输入上只读执行四项公开查询，不计时，完整 oracle 均通过；命令、二进制与输入哈希见 work-receipt.json。
- work-counter.cpp 复用 V0 认证供给与消费语义，每项只执行一次且不计时。全节点仍处理 225,000 候选、220,000 有值字段、440 批，精确结果 10,076；总准入回调由 220,880 降至 4,349。标签路径仍扫描相同候选并交付 100,000 字段，结果 12,500；总准入由 100,880 降至 2,474。次数减少分别为 50.79/40.78 倍，**不是查询提速倍数**。
- 公开计数中的类型段准入分别为 3,437/1,562 次，和总准入计数口径不同，不能混用。
- work-comparison.json 显示该输入上的字段页面复用、列解码、校验字节与 BufferPool 读取字节并未下降。当前不能将三个页面窗口宣布为新增收益；须结合资源与其他访问形态决定保留范围。
- 当前原生供给、认证身份和批算子已有公开采用；仍须完成在线格式模块和生命周期验收，不继承历史通过结论。

## 失败记录与配置边界

首次八模块执行错误地使用 SCAN=1 离线扫描格式库，包含在线初始化的测试因此失败；原始 module-tests.json 和日志保留，不能算通过。在线模块改用 HYBRID=1/SCAN=0，核心库正在重编译。测试构建使用当前 StorageIO 故障钩子对象覆盖生产静态库的对应对象，不等于重新构建了全库故障钩子版本。

preliminary-old-probe-* 使用了重新链接尚未完成的旧探针；preliminary-overlapped-* 有输出路径重叠，不作候选验收证据。最终串行 check-work.py 的 work-receipt.json 和 candidate-work.* 取代这些记录。预备测试在旧在线库完成链接时运行，也必须在新核心库完成后重新链接并验证。

预备在线模块中，字段更新 10 项、列复用 8 项、公开查询生命周期 61 项通过。ROW 元数据故障样例在 HYBRID 格式下不适用，正在用当前元数据/目录/树源码覆盖 ROW 依赖库单独验证。另有一项类型段路径仍复制最终页面的断言失败：已修改生产路径，在所有 run 借用消费完成后跳过冗余游标副本，非 run 缓存不变；待新库重新链接后验证，不改断言迁就结果。

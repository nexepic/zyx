# 原生缓存分配归属检查点

本记录仅为组件推进，不新增验收项，仍为 22/34（64.7%）。

原生创建/打开在取得已打开文件身份与持久数据库 ID 后，为同一活跃文件域申请一份 64 MiB 缓存预付额度。未使用部分同样计入现有进程/数据库总额并受维护保留空间约束；别名复用额度，注册表仅持有弱引用。准入发生在元数据打开/发布前，缓存实际分配使用局部原子计数，不嵌套资源协调锁与元数据锁。固定预留策略可能在进程压力下拒绝打开其他数据库，不代表每个句柄实际 RSS 为 64 MiB。新建引导及外部发布重绑定保留相同归属。

StorageIO 将拥有生命周期的分配器传给 BufferPool；页面数组/控制块、哈希节点/桶与队列节点均计费。额度可能先于纯页面容量耗尽，此时淘汰未固定页后重试；固定页或其他池压力下有界失败，保留原有脏页刷盘规则。

Codebook 元数据插入失败回滚，在正常按条目/载荷淘汰前先准入两个节点。不可变载荷容量、共享控制块及按值深拷贝使用拥有资源生命周期的分配器。逃逸读者乃至仍存活的弱控制块继续保留真实计费，淘汰不能退还活跃载荷额度。额度拒绝时有界淘汰自身缓存并重试，普通分配失败保留原有缓存值。临时解码 manifest/extent 块仍是待治理工作区；共享不可变 Codebook 存储归为缓存，包括未缓存但被读者持有的载荷。COW 私有页目前使用原始页缓存额度，完整写私有归属仍待完成。

检查点最终源码通过 21 个测试套件中的 241 个定向测试，包括 64 次原生重开、别名共享额度、真实元数据/载荷分配失败、固定读者、复制拒绝/重试、分配器传播及弱控制块生命周期。未运行全量单测或额外性能测试。证据和源码散列见 proof.json 与 module-evidence.tar.gz；维护/向量/DriverABI 的更广受影响模块仍需最终验证。

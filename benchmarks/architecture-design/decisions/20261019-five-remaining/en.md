## Boundaries that implementations must retain

The R1 quota fix is a correctness/resource classification change, not a sort speed claim. The old-source reverse control replaces only LogicalPlanReadRuntime.cpp from the parent while linking the current support library and tests; it is not a frozen before performance binary. Preserve `reverse-sort-parent-failure.json` and `reverse-process.json`. `run-sort-regression-control.py` reproduces that component control after the main runner. No source-side pressure/cancellation exception is swallowed or retried.

R2 borrowed bytes represent fixed decoded image sizes, including visited metadata types; they are not physical IO, RSS or an exact before/after memcpy reduction. Cache-miss moves/copies and other paths remain outside this assertion. First load authentication and current cache provenance/invalidation stay in the existing readers; no new cache or raised cap is added.

R3 reserves sizeof(holder) plus sizeof(FieldTransition) to cover named-return overlap even without NRVO. The same parent account is charged; the budget must outlive the holder. The holder cannot be copied/moved, and its result accessor rejects rvalues to avoid a dangling borrow. Caller-owned canonical extension bodies and future native map/allocator/publication buffers need separate admission. This wrapper is exercised by the native module test runner but is not connected to production property writes. It does not complete the native lifecycle or estimator.

R4's pressure count/oldest pair is coherent under one registry lock. Catalog and retire queue belong to the separately pinned observation root, so the entire observation is not a new transactional snapshot across concurrent registrations/publications. If registry oldest generation is newer than that root, lag is zero. Lag is a generation distance, not elapsed time. Queue fields count records, not bytes or distinct generations. Zero generations mean empty. The observer's pin still protects its reads and is excluded only from the reported pressure. This existing explicit observation already scans Catalog/retire queue; the change adds no scan to ordinary reads/commits and no extra traversal to this observation. Free-frame/tail budgeting and mature formal admission are not claimed complete.

R5's verifier preserves parallel edges and directional self-loops, allows the same type-token range as authoritative Edge (including zero), rejects duplicate/nonmonotonic IDs and stale/wrong identity, and checks exact first-edge resumption when supplied by logical continuation. Zero expected-first retains initial/lower-bound cursor semantics; no numeric contiguous-ID assumption is made. Empty terminal and full 64-reference batches are tested. Native producers must authenticate their on-disk routes and bind actual pin/store provenance before calling; database/generation fields alone do not establish that provenance. Each Lookup must use the existing authoritative Edge reader/record reuse, before any type filter. Lookup/guard exceptions propagate, no partial verified batch returns, and no auto replay occurs. The fixed result and transient return need native account admission when integrated. This is not a direct unchecked topology access path.

# 可选缓存拒绝、DELETE 预算与回收临时证据生命周期

完整 O6 准备复现三处阻塞，均保留负对照，不调整资源上限。

1. 公共实体批次将可选的 4 MiB 缓存视为完整结果来源；缓存拒绝后误报实体丢失。现在通过已准入的读取路径补取，并在深复制前预留拥有输出的字节。
2. DELETE 的隐式完整实体结果不能与 Kuzu 无返回结果直接比较。公共隐式结果语义保留；只有字面量 RETURN 使用内部引用行消费者，保留行的重复次数与删除身份。计划集合、保留输入、请求与逃逸结果均归属 QUERY；已耗尽 CACHE 的反证由 QUERY 所有权修复。
3. 原有 8 MiB 维护额度内，页面去重和物理池成员集合在消费后仍占空间，且发布向量与全部旧回收列表同时保留。现在完成完整校验后及时释放临时集合，逐项释放已经转入发布列表的证据。首次唯一性、可达性和物理池校验均不跳过；拒绝仍在发布之前。

新增五项真实模块测试覆盖缓存容量之外的 Node/Edge 完整输出、低预算标量删除、完整实体结果拒绝的原子回滚、CACHE 满额下的私有读取归属和结果释放退款。另修正两个旧测试文件的显式 PropertyMap 构造，以匹配已有 OwnedPropertyMap 接口，原断言不变。

完整输入验证：10,000 个 8 KiB Churn 节点一次原子删除，逐值核对 10,000 个 `[1]`，保留另外 10,000 个 User。随后同一图的 10,000 个不可达大值在原 8 MiB 维护额度内回收成功；重开、完整性、Churn=0 / User=10,000 校验通过。此为不计时正确性证据，不构成稳态或性能验收。

后续 O6 两端统一 `MATCH (n:Churn) DELETE n RETURN 1 AS deleted`，并核对所有标量与重复次数。该修复版本单独登记窗口；原 `6a735df8` 基线继续使用 hash 与原登记一致的不可变二进制及原 harness，不混合新旧样本。S0.3 和 S5.5 仍待完整验收，不新增计分。

最终受影响模块回归：**130 个模块／166 个套件／2,882 项测试，零失败**；30 项 campaign 测试与 14 个子测试通过。Release 的 13 类／886 次完整结果检查及额外四客户端 4,000 次操作通过；未运行全量单元测试。

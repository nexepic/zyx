# S2.2 原生 scan/filter/project/aggregate 接入

现有非 JIT 基线已贯通原生选择性属性读取、受认证批次发布、类型化谓词、标量投影、数值聚合及拥有数据的公开输出。`BoundNodeScanBatch` 保留原有有界源矩阵，绑定拥有名称的列布局，在预算允许时转换同类型整数/浮点字段，并加入绑定精确快照的 Node EntityRef 列。每次发布在消费者产生效果前校验完整矩阵。内部实体列名称不会与真实属性键冲突。源列继续执行读取前准入及解码后容量计费。

绑定的 Node 谓词按封存 ColumnID 和批次 RowID 消费。定宽单元使用仅栈分配的标量比较值；混合类型、字符串、列表、map 借用已经计费的源，沿用原有 variant 比较语义。名称属性读取桥接中 missing 和存储 NULL 仍等价，`exact_presence=false` 阻止消费者误认其为精确 presence 生产者。数值封装桥接未采用布尔列时，布尔过滤继续使用已有类型化 primitive 内核；不从观测类型建立永久属性 schema。selection 交集保留原始序号映射，批次 selection 发布保留重复及输入顺序。

清理被拒绝值或把源单元移入拥有数据的行之前，扫描销毁全部借用批次元数据。行/列交接保留为显式计费适配器。投影和通用聚合使用 S2.1 按算子作用域绑定的表达式输入；原生直接数值聚合使用相同查询程序/快照发布自己的封装。在发布边界创建不同批次 owner，避免跨修改保留借用。输出行及 QueryResult 独立拥有数据。混合类型、不支持的 reader 能力和可选元数据预算不足继续走原有计费语义路径。下游产生效果后不得重放源读取或 accumulator 更新。

验证通过 33 个绑定/布局/扫描谓词/原生集成测试，以及 222 个执行/selection/filter/aggregate 相关回归。前者覆盖扫描准备阶段每个取消检查点、owner 退款、schema 变化、无效 Node-ID 顺序、混合数值 variant 顺序、NULL、实体身份、重复 selection，及通过发布诊断确认实际原生 scan-predicate-project-aggregate 路径。新鲜原生正确性 smoke 验证 13 类工作负载共 916 条命令的完整输出、资源失败和快照。两组测试有重叠，不能宣称有 255 个独立测试。已有初始化告警仍保留；未运行全套或性能对比。

验收 S2.2 的首条 scan/filter/project/aggregate 接入路径。S2.3 其他消费者、S2.4 完整定向语义矩阵、S2.5 对比、因子化图中间结果、独立持久 schema epoch、全局预算和 spill 仍由原任务承担。不宣称全部属性载荷或全部算子都已改为类型化存储。不改变持久格式或公开 ABI。

# R3.2: durable inverse conversion, retirement and reuse

This round connects actual hybrid-to-ROW publication and fixes forward conversion's maximal-group account peak. Acceptance remains 13/24 (54.2%), without commit/push, a full unit suite or new performance/Kuzu timing.

The typed direction enum adds ROW_TO_HYBRID and HYBRID_TO_ROW with Windows-safe prefixes. Explicit inverse requests in isolated format 32 use the existing native transaction and exact source fence. Only this controlled route can acquire the writer on an installed nonempty layout; unadapted ordinary writes/reclamation remain rejected.

Metadata authenticates actual native sources and reuses accounted HybridPropertyRowPreparation. The current durable prototype requires exactly its one converted group/namespace. It enumerates group/column/extension locators and existing B+Tree retirement plans, auditing exact reverse ownership of physical fields. Each tree plan has a 128-page bound, per-page cancellation and a prepaid conservative 256 KiB standard-container frontier. The 4096-member bound applies to this inverse operation, not a lifetime group capacity.

New ROW roots share pages/pools with same-batch IDs and physical reservations. Existing authenticated independent single-field LargeValue references may be reused without a new Value ID. Other oversized ROW-carrier coordination is unfinished and refuses before disk writes. Existing canonical encoding preserves NULL, negative zero and NaN payload bits through actual durable round trips.

ROW frames precede one A/B publication installing allocator/Catalog/Page Directory/owner roots, removing native tree/field routes and descriptor root, and retiring candidate pools with their Retire Queue entries. At most 31 allocated frames per retiring pool are checked against current point routes, rejecting removal of unrelated current data without a whole-graph Page Directory scan. Source frames remain intact for old pins. Returning to ROW restores ordinary updates and reclamation. Clearing the descriptor does not downgrade the file: it remains experimental format 32, not production format 31.

The new 64-owner/4096-member test initially exceeded the 1 MiB account during actual forward publication, despite preparation-only passing. Decoded ROW roots/admission and classification workspace survived into index/physical publication. Reading/classification/field encoding now have a separate lifetime: field images and immutable proposals own their encoded bytes, so inputs/workspace die before later planning and refund afterward. Header-only decoding also finishes first. The limit remains 1 MiB. The maximal group now commits both directions and verifies old/current values and global integrity within that conversion account; full metadata/process-memory/cost admission is still unclaimed.

Twelve relevant modules pass 246 default cases and 359 experimental cases, with one format-conditional skip. These include publication/read/descriptor/shared-pool/snapshot/global-corruption modules and 26 existing B+Tree atomic-retirement cases. New coverage verifies native inverse commit and normal writes/writable reopen; partial/full inactive A/B recovery; old-pin release blocking and same-slot reuse at a different physical epoch without locator aliasing; independent-field reuse without incrementing next_large_value_id; propertyless groups; quota refusal and cancellation before/after physical writes with source preservation/refund/retry; unsupported ROW-carrier refusal; IEEE/NULL and maximal-account round trips.

Retained failures include the test's nonexistent traversal API (corrected to visitPageLocationsUntil), an IEEE fixture configured with ROW owner903 against seed902 (correctly rejected as foreign; configuration fixed), and the actual maximal-account failure before the storage lifetime fix. Source validation and the byte bound were not relaxed. Linux x86_64 only. Raw JSON/logs, exact link arguments, source/binary hashes and a complete workspace code patch against 9cc2821c are included.

Remaining: actual single/multi-field/whole-owner mutation publication while native routing is active; incremental maps across groups; fresh independent values and general ROW-carrier content/reference coordination; retirement/steady-state reuse of forward-cleaned empty ROW pages and old pools; complete costs, same-executor ROW comparison and R7; production R3.3 and unchanged R5.1–R5.3. Bidirectional prototype commits and reclamation tests alone do not complete those stages.

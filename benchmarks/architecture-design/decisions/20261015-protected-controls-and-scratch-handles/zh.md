# 快照控制与 spill 句柄内存

这是组件检查点，没有新增固定交付验收：22/34（64.7%）。本轮 5 项仍为 S5.3、S5.4、S5.5、S6.1、S6.3。没有启动新的性能测试。

原生文件别名共享弱注册、最多 1 MiB 的 MAINTENANCE 预付额度。元数据注册器状态、代际注册节点、读取上下文控制块及注册器的活动根枚举使用该额度；解码负载与缓存容器仍归 CACHE。元数据工厂分别传递两种 owner，不修改持久格式。新增压力测试发现空 deque 会立即分配缓存块，现已改为按节点分配的有界 FIFO list，使缓存负载额度耗尽时仍可创建空上下文。逃逸 pin 保留两种 owner。这保障控制分配与缓存负载压力分离，不代表所有维护任务都能推进；解码负载仍可能被正常拒绝。

查询 scratch 在获取文件会话租约或发布 owner 之前，先取得有限 QUERY 预付额度（4096 + 256 × 最大句柄数，单位字节）。会话对象通过 OwnedPmrObject 保留实际分配 owner，句柄 map 共享该额度；finish 后仍保留的对象继续计费，直至销毁。句柄节点仍在 IO 前插入。测试耗尽共享可用内存，检查拒绝时零写入、代际不变，释放压力后能复用单 segment 磁盘配额。载荷读写副本及 NativeBulkRunStore 工作区尚不在该句柄额度内。

事务保留的 Property patch 槽位及替换时的副本重叠使用已有 WRITE 分配器。拒绝复制后保留前一条语句，释放压力后仍能提交；回滚在关闭包装器继续存活前释放槽位容量。嵌套 key、set/remove 向量及 PropertyValue 负载仍待接入。

独立工作进程支持对已有文件强制退出，测试入口可在同一文件上重复崩溃、物理只读检查和可写恢复。每轮验证只读 SHA256 不变、用户数据、恢复后的完整性及单 segment 配额复用；记录实际文件大小，不截断或隐藏增长。当前源码的定向模块与逐分配点故障证据见 proof.json 和 module-evidence.tar.gz。新增 patch 压力用例最初为一个旧字段加一个 patch 字段提供了条目上限 1，现按现有接口合同改为 2，没有提高内存限额。

完整 WRITE/私有 COW/undo/overlay 与维护工作区、持久积压上限、分区聚合/哈希 spill 和最终验收仍待完成。早期分配次数仅代表当时源码，本检查点重新遍历当前正常执行轨迹的分配位置。没有新增固定进度，因此尚未触发对应的提交和推送。

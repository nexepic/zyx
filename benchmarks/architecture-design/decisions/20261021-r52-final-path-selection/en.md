# R5.2 final implementation selection: canonical key-only plus bounded primary reuse

Freeze the canonical bidirectional key-only B+Tree(index0x8000000000000002,BLVL_EMPTY) with bounded primary-record/routing reuse. Existing occupancy costs choose membership candidates versus scan; same-pin type/label statistics, supported reference width and semantic barriers drive R5.3 planning. No new trusted topology durability protocol. Graph read/write, space and resource admission still belongs to R7; this selection does not count acceptance early.

The covering prototype has tested both directions, ordinary writer coordination, pins/recovery/retirement, overlays and the same executor. It still authenticates every primary Edge, while physical-read-only setup needs explicit global reconciliation. Complete90-Edge hot-source allocation rises1703936→1835008bytes(+7.69%); retain the canonical tree in those costs. No validated replacement for primary checks and old-writer compatibility supports automatic production use. Keep laboratory readers and explicit writer options isolated. This is not a new latency-failure claim; no formal timing has run.

Shared segments remain an architectural cost comparison, not a revived per-node root/delta implementation: batches require EdgeId/NeighborId/TypeId, direction/visibility, continuation and directories while primary checks remain. Their added directory/COW/retirement/update costs lack a compensating benefit proof.17-byte canonical keys,33-byte covering key/value bodies and24-byte packed items are logical bodies, not whole-allocation claims. There is no complete persistent segmented lifecycle and no third production candidate. Do not expand an unproven storage subsystem.

The canonical choice is already durable in its IndexRoot/format contract; compatible ROW writers maintain the same primary and directional tree. Ordinary incremental images change no wire bytes. No extra flag that older writers ignore is introduced. Preserve primary authentication and existing atomic/resource bounds. Full-scale route/graph-index audits and six raw/optimized IR comparisons pass on both inputs. R7 latency/steady-state protections remain pending; R5.2 is not accepted merely by this decision.

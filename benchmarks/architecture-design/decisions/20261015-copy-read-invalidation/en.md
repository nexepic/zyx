# Copy reads and concurrent control invalidation

A current-source affected-module run exposed an adjacency-churn failure while background maintenance read the same file: buffer-pool invalidation rejected a pinned page. The prior checkpoint preserves that failure instead of reporting a clean run.

Typed copy reads previously acquired a public pin, released the cache lock, copied bytes, then unpinned. A concurrent writer could observe that temporary pin and reject control-record invalidation. BufferPool::readPage now copies under the cache lock, matching the existing bounded-copy read paths. SharedPagePoolAllocator copies the mutable pool control header into a fixed stack image; only the immutable data page escapes as a pin. Private COW rejection, typed generation checks, control CRC/visibility checks and the rule against invalidating explicit pins remain intact. Sequential misses still free transient cache storage after copying, while a live external pin retains its own storage until release.

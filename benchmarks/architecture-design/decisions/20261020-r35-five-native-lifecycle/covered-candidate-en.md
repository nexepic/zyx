# R5.1 covering-tree native candidate contract

Laboratory candidate only; no automatic graph route, reserved IndexId or production adoption. Reuse native EMPTY fixed-map leaves: 17-byte order-preserving (direction, NodeId, EdgeId) logical key and 16-byte little-endian (NeighborId, TypeId) suffix. Duplicate logical prefixes are corruption, regardless of suffix. TypeId zero remains valid; Node/Edge/neighbor identities are positive. Caller-selected laboratory index must not alias the production global adjacency tree or any reserved namespace.

Native graph transactions must stage both directional records together with the authoritative Edge, including self-loops and parallel edges. Candidate reads bind the actual Index Root Directory root, database and source pin; one bounded seek resumes at after-EdgeId+1 without rescanning a hub prefix. At most 64 outputs and one authenticated lookahead are private until every main Edge check succeeds. Continuation binds database/generation/direction/node/last/exact-next identities. No main-record check is removed. Native allocator, COW retirement and A/B fences are reused.

This is one candidate's protocol increment. Global reverse-entry completeness, backend type-index/statistics/overlay coordination, segmented candidate lifecycle, relocation/reuse, complete costs and final held-out performance admission remain required. Correctly checksummed missing/extra/wrong-direction records require full integrity reconciliation; a point read cannot establish global completeness. No stage acceptance or performance claim follows from this contract.

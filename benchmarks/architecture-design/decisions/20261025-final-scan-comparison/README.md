# Prepared final comparison — not yet executed

This is the single final measurement window requested for the scan-path work. It must not start until both real private images finish full integrity, actual whole-file space admission and all necessary module checks. `freeze.json` records exact source image, production archive and executable identities before execution.

The unchanged public probe uses one thread, three independent workers, three warmups and ten measured iterations. The four primary cases run on medium and holdout for the initial work binary, recalibrated frozen 369039d control, ROW candidate A, persistent candidate B and Kuzu. Historical AMD latencies are not used for current-machine acceptance. Full typed result bags and ordered results are checked against the CSV oracle. Timeout, resource and failed-worker evidence is retained. No full unit suite is invoked.

Registered point, adjacency, expansion and write guards compare both candidates with both controls. Large/Skew conversions refused the frozen resource/whole-file gates; their original ROW images are tested with A and the controls, and no B adoption is claimed. These failures must appear in the final total-cost report. Guard ratios above 1.05 require targeted confirmation and explanation; failed samples are never dropped.

`value-probe.cpp` is a separate diagnostic source derived from the same public probe. Use only `check-read` with no warmup and one iteration in the final window. It resets value counters immediately before each query and writes observations to stderr. It supplies no latency evidence and is never substituted for the production timed probe.

`evaluate.py` requires thirty samples per case, evaluates each dataset separately and lists speedups against both controls plus the Kuzu outcome. It does not grant acceptance or mark progress 100%. Lifecycle, space, resource, construction cost and stable guard gates remain separate requirements.

The saved `freeze.py` refuses to overwrite an existing campaign identity and requires completed construction logs and both actual 10% whole-file savings before hashing inputs, production archives, binaries, scripts and source files. Each worker receipt must match that frozen identity on resume. Public and diagnostic compile/link recipes are saved separately. `construction-costs.py` reports successful and failed construction resources without running queries; summed worker wall times and cumulative OS writes are explicitly distinguished from elapsed campaign time and disk peaks.

The registered matrix contains 177 timed worker processes and 3,900 measured case samples. Both per-worker `case_statistics`/`process-summary.csv` and pooled `summary.csv` retain P50/P95. Evaluation enumerates every expected guard case so a missing worker cannot disappear from the assessment. `verify-admission.py` is an untimed public correctness check used only after a completed image exists.

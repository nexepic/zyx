# V0 阶段退出：scan-supply-20261026（15%）

当前结论取代首次失败诊断；首次原始数据及 `quality.json` 保持不变。尚未测量或接受候选实现。`acceptance-registration.json` 在 V1 实施前冻结候选、性能门槛和资源限制。

## 证据与成本模型

- `baseline/` 冻结控制与 Kuzu，两个数据集、四项查询、各三个进程和十个正式样本，共 480 个结果校验通过。八项 P50 差距仍为 16.4–176.2 倍。进程及 P95 波动明显，最终使用同窗口控制，不能减去历史时间宣称收益。
- `isolated/` 使用 50 ms 叶子采样，同进程交替两次采样/两次控制；80 个完整 oracle 通过。全节点/标签采样与控制中位比为 0.9571/0.9700，均在 5% 观察扰动目标内。仅支持粗粒度 CPU 定位：208/71 个独立叶子样本；未知 libc/vdso 不分配给猜测函数，无硬件计数或调用栈。
- `current-work.*` 为冻结源码确定性计数。全节点查询 225,000 个候选、440 批，3,516 次组/成员解码、3,437 次列解码、83,614 次元数据解码缓存命中、10,031 次文件大小调用。151,552 字节为 BufferPool 物理读计数，不等于真实磁盘读取。身份已批认证，但源端预算仍逐值检查。
- `layer-receipt.json` 在真实持久 medium 文件上只读执行；全节点 10,076、User/CN 12,500 精确计数通过，十次结果正确且输入哈希不变。供给加简单消费 P50 为 246.994/87.1589 ms，内部字段供给加回调为 226.319/77.4556 ms。这是同进程包含关系的诊断区间，不能与公开查询时间相减；回调含谓词计算，不能称为纯 I/O。220,000/100,000 个值、440 批仍触发 220,880/100,880 次准入。这证明逐值管理结构及较大的供给包含区间，不证明任意单函数的精确耗时占比。
- `kuzu-plans.json` 保存 EXPLAIN 扫描/过滤/聚合计划，实际跳块未观测，不据此虚构 Kuzu 剪枝收益。

成本模型分为候选/可见性、组定位/认证、字段解码、逐值管理/交付、算子/结果。计数和时间分开，不能累加重叠的包含区间和 CPU 样本。必要解码按有效值线性增长，重复管理应按有界段/页面摊销。单函数耗时比例仍不确定，不能据 Amdahl 定律预测精确倍数，更不能直接据此改持久格式。

## 选型与预登记

先贯通保留布局的 A。最小实质收益设为八项主查询加速几何平均至少 2 倍、两个数据集全节点过滤分别至少 2 倍。这是验收门槛，不是预测结果或超越 Kuzu 的声明，避免在两个数量级差距下接受零碎提升。主查询/守护 P50/P95、内存或空间超过 5% 退化进入复核；可重复重大退化须解决。预算及单线程固定。仅当 A 剩余成本证据支持时进入 B。初始 holdout 基线已可见，但候选调优仅用 medium 或独立合成样例，候选 holdout 执行前冻结选型。

V0 完成依据是公开采用路径、供给包含区间、确定性工作量、观测限制和决策门槛已有记录，V1–V4 尚未验收。细粒度分配/流量缺失如实列为限制，不能假装其成本为零；后续工作量计数和资源测试必须验证实际消除的工作。

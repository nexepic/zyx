# A1 immutable input-column layouts and per-batch aggregate checks

Date: 2026-10-14. Status: a column-binding boundary is integrated into one production aggregate path. Complete physical-program/layout/data-snapshot envelopes, property-token consumer interfaces, and all-operator migration remain pending. Accepted progress stays 5/34 (14.7%), with no newly accepted complete item.

BoundColumnLayout is a noncopyable/nonmovable query-local owner. Ordered names are owned in shared-budget PMR vectors/strings, with a nonreused layout identity. BoundColumnId contains a uint32 index and uint64 layout identity. Foreign, reconstructed-at-the-same-address, zero-identity, and out-of-range descriptors fail. Producer string destruction or mutation does not change owned names. Name layouts do not specialize value types: numeric/dynamic types are still inferred independently for each batch by existing consumers.

Construction checks uint32 width, nonempty names, and duplicates using a charged PMR set rather than pairwise comparisons. Validation nodes live only during construction and refund afterward; retained name/string capacity remains charged until destruction. BudgetMemoryResource admits requests and growth overlap before upstream allocation and refunds failures. Query guards run for input/build entries; bad_alloc and cancellation cannot become unsupported-optimization results. Empty layouts are valid. Raw string_view borrows still require layout lifetime discipline and are not authenticated span views.

The production boundary previously mapped Node aggregate column names to indices only on the first batch and reused those numbers for later batches. Each callback now validates column width, every column's row count against selection, and original ordinal bounds before accumulating any row. It then validates the first batch's layout names/order. Initial optional metadata admission pressure can select an explicit name adapter before effects; that adapter validates each bound index against the expected aggregate AST property name on every batch. Only metadata MaterializedByteLimitExceeded is caught. Other errors propagate and accumulated rows are never replayed. Layout buffers release after aggregate input and before downstream output admission. COUNT(*) row-only and grouped row/evaluator paths are not migrated; all-operator coverage is not claimed.

No incorrect query from a legitimate reordered producer was observed. This closes a missing boundary in the existing first-batch-only binding. Synthetic layout reorder/rename/width tests prove rejection before consumer effects. Existing multibatch, batch-local type inference, corrupt-source, tight-budget optional-buffer release, and dynamic retry regressions pass. The new test file is registered in cmake/SourceSets.cmake's native allowlist.

Seven new layout tests cover owned names, order/width changes, foreign/stale identities, invalid names, preallocation budget rejection, and refunds/retry at every observed upstream allocation and guard failure.

# 原生大字段的有界检查

任务：R3.2/R3.3，仅为实现检查点，没有新增验收项。工作树基于远程 `work` 的 `9cc2821c`；变更及新增 C++ 文件身份见 `source-manifest.json`。验收进度没有增长，因此不提交、不推送。

`LargeValueStore::verifyContent` 复用现有已认证 manifest/chunk 遍历，逐块计算完整 SHA-256，不分配与整个值等长的输出。解码块和 manifest 前沿沿用范围读取的预算准入。取消、I/O 和损坏错误直接传播，仅完整认证后返回根。

规范值形状检查器增加不可变范围读取入口，与借用缓冲入口共用同一验证实现。继续检查子范围、flags、标量长度、嵌套深度、数量及 map 键的规范字节顺序；map 键按 256 字节块比较，不分配完整键。调用方必须先认证整个不可变来源；跳过字符串／字节正文不等于内容认证。

原生 integrity、非 NULL 检查及输出编码额度预准入共用 `HybridPropertyLargeFieldInspection`：先认证整个值，检查既有单字段 envelope/token，最多保留一个已认证原始块供范围复用。manifest、临时输出、块缓存及目录预算持续覆盖各自缓冲生命周期。非 NULL 检查在内容认证后保留原有仅检查 canonical 头的结构语义；拥有数据的值解码仍遵循原有输出／分配合同。

定向检查覆盖位变异／截断、长键和无符号字节键、读取错误／取消、分层 manifest、压缩、合法块校验和下的完整哈希错误、额度拒绝／重试及既有范围／快照／重开／故障模块。原生 512 KiB 字段在 128 KiB 额度内通过 integrity、非 NULL 和预准入，且不解码 PropertyValue；分层载体测试还验证同额度下 owning 读取明确拒绝。这些是资源／正确性检查，不是性能成绩。

逐用例最新状态：默认 86 项、实验 124 项通过，来自 `proof.json` 中的分批定向运行，并非一次全通过矩阵。实验首轮有一个新夹具失败：大来源占用了夹具固定逻辑 PageId。夹具现从未使用的逻辑 ID 选择，保留历史小案例和原有断言，随后受影响模块通过。首轮失败证据保留。未运行全量单测，仅验证 Linux x86_64。

## 用户要求的开始对比

代码修改前已从实际 `9cc2821c` 重建 Release 对比二进制。small 扫描基线运行三个独立轮次，每场景三次预热、十次测量，单线程，关闭 PROFILE。全部轮次的标量及完整分组／Top-K 结果检查通过。二进制及来源清单位于 `benchmarks/architecture-design/results/20261020-work-resume/start/`；压缩样本、登记及来源 hash 保存在 `raw/`。

各进程 P50 的中位数，单位 ms：标签过滤 11.4647 对 Kuzu 0.276455；实际 group-by 11.5349 对 0.409294；一跳 0.772040 对 0.231327；两跳 0.955275 对 0.522976。十个被测场景均慢于 Kuzu，完整分布见压缩比较 JSON。

这个 small 起点观察不构成 R7 准入：原生 C++／IPC 与 Kuzu Python 的入口不同，原生预算保留 benchmark 默认值，Kuzu Buffer Pool 明确设为 64 MiB。页缓存和查询预算不是同一概念，不能宣称严格同资源比较；也不替代最终 medium／留出、写入及稳态资源窗口。

剩余：原生 data／manifest／内容索引／目录／描述符的物理原子发布、权威写入和双向布局转换、全局恢复／integrity／回收／搬迁、完整成本、R5 候选及最终 R7 准入。非空持久布局保护仍保留，生产属性继续使用 ROW。

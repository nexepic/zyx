# 逻辑 ID capability 原子注册

直接命名空间预留在持久发布后才插入 Node/Edge capability；缓存及新租约获取逐个注册范围。后续节点分配 OOM 时，调用可能失败，却留下可领取的未返回 capability。现改为先校验和准备所有种类/范围，再发布命名空间或改变 outstanding 表；在既有租约锁下以相同分配器转移节点，不再分配。新缓存尾部与返回范围在发布前准备，持久发布及回收阶段结束后才安装。转移前验证完整区间重叠。较早缓存获取失败时允许跳过未返回 ID，ID 租赁不改变用户图根。

120 项受影响元数据/租约测试通过。独立工作进程在失败后逐个检查已知范围不能被领取，要求其他活跃 capability 不变；成功时验证完整结果、仅能领取一次，并在重开后验证完整性。全部 163 个直接预留、4 个缓存获取、169 个新租约获取分配点及 4 项既有场景通过。冻结旧编译单元分别在 162、3、168 点复现部分注册泄漏。复现需先恢复本检查点源码 patch/头文件；后续 capability 分配器接入可能改变元数据对象私有 ABI。

本检查点修复异常原子性，尚未为 capability map 分配接入协调预算。下一步为 PMR 表配置发布前取得的有限共享 WRITE 额度，并保留同分配器节点转移。没有新增固定验收：22/34（64.7%）。没有执行全量单元测试或性能测试。

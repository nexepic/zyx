# 快照与解码元数据缓存分配归属

本检查点不新增验收项，仍为 22/34（64.7%）。

原生新建/打开现将已有的文件域共享 64 MiB 缓存额度传入元数据工厂及快照注册表。注册表状态/控制块、代际映射节点、读取上下文状态/控制块、哈希桶/节点、FIFO 存储、缓存页对象/控制块及活跃根向量工作区均通过拥有生命周期的分配器或 PMR 计费。元数据发布锁内仅使用预付额度的局部准入，不获取进程协调锁。

Catalog/位置叶条目及元数据路由数组改用拥有资源的向量，显式线程局部构造/复制作用域将 codec 和缓存副本绑定到目标归属；逃逸副本继续保留分配域。分配器固定捕获借用的默认资源，并在移动后保留源容器可复用的分配器。原生额度显式使用进程生命周期的 new/delete 资源，避免借用临时默认资源。仅改变内存归属，编码页布局及版本不变。

协调解码缓存仅接受六种已审计原生 codec 页类型。未注册的含堆载荷页（包括未注册的嵌套拥有向量）不会绕过计费或淘汰有效条目。额度压力下，缓存副本分配失败会释放该可选条目，允许重新完成一份经认证的解码；可选缓存插入失败回滚元数据并放弃保留。普通底层分配错误保留原有错误语义。chargedBytes 仍是原局部逻辑上限，实际请求分配由共享额度 used 计数，未使用额度继续计入全局预留。

最终源码通过 41 个套件的 829 个定向测试，覆盖元数据 codec/树/目录、快照并发与生命周期、查询运行时、原生读取/输出/事务隔离、缓存/Codebook 与 scratch 故障。重建后的独立事务故障程序再次通过四个 OOM/终态保留场景。未运行全量单测或新增性能测试，源码散列及原始证据见同目录归档；不冒充最终 S6.1 验收。

NativeReadSession 独立的 token/Property/schema/pool/cursor 缓存仍待共享归属；计划 IR/编译、写私有/undo/overlay、维护/恢复、其他临时工作区及非读取输出亦待完成。缓存满时的受保护维护进度、有界可观测长快照积压、分区 hash/aggregate 及最终故障/长跑验收仍未闭环。未新增固定项百分比，未提交/推送。

# A1 类型化列基础合同

任务：S1.1/S2.1 的局部基础。状态：定长列/批次已通过模块测试；直接引用的槽位适配器已接入普通多项投影，列批次尚未接入查询路径。不代表完整设计、执行链路或性能验收。

## 当前链路与替换边界

现有 LogicalPlanReadRuntime 持有字符串键行、属性缓存、EntityRef 和若干选择读取快路径。BoundedBatch 管理通用行的逻辑字节预算，BudgetMemoryResource 已为部分 PMR 容器计费。本组件复用后者，增加固定类型的连续列，不替换 parser/逻辑 IR，不改变存储格式、QueryResult 或 Driver ABI，也不新增数据库 backend。

实现入口：`src/query/execution/FixedWidthColumn.hpp`。后续绑定器将编译期变量名转为槽位，槽位确定列类型；本轮没有假装将旧 map 行适配为列就完成 A1，也没有改变现有查询调度。

## 已确定的局部接口与所有权

- 支持 int64_t、double、bool；布尔使用连续 uint8_t 载荷，避免 vector<bool> 的代理引用。列内没有字符串键或每行动态类型分派。变长、复杂、混合类型的拥有化列和有语义等价性的动态回退留待后续实现，不拒绝原数据库支持的类型。
- 一个连续值数组加一个逐行状态字节，状态明确为缺失、NULL、有效值；NULL/缺失位置载荷初始化为零，消费者必须检查状态。该状态编码只在内存使用，不是持久 codec 或公共 ABI。
- 每列显式传入最大行数和查询共享预算；不硬编码 benchmark 大小。容量从 1 有界倍增，到最大行数为止；计费包含两个数组的真实容量及扩容时旧/新分配重叠。
- clear 清空逻辑行但保留已计费容量以复用；release 和析构返还分配。truncate 仅允许缩小，用于矩形批次多列追加失败时撤销尚未发布的行；预算不因逻辑截断而错误退还仍存活容量。
- 列自身拥有数据，预算必须比列活得更久；不可复制/移动，避免内部 PMR resource 地址失效。借用 span/值引用在任意修改后失效。当前不借用存储页、不持有 snapshot pin，也不允许 EntityRef 被误当成普通整数免校验。
- 列及 allocator 状态归任务局部所有；多个列可共享同一单线程预算，但不同时并发修改。未来并行任务需单独局部计费与受协调的共享额度，不能将此非原子预算直接共享给工作线程。

## 失败与生命周期

非法行上限、空 allocator、越界访问及读取 NULL/缺失载荷显式失败。追加先完成两个容量申请，再发布长度；预算不足、分配失败或行上限超限不会改变已有行。若第一个容量申请成功而第二个失败，已分配容量允许保留，且仍准确计费；release 可释放。上游 allocator 抛出异常时 BudgetMemoryResource 回滚尚未成功的预算申请。

查询取消由上层 batch/算子边界检查，错误向调用方传播；本列不自行吞错或截断结果。多个列组合时上层先保留所有列旧长度，成功后才发布批次行数，失败调用 truncate 回滚各列。不得向消费者暴露非矩形中间状态。列仅为进程内任务数据，无持久恢复/回收协议；析构按数组、allocator、外部预算的顺序释放。

## 状态划分与后续完整 A1

不可变物理计划拥有槽位布局与表达式/访问描述符；查询共享状态拥有快照、guard、总预算和输出合同；任务局部状态拥有列、选择向量、游标和局部聚合；阻塞算子拥有合并/排序及未来 scratch。物理计划不能持有可复用 batch 或借用页 pin。具体绑定/缓存 schema 身份、变长 owner、所有算子适配、分组表示和公开输出拥有化仍需完整 S1.1 决策，因此本项不单独验收 S1.1/S2.1。

性能假设：连续类型化数据与复用容量可减少每行 map/动态对象成本。反证：同输入的最终执行链路若没有收益，或在点读/资源保护场景产生不可接受退化，则调整或拒绝使用；仅组件测试通过不构成性能结论。按用户最新要求，性能实验留到优化实现完成后。

## 矩形批次组合

`src/query/execution/FixedWidthBatch.hpp` 将已确定类型的列组合为任务局部批次。列对象以内联递归布局在最终地址构造，不为每列建立未计费的 heap owner；数组继续复用共享预算 allocator。模板列类型在编译时确定，当前只支持上述三种类型，尚不构成通用运行时槽位布局。固定对象元数据位于调用方对象中；父执行状态后续负责其计费，不宣称当前列预算等于完整查询内存或 RSS。

TypedCell 的构造接口仅允许有效值/NULL/缺失三种状态，值访问拒绝无值状态。批次仅公开 const 列访问，消费者不能破坏矩形性。追加依次写入各列，全部成功后发布一次行数；预算或上游分配失败时，所有列截断到先前已发布行数，再重新抛出原异常。保留扩容容量及计费，不将失败回滚解释为全部释放内存。clear/release 作用于全部列；批次不可复制或移动，所有借用在修改后失效。

7 项 `FixedWidthBatchTest.*` 与原 10 项列测试共同通过，使用同样的 C++20/警告作为错误编译条件。覆盖跨列三态、前列成功/后列失败、已有行之后部分扩容失败、预算压力释放后重试、上游 bad_alloc 后重试，以及整批复用和释放。测试文件：`tests/src/query/execution/test_FixedWidthBatch.cpp`。本组件仍待槽位绑定、选择向量、EntityRef/变长 owner、物理算子与输出接入；没有新增 S1.1/S2.1 验收，也未运行性能测试。

## 计划内槽位与作用域

`src/query/execution/BoundSlotRegistry.hpp` 建立编译期变量名到计划内 uint32_t 槽位的映射。名称哈希查找仅供绑定阶段使用，消费者后续保留槽位，不在每行重新解析名字。每个槽位/作用域携带不复用的进程内计划身份；注册表地址重用也不使旧 ID 有效。此身份不是数据库、schema 或快照身份，不能代替后续属性 token 与计划缓存依赖认证。

作用域仅引用先前创建的父作用域，因此无环。lexical 模式允许沿父链解析名字，局部声明产生新槽位并遮蔽同名外层变量；isolated 模式只查本地。显式 importFromParent 从直接父作用域的可见名字导入别名，复用原槽位，不能越过隔离边界或看到兄弟作用域。这里只提供作用域机制；完整 Cypher binder 必须按现有表达式/子查询语义选模式，不能将所有子查询一律隔离或改变已有可见性合同。

绑定数（含导入别名）、作用域数和名称字节数均有显式上限。PMR 数组、哈希节点/桶和长字符串归计划拥有的编译预算计费；该预算必须比注册表及缓存计划活得更久，不能借用会在单次查询后销毁的预算。内部记录禁止复制，容器扩容移动时保留原 allocator；固定对象元数据仍由父计划 owner 负责。声明在名称索引与槽位描述符全部成功后发布计数；分配失败撤销新名称，允许保留准确计费的容量。seal 禁止所有布局修改；seal 后可只读复用，调用方必须保持注册表生命周期。

12 项 `BoundSlotRegistryTest.*` 通过，C++20/Wall/Wextra/Werror 编译；覆盖声明/遮蔽/导入、隔离边界、外来和地址重用后的 ID、sealed 布局、上限、逐分配故障与重试、作用域/描述符扩容和共享预算返还。测试文件：`tests/src/query/execution/test_BoundSlotRegistry.cpp`。此模块尚未遍历真实 LogicalOperator/Expression，也没有完成类型推断、schema 缓存身份或查询算子接入；保持 S1.1/S2.1 未验收。没有性能 benchmark、全量测试或提交推送。

## 真实投影引用绑定的过渡接入

实现入口为 `src/query/execution/BoundProjectionReferences.hpp`，由 `LogicalPlanReadRuntime.cpp` 的普通多项 Project 路径使用。直接 VariableReferenceExpression 在执行算子初始化时根据子算子的可见输出绑定为计划内数值槽位；同一源变量的多个引用复用同一槽位。属性表达式优先绑定同名投影列（例如 WITH n.rank 暴露的 n.rank），否则绑定 n 的值槽位，再调用原 readProperty 读取属性。规范名称匹配不生成未计费的临时字符串。这里不是持久 PropertyToken，不需要假设动态实体的永久字段类型，也不把此局部绑定器放入逻辑计划缓存。

适配器每行仅在输入边界解析旧 values 哈希表，指令通过数值下标借用该行的值。PMR 名称索引、槽位描述符、指令及借用指针数组共用当前查询预算；子算子输出名称的临时数组/动态字符容量在持有期间计费。该临时数组仍由既有 getOutputVariables 接口先生成后检查，未达到全查询分配前准入；后续不可变物理计划应提供已预算的借用布局，消除该复制接口。固定对象元数据仍需由父执行 owner 最终统一计费。

RowBinding 在输入行销毁、输出回调或异常离开之前清空借用指针。借用不跨行、不跨查询或缓存计划；适配器为查询局部不可移动 owner，不能并发使用。现有局部推导通过 insert_or_assign 临时替换并恢复值，不删除已有输入节点，因此绑定的值地址保持有效。单项拥有化/缓存移动快路径、复杂表达式及未知引用保留原语义求值；无法解析的引用在实际求值时按原规则报错，不提前改变空输入的错误语义。字段缓存、EntityRef 和选列快路径继续使用原实现。

移除边界：真实物理批次 producer 输出相同槽位布局后，删除此旧行输入适配；所有表达式绑定完成后删除对应动态回退；单项转发应迁移到相同物理投影指令的拥有化模式，而不是长期保留独立执行器。当前仍有字符串哈希、动态值、属性缓存和复杂表达式 RTTI，不能称为完整类型化执行。适配成本可能抵消部分查询收益，最终基准需要单独验证，而非以模块测试时间推导性能。

# P4 标签候选访问验收

进度 65%；85 项相关模块测试通过，未执行全量单测或正式性能矩阵。

复用既有标签 B+Tree、原子维护的 TokenCardinality 和 Entity Map。Node 访问选择改为按实际记录/索引键宽度与页验证字节估算工作；极稀疏候选无需采样，全覆盖标签直接顺序扫描，其余最多检查首 64 个候选的实际页局部性。前缀估计只选择访问路径，不能回答查询；缺少统计、不一致计数和扫描预算继续保留认证候选。没有添加持久索引或另一套权威缓存。

候选批先验证主标签，再检查所有标签；多标签批不超过既有 128 条实体缓存，避免第二次标签验证重解码。输入/顺序/别名校验保留。采样瞬时集合计费，额度拒绝只允许在未输出任何候选前回到扫描；输出后不重启，避免重复。

medium 普通过滤/真实分组各一次只读机制诊断：从 225000 个 Node 扫描降至 100000 个认证候选、100000 次实体解码，前缀 64 行落在 1 页。结果 oracle 一致；不是正式时延数据。1024/400 的模块夹具验证精确 400 次解码，全覆盖标签走 1024 条顺序扫描；多标签、替换、删除、旧 pin、实际 read-your-writes overlay、rollback、重开、取消、统计损坏和游标上限均通过。

扩大测试发现普通 8192 边写入逐行申请 ID 会累积 capability map 并拒绝原有额度。批协调器改用现有区间预留与 ReservedId 创建接口，保留独立耐久高水位、取消和回滚语义；8192 边只申请一次 ID 区间。不提高额度、不改变文件格式。这是 P6 的必要依赖，不单独授予 P6 权重；异常栈仅为定位证据。

局部性前缀无法证明全部碎片分布，成本单位不是拟合延迟。P5 仍须解决 100000 个字段的定位/解码及直接批消费，最终结构性收益和 Kuzu 目标留待 P7。

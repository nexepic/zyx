# 受保护的完整性扫描工作区

本记录仅为组件实现，验收进度仍为 22/34（64.7%）。原生完整性检查在发布锁之外申请可配置的 8 MiB MAINTENANCE 额度，扫描器 map、set、vector 槽位及拥有所有权的页面缓冲按实际分配请求计入额度。扫描作用域保留脏缓存命中的可见性，顺序读取未命中时不申请缓存驻留，并禁用扫描期间的解码元数据缓存。共享页、SlottedPage 副本和临时读取会话优先继承调用方明确指定的分配域，包含主扫描之后的约束支持树检查。

进程/数据库总量及各类别上限不变，数据库级新增与进程级相同的 16 MiB 维护保留量，避免前台额度耗尽时阻塞维护。快照解码缓存容器延迟构造，覆盖标准库可能为空容器分配的哨兵节点；可选缓存准入失败后仍可重试。

55 个套件、1,430 项定向测试全部通过。覆盖低额度拒绝、归还且不写入/不推进代际、只读重试、含 LargeValue/唯一约束/向量索引的数据在 CACHE 耗尽时完成扫描、前台 QUERY 饱和、缓存全部被 pin、脏页可见性、私有页保护、作用域恢复和线程隔离。没有运行全量单元测试或新的性能基准。

CACHE 耗尽测试曾真实失败。分配调用栈依次定位到共享页 payload、SlottedPage 副本和临时读取会话 deque 强制使用快照 CACHE。修复调整分配归属及扫描策略，没有提高配额或降低断言；归档保留了早期失败和最终通过的证据。

同时包含前轮输入语句原地规范化：四个去重集合使用 WRITE，属性/标签请求稳定压缩，不再创建持久目标的临时请求向量。普通暂存 5 个、混合暂存 17 个分配失败点以及各自的 4 个清理用例通过。这是分配次数证据，不是性能测量。

冻结的当前 worker 已通过所有 4,346 个实际触发的分配失败点：暂存 5、提交 3,941、overlay 16、创建 10、overlay 创建 21、直接/缓存/新块 ID capability 登记 163/4/169、混合暂存 17。另有 4 个终态清理/保留用例，以及重复 32 次 scratch 崩溃恢复的一条流程，共 4,351 个通过用例。各阶段针对该固定工作负载及二进制穷举；这不等于穷举所有操作/工作负载。每轮恢复文件均为 1,572,864 字节，物理只读检查前后文件 SHA-256 相同。嵌套标准 codec/schema/property 负载、其他维护任务、积压、编译/IR 所有权和分区算子仍待完成。本记录不验收 S5.3/S5.4/S5.5 或 S6.1/S6.3。

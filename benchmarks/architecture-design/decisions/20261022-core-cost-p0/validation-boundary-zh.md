# P1/P2 校验范围决策（用户已确认；实现待完成）

## 已核对的现行行为

`MetadataRouteBranchReuseTest.UnmodifiedCorruptLeafIsRejectedBeforeAnyPublicationFrameAllocation` 在三片叶子的旧树中修改第一片对应路由，损坏第三片，然后要求构建新树在分配任何发布帧之前失败。`collectRouteBranch` 还全局检查路由目标、bootstrap frame 的重复与别名。当前缓存通过全局 StorageIO mutation epoch 失效，未保存跨提交的完整认证证明。

## 无法同时无条件满足的要求

如果一个无关页在已有证明之后被独立改坏，修改路径的页与根引用均可保持不变。只访问修改路径的提交无法区分“无关页完好”和“无关页损坏”两种文件状态。根中的校验和/Merkle 摘要不能在不读取该页时证明实际磁盘字节未改变。仅保存旧认证标记也不能证明新发生的损坏不存在。

因此，若将现行测试推广为“每次提交都必须发现未访问分支的新损坏”，则严格 O(k×h) 普通提交和该保证不能同时成立。需要明确校验边界，而不是把现有断言删除或让失败测试变绿。

## 推荐合同：局部访问验证，加完整 integrity 检查

- 普通读写验证所有实际访问页的 CRC、类型、身份、代际、键范围与可见性；修改路径的新图像在发布前完整验证。
- 已有未修改子树按精确不可变根引用复用；新路由目标必须来自当前批次独占分配，避免新修改造成跨树别名。对原先所有全局不变量逐项给出归纳证明或有界辅助索引，不能直接假定成立。
- 发布的原子性、同步顺序、旧快照、取消/失败回滚和回收保证不变。
- 未访问分支中后来发生的损坏，在首次访问或显式完整 integrity 时发现；不能承诺无关提交提前发现。这是可观察的错误发现时机变化，必须公开记录。
- 现有全树收集/integrity API 仍须拒绝未修改叶损坏、重复/孤立及别名；新增测试分别证明局部写不访问无关叶、访问损坏页必失败、完整检查必失败。不得把旧全局测试简单删除。
- 变更适用于新合同；若格式中的局部信息不足以验证新增关系，先补元数据和版本化，不直接启用快速路径。

## 保守替代

维持每次提交的全局检查，可复用同一次提交内的认证结果、减少重复构造、改进缓存与布局，但不能将该路径宣称为与 M 无关的增量提交。移到启动时执行一次完整检查，需要另行接受启动 O(M) 及随后未检测的存储损坏边界，也不是免费解决。

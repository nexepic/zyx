# P6 有界导入与发布生命周期

实施进度 90%，262 项受影响模块测试通过；没有执行全量单测或正式性能矩阵。导入复用现有 1000 行公开批接口、区间 ID、按页实体/属性写入、有序索引修改和 P1/P2 增量发布，不提高额度、不更改持久格式，也没有另建 backend。

修复实体插入目标缓存丢失“已检查且没有空槽”的结果。每种记录类型的完整性证明绑定精确物理 COW 根（包含 generation）；当前句柄发布维护证明，其他句柄改变实体根后必须重新发现。只记住正候选不能避免满页批次触发反复全目录扫描。65 行整页批连续三轮的实际记录：缓存命中 3、实体目录遍历 0、全量元数据遍历 0。

生命周期测试同时发现旧句柄仍持有另一句柄发布前的控制页/分配状态。生产句柄现在按已打开文件的身份（设备/inode 或 Windows 文件身份）及数据库 ID 共享发布屏障与快照登记，保留每个 registry 的句柄/guard 所有权和原账户。打开时保护所有句柄的 pin；发布源改变后先丢弃旧缓冲内容，再按持久根和全部 pin 重建缺失的分配/退休证明与逻辑 metadata ID 上界。自身发布（含 ID 租约等直接发布路径）同步源身份，普通单写句柄不触发这条全量恢复。恢复联合多个根时，已登记的空 emergency reserve 不再被误判为当前旧根的别名。新路径不改变 A/B、data-before-root 或实际页校验。

实际反例回归：260 个原始节点，其他句柄删除后负缓存失效并访问 259 条当前映射；20 次轮流发布后，驱逐旧 view 的记录缓存，旧 pin 仍读到原始全部节点。排空、完整检查与重开通过。公开 API 一批 1000 节点＋1000 边仅预留两个 ID 区间，无全量元数据回收，重开后索引点查、两组各 500、拓扑和属性聚合均正确。JSON 中保留真实 RecordProperty 计数。

**剩余核心缺口未掩盖**：冷打开后的首次实体插入仍按所有实体映射寻找空闲页；初始 medium 诊断的一批 1000 节点枚举了 225000 条映射。内存负缓存只消除连续导入的重复扫描。P7 正式冻结前必须消除此冷路径总量成本，不能把它挪到计时外，也不能把当前计数称作已达到 Kuzu。原始计时为嵌套诊断，仅使用工作量计数，不相加或充当正式延迟。

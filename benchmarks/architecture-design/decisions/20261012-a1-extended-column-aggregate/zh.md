# A1 直接列消费者扩展到集合、标准差与分位数

日期：2026-10-12。状态：当前源码构建后，27 个相关模块套件共 432 项测试通过。仍为 S1.1/S2.2 局部交付，不增加完整验收项。

直接 NodeScan、无分组、非 DISTINCT、同一节点直接属性参数的列消费者新增 COLLECT、STDEV、STDEVP、PERCENTILE_DISC、PERCENTILE_CONT。分位数额外参数由既有通用参数验证与工厂创建协议处理；COUNT 属性只在其他值消费聚合已需要同字段时复用载荷，继续保留独立 COUNT 的无载荷探测路径。所有扩展聚合复用原累加器、最终输出和实际状态计费，保持物理扫描顺序。

集合与分位数存在增长容量，本轮不将 MIN/MAX 的失败重试推广到这些状态。含扩展聚合的批次直接消费动态属性列，不创建可选数值转换缓冲；由此避免转换缓冲与增长状态争抢预算。这是明确的过渡边界：仍需完善各聚合的类型化内核、分组及 DISTINCT 等迁移，不能声称完整物理执行层已经完成。

新增四项测试，包含原标量路径与列路径的标准差/分位数结果、COLLECT 扫描顺序、共享 COUNT、混合 SUM、缺失和 NULL 跳过、集合结果拥有化、错误数值传播、预算拒绝后重新执行以及空输入结果。初版预算测试期待内部专用异常，但 1 字节上限首先触发既有结果列预算检查并返回 runtime_error；经核对该公开合同后修正测试期待，没有修改生产错误行为。这项预算测试验证查询边界拒绝，不代表已经覆盖新增累加器全部容量增长点；已有累加器模块中的准入测试继续通过。

# A1 可选数值缓冲向极值复制让出预算

日期：2026-10-12。状态：补齐混合数值/宽动态极值的复制准入退回，428 项相关模块测试通过。仍是 S1.1/S2.2 局部实现，不增加完整验收项。

## 问题与替换边界

此前为 MIN/MAX 首次保留数值结果预留标量空间，但该额度不覆盖字符串等动态极值的复制需求。SUM 已经完成当前行累加时，MIN 的宽结果复制可能被仍存活的可选转换数组和描述符挤占预算；此时不能重新执行当前行，更不能重读整个批次来重试。

PrimitiveNumericColumns 新增 release，销毁自身描述符和数组并归还实际 PMR 容量，其他查询 owner 的预算不受影响。没有任何类型化字段的批次，在聚合前立即释放转换描述符，直接使用原动态列，不长期占用无收益的 metadata。释放后可重新准备新批次；已有类型化访问全部失效。

MIN/MAX 的复制准入明确区分 guard 失败与 updateScratch.set 的真实预算拒绝。只有后者、且仍有可选转换 owner 时，才释放可选缓冲，改用原动态列，并仅重试当前极值更新。输入行数、先前 SUM/COUNT 以及其他已完成聚合项不重放。当前批次后续值保持动态消费；下一批次仍可独立尝试转换。

该重试依赖原 MinAccumulator/MaxAccumulator 的 updateAdmitted 合同：复制及所有 guard 完成后才替换持有结果，准入失败不发布新状态。此规则不能直接推广到其他可能在失败时保留新容量的聚合器。再次准入失败直接传播，不循环重试、不提高预算，也不改变输入顺序。

guard 检查位于真实字节准入捕获之外。即使嵌入方的 guard/sampler 抛出相同的 MaterializedByteLimitExceeded，也不会被标记为可选缓冲压力；bad_alloc、损坏与其他错误继续传播。最终拥有化输出的实际预算需求仍独立检查，释放转换缓冲不保证任意预算下都能返回结果。

## 正确性与资源验证

新增 3 项回归：

- PrimitiveNumericColumns 的 release 只归还自身容量，保持另一个共享预算 owner 的 256 字节不变；释放后重新准备并正确累加。
- SUM 与宽字符串 MIN 在一组 4–16 KiB 预算下执行。首个宽极值随后被短值替换，避免最终输出的真实宽载荷要求掩盖复制退回。至少一档完成查询的预算实际发生缓冲退回，最终 SUM 为 7 而非重复累加的 14，MIN 为短字符串。
- 通过真实 QueryGuard 的自定义 sampler 在极值复制阶段注入与准入相同类型的异常，确认异常传播、没有缓冲压力重试；移除 guard 后同一计划可重试。

预算枚举只核验资源边界与结果，不比较耗时，不是性能 benchmark。初版测试错误地将节点页行限保留为 2、节点总上限改为 1，既有 bounds 合同正确拒绝；已使用兼容的两节点上限。另一初版保持宽最终结果，其复制退回成功后仍可能在拥有化输出时真实超限，因此最终测试用短最终极值验证当前重试合同，不将真实输出超限改成成功。

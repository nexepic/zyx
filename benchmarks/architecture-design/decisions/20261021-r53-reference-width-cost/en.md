### 2026-10-21 R5.3 reference-row width and JOIN retention costs

Evidence: `benchmarks/architecture-design/decisions/20261021-r53-reference-width-cost/`. JOIN selection accepts optional estimated retained bytes for both sides, preserving cardinality selection if either width is unknown and original order on equal byte estimates. The native provider models only bounded Node-scan/single-hop reference chains with usable maintained statistics and no property payloads. Width matches the existing logical runtime row metric: row object plus each variable name, value variant and EntityRef. Expected rows multiply this width with checked overflow. This is a logical retention cost, not an allocator/RSS estimate or memory-admission grant. Actual runtime budgets remain authoritative.

Unknown/malformed label or type estimates, unsupported operator envelopes and property payloads refuse this model, preserving fallback behavior. The initial regression exposed an unwanted variable-name-driven reorder under unknown label counts; the provider now requires the relevant maintained statistics.

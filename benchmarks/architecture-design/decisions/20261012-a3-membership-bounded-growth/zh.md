# A3 目录有界扩容与 owner 暂存预算

日期：2026-10-12。

将 token 目录每 owner 精确 reserve 改为至多翻倍且受 maximumFields 限制的请求容量，避免连续单字段 owner 引起逐次复制。增长取 max(本次所需、旧容量加 min(旧容量、剩余上限))；需要增长时旧容量小于所需，而所需不超过字段上限，因此差值不下溢。保留分配前预算及分配后的实际容量回报。

owner 枚举数组在构造前准入请求容量，构造后更新实际容量，并与目录、当前源数组、LargeValue 临时缓冲合计。返回前释放该数组并更新回报。token 扩容后额外回报新数组实际容量与旧数组容量之和，以补齐之前仅按请求值计算的峰值；此时旧数组已释放，回报是保守的扩容峰值准入。严格分配前限制仍需预算 allocator。

新增真实 33-owner、每 owner 一个不同字段的测试，逐个核验字段，比较紧凑目录与增长目录容量，检查最终回报等于目录实际容量且峰值更高。五个限定模块共 59 项通过。构建、测试 JSON 和源码 hash 在同名 results 目录。

仍未覆盖 NativeReadSession、输入页复制缓冲及 allocator 元数据，不宣称统一预算或 RSS 限制。A3 真实页布局、更新生命周期、恢复回收及成本验收仍待完成。现有按检查次数触发的取消回归不应继续被解释为固定第 100 次必然对应复制阶段；codec 层测试独立覆盖校验及复制。

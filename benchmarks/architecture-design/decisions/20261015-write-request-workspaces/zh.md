# WRITE 请求槽位与规范化工作区

原生事务的六类请求槽位改为内部 OwnedMutationBatch，公开 batch 表示不变。复制显式保留分配 owner，新缓冲区先准入再替换旧状态；终态在关闭包装器继续存活时归还槽位容量。替换目标索引也使用同一 WRITE 分配器。

规范化的取消标记、序号/指针向量、删除/detach 集合与映射、属性/标签替换映射节点、patch 校验集合、合并映射节点和规范化 patch 指针索引按实际 PMR 分配请求计费。这些操作位于原生发布门之前。字符串、嵌套属性/标签向量、PropertyValue、公开 canonical batch 返回值及原生私有 COW/overlay/undo 负载仍未完整覆盖。

压力测试验证创建规范化工作区被拒绝后完整回滚，32 个暂存节点均不可见，完整性正常，后续 ID 与提交仍可用。32 个目标的 patch 测试留下 512 字节供单目标校验，但不足以复制保留槽位；拒绝后仍可提交前一条语句。槽位归属与释放测试保留关闭包装器计费。此前精确 ID 计费断言增加 sizeof(LogicalGraphNodeCreateRequest)，与当前构建新计入的 48 字节请求槽位一致，没有提高内存限额。

当前源码最终选定的 51 个套件、1,227 项测试全部通过。另有 170 项原生工作区测试包含完整的原生逻辑只读 spill 排序集成；这不是新的计时对照。早期逐分配点故障证据对应这些修改之前的源码，不将其声明为当前源码验证。没有启动性能测试或全量单元测试。没有新增固定交付验收：22/34（64.7%）。继续补齐嵌套负载、overlay/undo/私有 COW、维护与积压、分区 spill 以及最终验证。

# S3.4 property correctness and fault acceptance

The default-enabled ROW placement passed **245 selected tests from nine suites** on current source. The selection combines property/LargeValue/owner/cache/codec/content/range/retirement cases, native lifecycle, integrity corruption and native transaction publication/validation. The current S3.3 916-command native correctness report remains applicable: only tests/evidence changed since that checkpoint. No full suite or timing run.

The new actual native fault matrix writes a cost-admitted 256 KiB collection, pins the old graph, and injects four publication faults: ENOSPC before a public LargeValue data frame, a real 64-byte partial data-frame write followed by EIO, a real 64-byte partial graph Superblock write followed by EIO, and final sync failure after a complete graph Superblock write. All preserve the old pin's scalar and full body. Pre-publication/torn-root cases reopen to the complete old graph. Ambiguous final sync rejects later writes on that handle until reopen; recovery exposes only a complete old/new graph and retry succeeds. Native integrity passes after recovery.

A separate physically read-only backend reads scalar/body/non-null data through variable chunks, rejects replacement, emits zero write bytes and preserves complete file size. Existing modules reject bad owners/generations/tokens/offsets, malformed canonical values, checksum/data/Manifest/content mismatches, foreign/released snapshots and incorrect root routing. Range reuse, admitted owning output, large-to-inline, delete, pinned retirement, data relocation, multilevel streamed materialization and unknown-media retention keep their established contracts.

Accept S3.4 for the implemented ROW layout and property consumers. This is not MIXED/column-group corruption coverage or a claim of independent per-property LargeValue writes. Memory/resource coordination, spill, comparative O3/O5 and long-run maintenance remain their separate work items. The four injected histories model the actual test process/reopen boundaries; no hardware power-loss durability inference is made.

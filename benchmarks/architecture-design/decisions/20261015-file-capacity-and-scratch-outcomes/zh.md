# 文件容量与 scratch 结果语义

本记录仅为组件实现，没有新增验收，仍为 22/34（64.7%）。原生配置提供有限、打开期间不可变的 maximum_database_file_bytes，默认 1 TiB。原始/类型化/批量/控制记录/追加/预留均先检查完整范围，再修改缓存或执行 I/O，测试 hook 的逐页循环也先检查整批。既有嵌入式构造函数保留原有行为。可写打开在恢复修改前拒绝超出上限的既有文件，只读检查仍可进行。同一物理数据库的活动可写别名必须使用相同上限；旧上限值不会污染复用的注册表槽位。上限不持久化，所有可写所有者关闭后可以重新配置。

长快照用例反复修改 6,000 字节属性集合中的标量，直到候选写入被文件上限拒绝；旧快照和最后成功发布的数据均完整。释放快照、重开并显式执行有界 LargeValue 回收后，可以在同一上限内继续写入。最初不执行回收就重试会失败，因为逻辑所有权退休不等于自动回收全部不可达 LargeValue，归档保留该失败。该用例不承诺自动回收、所有维护任务的保留空间或通用稳态上限。

scratch 原先将所有配置容量拒绝视为 I/O 不确定，阻止已有句柄清理。StorageFileLimitExceeded 与真实操作系统错误区分；只有 namespace 预留不可能发布片段所有权，或物理分配前后持久 Catalog 根一致时，NativeBulkRunStore 才报告 NativeBulkRunCapacityDenied。其余异常保留重开恢复要求。会话仅对明确未发布的拒绝归还待用磁盘额度，旧句柄保留，并允许图快照仍在时复用额度。

片段回执在发布前预分配；物理/extent 分配通过移动预留向量返回，避免元数据发布后复制。仅恢复旧复制表达式的对照程序在同一 scratch 用例分配 1,699 次，修复后为 1,698 次。让被移除的最后一次分配失败时，对照路径要求恢复，修复路径不会触发该分配并返回完整句柄。这是可用性及分配次数证据，不是延迟测量，也不表示所有发布路径均无分配。

66 个套件、1,625 项定向测试通过。scratch 写入全部 1,698 个实际到达的堆分配失败点通过，覆盖成功句柄完整、无需围栏时保留旧句柄、需要时保守恢复、用户数据/图围栏不变、单 segment 额度复用及重开/完整性检查。另有 4 个终态用例、32 次真实 scratch 崩溃恢复通过，每轮恢复文件均为 1,572,864 字节，只读孤儿检查前后 SHA-256 相同。当前 worker 以 SHA-256 冻结；前一检查点的 4,346 点更广矩阵仍归属前一源码，没有冒充当前源码证据。没有运行全量单元测试或性能基准。

StorageIO 的 pin 计数测试同步了前次复制读取并发修复：复制页面不再发布外部 pin，两次显式 pin 同一页只算一个不同物理页，随后复制另一页不增加计数。没有为通过断言而降低计数实现或资源上限。

嵌套 mutation/Property/undo/overlay/COW/编译/schema 负载所有权、所有维护资源及进展/积压、分区算子及最终完整工作负载验收仍待完成。本组件检查不验收 S5.3/S5.4/S5.5 或 S6.1/S6.3。

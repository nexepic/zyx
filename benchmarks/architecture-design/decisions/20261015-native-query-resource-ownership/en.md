# Native query resource ownership checkpoint

Date: 2026-10-15. This advances implementation within S5.3/S5.4. It does not accept either milestone or any of the current five priorities (S5.3, S5.4, S5.5, S6.1, S6.3). Accepted progress remains 22/34 (64.7%).

## Implemented ownership chain

The coordinator now lives in the public include tree, with an execution-private compatibility include. ProcessResourceDomains owns the shared 512 MiB process budget, its protected 16 MiB maintenance floor, and at most 64 weak database slots. Each native opened-file identity plus durable DatabaseId selects one 256 MiB database domain; physical hard-link aliases reuse it, while distinct files do not share database quotas. Database category limits retain the A6 defaults (query/cache/write/maintenance/code = 192/64/128/32/0 MiB). Only query consumers are connected in this checkpoint; these category limits alone do not account for the remaining categories.

Native QueryEngine creates one bounded query account, retaining the existing materialization ceiling (64 MiB by default) and any smaller resident-memory policy. All connected read execution-local budgets share this account. Caller-supplied accounts must belong to the native domain and cannot raise its query policy. Transaction-overlay execution uses the engine's native domain too. Metadata publication and resource registry/admission are not nested.

MaterializedByteBudget admits both PMR requests and manual reservations against local and shared parents before publishing new counters. Admission rejection preserves all counters; upstream allocation failure refunds both levels. Independent task budgets cannot multiply query/process allowance. Advisory shared headroom reuses the same locked calculation as actual admission, including maintenance floors. Reservations can detach a nonembedded payload to an owning global lease without a refund/readmit gap; embedded parents must be reclassified first.

Read output columns and resident batch slots are charged separately. Successful output detaches its final reservation to QueryResult, while partial output is destroyed before failure refunds. Results retain their account/database/process after execution, backend close, and reopen. QueryResult deep copies admit a second charge before copying payload; moves transfer ownership; assignment destroys prior containers before their charge. Subsequent row/column/notification growth is admitted including vector growth overlap and nested/entity heap estimates. Counters describe supplied ownership/capacity estimates, not complete RSS or a new guarantee about every allocator's private metadata.

## Verification and remaining gates

25 foundation tests, then 116 read/output tests, then 146 tests across 15 selected suites passed; only affected modules were compiled/linked, never the full suite. The final selection includes real native backend queries, physical read-only zero-write behavior, hard-link domain identity, close/reopen and retained outputs, foreign-account rejection, transaction rollback, query scratch and isolation regressions. Source/evidence identities are in proof.json. A pre-existing nodiscard warning in an exception assertion was corrected with an explicit void cast; its expected exception is unchanged.

Cache/plan/codebook allocation, mutation/write-private/undo buffers, maintenance/recovery workspaces, the generic BoundedBatch capacity audit, and bounded retirement backlog are not comprehensively connected. Query parsing/compilation and some procedure/mutation budgets and their returned outputs remain outside this ownership path. Partitioned hash joins/aggregation and the complete resource-pressure/fault/steady-state matrix remain required. Do not advertise total process-memory governance or accept S5.3/S5.4 from this checkpoint. S6.1 is not accepted from a subset of final-source regressions. No final performance benchmark was run; the before campaign is a separate record and currently shows substantial Kuzu gaps.

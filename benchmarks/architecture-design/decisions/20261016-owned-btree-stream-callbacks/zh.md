# BTree 有序流回调的分配所有权

此前原生有序流使用 std::function，非平凡闭包的存储与复制绕过已安装的预算。现在 OrderedBTreeEntrySource 和 OrderedBTreeEntryCursor 使用 OwnedFunction：小型平凡闭包内联，其他闭包在构造前申请对象和共享控制块额度；复制克隆可变状态，移动不分配。失败复制保持原对象和目标不变。分配所有者随闭包保留，离开创建作用域后复制仍可计费，调用方显式资源作用域可选择副本归属。

这只治理闭包本体和控制块；被捕获的载荷及指针目标必须自行持有额度。外部 std::function 的不透明捕获不会被通用包装器自动治理。函数调用继续遵循调用处的资源作用域，原生 BTree 工厂/游标已显式选择其原有所有者；不改变该调用语义。

新增 8 项通用测试及 2 项原生测试，验证空/内联、独立状态、引用/void、拒绝、部分复制回滚、所有者重绑定和逃逸游标生命周期。原生测试明确要求复制增加实际计费，低额度在任何根 I/O 前拒绝，最后一个游标销毁后原账户可释放。

1,762 项受影响测试通过；随后增加的两项原生测试连同相关用例共 24 项通过，独立用例并集为 1,764。当前 worker 的 1,275 个隔离案例和 32 轮崩溃/只读/恢复通过，长分配路径抽样最多 96 点。资源模块的独立复验另记于 proof.json。

没有全量测试、新性能测试或新增整项验收。实现复杂度用于实际预算能力，不宣称端到端提速。未完成的其他资源工作区继续归属于 S5.3，S5.4 的已有故障合同保持独立。证据与源码 hash 见 proof.json；所有运行证据仅为 Linux Clang19/libstdc++14，不冒充 Windows/macOS 实测。

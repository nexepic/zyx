# A1 节点列过滤的生产接入

日期：2026-10-12。状态：类型化过滤已接入现有原生节点引用扫描，267 项相关模块测试通过；这是 S1.1/S2.1 的部分实现，不代表完整物理执行器或存储布局迁移。总体验收保持 1/34（2.9%）。

## 调用链与替换边界

LogicalPlanReadRuntime 的 tryVisitBatchedNativeNodeRefScan 原本批量读取属性列，再为每个候选节点构造字符串键行与属性缓存，最后求值扫描谓词。现在先根据实际读取字段顺序绑定谓词列序号，在完整校验列矩阵后进行过滤；仅幸存节点进入既有行表示和下游投影、聚合。原扫描顺序与重复行合同保持，排序读取顺序不成为输出顺序。

BoundNodeColumnPredicates 编译普通相等、查询参数相等、范围及复合相等谓词。描述符借用当前逻辑计划和本次参数值，不跨查询缓存，不假装具备数据库/schema token。字段名仅在初始化时解析；分组谓词按数值列序号执行。

PrimitiveColumnFilter 支持同类型整数、浮点和布尔列，将已有 PropertyValue 载荷转换为有界 FixedWidthColumn，再使用类型化比较内核。存储端仍返回动态值列，转换扫描和临时数组仍有成本；尚未实现直接类型化生产、可变长列、通用物理批次、连接/排序迁移或完整类型化聚合。混合类型、字符串和其他动态值保留原 PropertyValue 比较。索引候选残余过滤路径尚未迁移。

## 语义、所有权与资源

- 保持整数完整精度，不经 double 转换。保持现有跨类型 variant 排序；浮点 <= 与 >= 使用原有的否定小于规则，包含 NaN、无穷和正负零。
- 当前存储列将属性缺失与显式 NULL 都映射为 monostate；扫描过滤均拒绝二者，但不能声称生产者已经保留独立 presence 状态。无上下界的范围也必须拒绝 NULL。
- 选择向量只剔除行，不重新选中先前被拒绝的行。完整列宽/行数检查先于过滤，不能让全拒绝结果掩盖源数据损坏。
- 谓词 PMR 容量、类型化值/状态数组和常量数组共享查询预算。列的 reserve 支持精确行数准入；部分分配失败保留的容量仍被计费，析构返还。
- MaterializedByteLimitExceeded 仍继承 runtime_error，保持既有错误捕获兼容。只有类型化缓冲的预算不足可以在尚未修改选择向量时退回标量路径；bad_alloc、取消和源数据错误传播。guard 放在预算回退捕获之外，避免吞掉取消或消费者错误。
- 原生节点扫描的谓词元数据或选择位图无法准入时保留旧行过滤。原读取与批次拆分的预算协议继续存在；不声称与旧实现具有完全相同的最低可运行字节阈值。
- 拒绝节点的属性载荷在幸存行向下游交付前释放并更新计费。最终 QueryResult 继续生成拥有化结果；内部借用不得逃逸源批次。公开 ABI、持久格式、快照认证和恢复协议没有新增变化。

## 后续预算生命周期修复

同日后续回归发现：查询级可选谓词元数据在下游生成拥有化结果时仍占预算，等价范围条件较多时，会让原本可运行的扫描失败。测试使用一个 1 KiB 字符串属性，比较一条与 32 条等价闭区间条件，在 2–8 KiB 的多个预算下核验输出，不使用运行时间判断性能。最初试写的重复相等键被既有合同正确拒绝，已改为合法的范围条件；正式修复前证据对应合法条件，并确实复现共享字节预算错误。

修复将可选描述符的申请移到源列和结构行已准入之后，生命周期限制在当前批次过滤期间。申请不成功时使用原标量过滤；过滤结束即释放描述符容量，再交付幸存行。这样不会由可选元数据提前缩小原引用批次容量，也不会在下游拥有化输出时继续占住该容量。源列、选择位图和实际结果仍准确计费，不吞掉真实超限、取消、分配失败或数据损坏。

该适配器现在每批绑定一次，而非整次扫描绑定一次；这是当前查询预算与旧行输出共存时的明确取舍。未来不可变物理计划应拥有已绑定且独立计费的描述符，删除这一临时绑定接口。每批绑定可能增加 CPU 成本，必须在最终性能窗口验证，不能据正确性回归声称提速。

新增 RedundantPredicatesDoNotConsumeTheLastAdmissibleRowBudget 验证所有最小条件查询可运行的测试预算下，冗余等价条件产生同样拥有化结果。对照查询若失败，只接受字节预算错误，其他错误不得被当成不适用预算跳过。11 项节点列谓词测试及 268 项相关模块回归全部通过；仍只验证本机 macOS，未运行全量测试或 benchmark。

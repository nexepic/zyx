# Allocation-free pre-decode shape inspection

Foundation component; accepted progress remains 22/34 (64.7%).

CanonicalPropertyValueCodec now offers full borrowed-input inspection with checkpoints, structural counts and atomic cursor advancement. It validates the same kinds, flags, lengths, scalar constraints, nested bounds, canonical unsigned-byte map-key ordering and complete payload consumption as the decoder. Counts describe the wire shape, not actual decoded heap capacity or RSS. decodeNextWithAdmission invokes the caller's required admission callback after full validation and before constructing decoded payloads; caller-owned admission must cover the returned value's lifetime. This opt-in entry point is not yet a comprehensive native heap-budget integration.

The ordinary decoder now moves freshly decoded strings into PropertyValue and borrows the previous canonical map key directly from input instead of allocating/copying it. Input bytes remain borrowed only during synchronous decoding; decoded results still own their data. The wire format and normal decoding trace accounting are unchanged.

All 113 selected tests across five suites pass. Every single-bit mutation of a nested wire value must give matching inspection/decoder success, consumed cursor or FormatError. All existing scalar/container kinds also compare inspected and decoded boundaries. Tests cover cancellation, quota rejection and unchanged cursors. An isolated worker inspects 1,025 values containing 524,288 string bytes with every C++ heap allocation denied; cancellation and an admission rejection also complete under that restriction before any payload is decoded. The worker passes 113 cases in total: nine exhaustive stage faults, 96 sampled commit faults, four terminal checks and four structural/heap probes. Earlier overlay/scratch/crash evidence remains separately tied to its frozen source.

Source and normalized payload ownership, decoded-capacity modeling, remaining publication/compiler workspaces and whole-stage acceptance remain pending. No full suite or new performance campaign ran; no Kuzu win, platform execution beyond Linux, or universal OOM guarantee is claimed.

Heap-bound followup: inspection also computes a separate admitted-decoder allocator-request upper bound, including vector slots, fresh strings, reserved hash buckets and moving-container headers. Only decodeNextWithAdmission pre-reserves maps; ordinary decoding retains its old growth policy. Double ULP padding covers float rounding both below element count and above the reserve request. Pinned libc++/libstdc++/MSVC source audits and the reachable uint32 map domain support the model; this is not an arbitrary row multiplier. All 113 module tests pass. Nine isolated cases pass, including 11 observed admitted-decoder shapes with zero uncovered private requests and a 590,848-byte maximum observed retained allocation. A zero-width multiplication guard found by the first focused test was corrected. Source, audit headers/licenses and raw evidence are in heap-upper-proof.json / heap-upper-evidence.tar.gz. The new bound still needs native source-lifetime/metadata integration and does not claim exact retained capacity or Windows/macOS execution.

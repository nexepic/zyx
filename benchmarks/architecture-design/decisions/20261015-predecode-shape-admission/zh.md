# 解码前的无分配结构检查

基础组件；验收进度仍为 22/34（64.7%）。

CanonicalPropertyValueCodec 新增完整借用输入检查、取消检查点、结构计数及成功后一次性推进游标。它与解码器检查相同的类型、flags、长度、标量约束、嵌套深度、按无符号字节排序的规范 map 键及完整 payload 消耗。计数描述编码形状，不是解码后实际堆容量或 RSS。decodeNextWithAdmission 在完整验证后、构造解码负载前调用必需的准入回调；调用方负责让准入所有权覆盖返回值生命周期。此可选入口尚非完整原生堆预算接入。

普通解码器把刚解码的字符串移动到 PropertyValue，并直接从输入借用上一个规范 map 键，避免相应的分配/复制。字节只在同步解码期间借用，结果仍拥有数据；编码格式与普通解码 trace 计数保持原合同。

五个测试组共 113 项定向测试通过。嵌套编码的每个单比特变异都要求检查器与解码器的成功/失败、消耗游标或 FormatError 一致；所有既有标量/容器类型也比较检查和解码边界。测试覆盖取消、准入拒绝及游标不变。独立 worker 在禁止全部 C++ 堆分配时检查 1,025 个值、524,288 个字符串字节，并在相同限制下完成取消及解码前准入拒绝。worker 共通过 113 个案例：九个穷举暂存分配点、96 个抽样提交分配点、四个终态检查及四个结构/堆探针。此前 overlay/scratch/崩溃证据仍单独对应各自冻结源码。

源与规范化负载所有权、解码容量模型、其他发布/编译工作区及整阶段验收仍待完成。未跑全量测试或追加性能基准，不宣称超越 Kuzu、Linux 以外平台执行或普遍 OOM 保证。

解码上界后续：检查另行计算准入解码器的分配请求上界，含向量槽位、新字符串、预留哈希桶及移动容器临时头。仅 decodeNextWithAdmission 预留 map；普通解码保持原增长策略。两次 ULP padding 分别覆盖低于元素数及高于 reserve 请求的浮点取整。固定 libc++/libstdc++/MSVC 源码及可达 uint32 map 域支持该模型，不采用任意行数倍数。113 项模块测试通过；九个独立案例通过，其中 11 种准入解码形状的未覆盖请求字节为零，最大观测保留分配为 590,848 字节。首轮定向测试发现并修复了零宽度乘法检查。源码、上游审计头/许可及原始证据见 heap-upper-proof.json / heap-upper-evidence.tar.gz。此上界仍待接入原生源生命周期及元数据，不宣称精确保留容量或 Windows/macOS 执行。

# 事务终态资源清理

本组件检查点不新增验收项，仍为 22/34（64.7%）。

原普通逻辑事务提交后，累计变更载荷及已发放 ID 数组会一直保留到已关闭事务对象销毁；回滚/冲突路径也保留部分数组容量。普通事务的所有终态现都会在放弃/消费对应能力后立即释放累计请求、补丁容量、已发放 ID 及租约范围容量。

原 noexcept 放弃能力函数会分配临时转换向量，内存分配失败可在回滚中终止进程。暂存现直接保留原生租约范围表示，经既有元数据 API 无分配放弃；仅在规范化发布计划时转为公共逻辑身份表示。精确能力、取消 ID 空洞及持久高水位规则保持一致，不重复保留第二份范围账本。

显式选中的 zyx_transaction_resource_fault_worker 仅在独立进程替换 new/delete。四个场景覆盖：拒绝所有新堆分配后的回滚、40 次独立暂存租约的同类故障、8,192 个暂存 ID 的终态保留检查，以及提交后释放缓冲区仍能读取 1 MiB Property。四项全部通过，本构建关闭后仅剩 1,408 字节事务对象，并验证完整性及重开。这是请求分配计数，不是 RSS 或性能结果；生产及性能程序的分配器不变。

负对照仅将刚修复前的后端实现替换进当前静态库的副本：两个 OOM 回滚均因 bad_alloc 中止，旧提交路径未通过载荷保留检查，三项均复现目标缺陷。当前独立故障场景及全部 155 个受影响后端测试通过，未运行全量单测或性能测试。显式构建 EXCLUDE_FROM_ALL 故障目标后，可运行 scripts/test_transaction_resource_faults.py --worker buildDir/zyx_transaction_resource_fault_worker。前一检查点的 681 个读取/批处理测试属于本次后端专有修改之前的证据，不冒充最终全部源码验收。

本次修复保留与 OOM 清理缺陷，尚未实现生产写入/undo/overlay 或维护内存归属。计划缓存 IR、临时工作区、有界持久积压及分区算子仍阻止 S5.3/S5.4 及后续验收。未新增固定项进度，未提交/推送。

# S4 native ROW lifecycle and bounded-work validation

The selected scan format shares the property-pool numeric owner namespace with ROW records. Cold writes formerly decoded the descriptor for every new owner and built free-space indexes over unrelated native pools. This change reuses one negative source-group fact within a commit and prioritizes compatible ROW capacity. Hints never authorize a write: positive native groups authenticate each owner, an I/O epoch change invalidates hints, and the original complete search remains the fallback. BUILDING retains its original global best-fit placement.

The first real create/delete check exposed a pre-existing native COW capacity gap. `EntityPageStore` tried generic Property-pool reconciliation before its metadata writer could choose an already implemented fresh-pool destination. Native snapshots now use that writer fallback; generic failure cleanup also preserves the original native publication error. No generic allocator authority is extended to native field pages.

Five added regression tests cover a persisted 1000-edge batch, compatible-pool selection and invalid candidate IDs, mixed native Node/ROW Edge writes with an observer-induced I/O epoch change, pool-hint invalidation, and 40 consecutive property updates preserving an old pin while the source pool exhausts. The original S3 archive fails the continuous-update regression; the corrected implementation passes. Existing module checks cover publication failure, recovery, cancellation, memory limits, read semantics, and compatibility. No full unit suite is built or run.

`untimed-work-comparison.json` records medium's 1019 to 35 descriptor decodes, 14815 to 375 indexed pool frames, and 120115200 to 2613248 buffer-pool physical-read bytes for 1000 edges. These are work counts, not latency or cold-disk measurements. Complete public oracles on both real images and the preregistered 16384-owner/512-batch generality fixture are recorded separately.

Reproduction: source `/workspace/zyx-cloud-env.sh`; build only `zyx_core` in the three registered profiles. `verify.py PROFILE` compiles affected modules only. `relink-tests.py` recompiles the changed test TU and relinks the registered module objects. `build-final-probes.py` reuses unchanged harness objects and links separate production executables; historical measured executables are never overwritten. `check-public-final.py` runs zero warmups and one untimed complete-oracle check. Generative inputs, original failed benchmark records, and their frozen identities remain intact.

Final measured write corrections and the repaired registered Skew fixture belong to the separate `20261026-s4-correction-window` protocol. Earlier read measurements identify their original binaries and source. The only engine changes in this correction affect write placement/publication; they do not constitute new read timing measurements. Kuzu superiority is not claimed.

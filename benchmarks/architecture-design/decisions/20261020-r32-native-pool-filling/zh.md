### 2026-10-20 R3.2／R4.3：实际原生池填充与中断后的跨对象恢复

证据：`benchmarks/architecture-design/decisions/20261020-r32-native-pool-filling/`。显式正向转换、共享目录／内容索引的变化路径、字段 SET／REMOVE 和受控 Node／Edge／LabelSet 删除现可复用已认证池的空闲／无 pin 旧帧。放置先在私有影子容量中完成，之后才物理清理／追加并共同发布。每池至多31帧；固定12项 kind／owner 提示、直接源／根和两个邻组只提供候选，逐次核对 Catalog、allocator、全部位置及精确当前／旧 pin 路由，普通小写不扫描全库。

同批的后续私有追加不会再次被物理清理；接收新帧的池在源池整体退役证明前选定并排除。暂存树根的 epoch1 在放置后绑定实际池 epoch，同时更新 Index Root／描述符。只有真正新建的池才增加 allocator／Catalog 和新池空间计数，复用池不冒充新增128KiB分配。逆转换 ROW 载体和显式搬迁继续沿用原有新池放置。

写锁释放时记录未成功确认且发生 I/O 的原生写入；下次原生写入及首次可写重开，在任何新发布前流式恢复可见池的未发布帧。先核对当前与 pin 可见 bitmap，再清理，保留旧物理版本；通用未适配 writer 仍拒绝。成功发布在统一入口刷新 I/O 基线，no-op 不触发恢复写。此全库流式遍历只用于中断／重开恢复，不用于正常放置发现。

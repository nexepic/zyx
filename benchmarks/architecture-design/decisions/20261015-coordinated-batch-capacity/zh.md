# 协调批容量检查点

仍为 22/34（64.7%），本组件推进不新增验收项。

原生协调路径的拓扑/节点引用、Join/OptionalMatch、NamedPath 与内存 Sort 批向量现通过共享执行预算分配。活跃对象归为已计费向量容量中的嵌入对象；未用槽位及增长重叠继续计费。未协调的公共嵌入接口保留原有逻辑字节契约，与已确立的协调/传统输出计费边界一致；原生 QueryEngine 必定绑定文件域账户，不能借此绕过容量计费。

BoundedBatch 移动构造保留嵌入对象分类。带费移出在修改批次前申请独立值计费，拒绝时保留原批次，值移动抛错时恢复计费。共享预算下从一个预留槽位开始按实际输入增长，避免闲置容量挤占可用行，不提高预算。

输出行槽位改用 PMR，在底层分配前申请实际分配额度。存在共享账户时按更小可用额度选择批次，尽可能为执行/结果保留 15/16 空间；局部执行预算仍扣除驻留输出槽位，父级仅计一次。局部上限为 64 MiB 时，128 KiB 调用者账户可执行本次小规模原生 Sort/Join/OptionalMatch；原有 512 行预分配会提前拒绝。1 KiB 账户失败后退还全部查询计费，随后正常额度重试成功。

扩大回归发现流式 COUNT 测试替身遗漏能力：仅支持引用扫描，不代表支持避免载荷读取的可选非空探测。该用例现显式启用真正借用数据的非空探测，覆盖显式 NULL/缺失字段并断言零完整 Node 物化；原 2 KiB 预算及结果均保留。原生生产路径已有该能力。

检查点最终源码通过 28 个套件中的 678 个定向测试，覆盖图读取、拓扑批处理、列聚合、模式/变长/Union、排序与 scratch 故障、缓存归属及原生事务隔离。未运行全量单测或性能测试。独立 Property 预取行向量容量、计划/写入/维护及临时解码工作区、有界持久积压和分区 hash/aggregate 仍需完成。详见 proof.json 与 module-evidence.tar.gz。

# A1 数值聚合的整数溢出边界

日期：2026-10-12。状态：SUM 的 int64 累加消除了有符号整数溢出的未定义行为，409 项相关模块测试通过。属于执行语义边界完善，不增加完整阶段验收项。

## 问题与确定行为

LogicalAggregateAccumulator.hpp 的 SumAccumulator 原本直接执行 sumInt_ += input，正负溢出触发 C++ 未定义行为。旧行消费者与刚接入的节点列消费者都使用该累加器，因此必须统一处理，不能只修复列路径，也不能用可能已经溢出的运算结果判断是否越界。

现在在加法前分别检查正输入与负输入的安全边界，再执行原加法。检查仅使用标准 int64_t、numeric_limits 和比较，不依赖编译器内建、128 位整数或平台 API。越界抛出 std::overflow_error，英文错误消息为 sum() integer accumulation overflowed；不会改变原整数部分、浮点部分或类型标记。调用方可以检查先前状态、clone、reset 或继续安全追加。

混合数字仍保留原本独立整数部分与浮点部分，最终按既有方式合并。即使已经看到浮点数，整数部分溢出仍显式失败，不静默转为 double、饱和值或整数回绕。相反符号的整数极值可以精确相加。浮点 NaN/无穷行为和 AVG 算法本轮不修改。

该检查约束累加过程，而非只检查最终数学总和；若某个中间整数和超界，即使后续值可能抵消也会报错。这使行为确定，但不等于任意精度 SUM。最终正式文档更新时应说明该数值边界；当前按用户要求不修改正式数据库文档。

## 验证

新增 4 项累加器测试：正溢出与继续追加、负溢出与 reset、两个整数极值的相反顺序精确相加、已有浮点输入时的整数溢出及 clone 状态保持。新增 1 项生产运行时回归：原生列消费者和标量消费者都拒绝整数溢出，修正输入后重用同一逻辑计划返回正确结果，失败不会发布部分聚合。

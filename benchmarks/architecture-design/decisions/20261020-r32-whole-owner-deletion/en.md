# R3.2: private whole-owner deletion lifecycle

Only R3.2 within the fixed five advances. Acceptance remains 13/24 (54.2%), without commit/push, a full unit suite or new performance timing.

`HybridPropertyDemotionPreparation::prepareOwnerDeletion` completely enumerates fields of at most 64 live owners of one group under the exact source pin and MetadataWriteBatch. Duplicate, dead, cross-group or absent sources fail. The current field-enumeration work is bounded by 4096. Changes to one column merge across owners before evaluating the final 48-member threshold, then reuse the shared COW coordinator. Ordinary partial-column preparation still rejects clear_live; only this complete owner enumeration enters the internal deletion route.

Merged group membership/column counts also subtract removed existing extensions, and deleted live bits clear once. Qualified columns remain, underqualified columns demote, and removed extension slots plus owner/extension directory keys are erased. Removing the last owner erases the group slot/key instead of encoding an invalid zero-live group. Extension-only owners use the same authenticated source-page image. Generated extensions share pages across fields and existing private source-page copies are reused. Outputs remain private images and final directory mutations.

Current group.live is authoritative. An uninvolved column can retain its older live snapshot when its presence excludes deleted owners, so it remains byte-identical. Deleting one extension referencing a shared LargeValue does not retire that value; the other owner's original reference and manifest remain usable. Global ROW/native reference reconciliation and safe retirement still belong to the future publisher.

The previous checkpoint's whole-group membership<=4096 restriction is removed. R3.1 defines a conversion-plan ceiling, not a lifetime layout capacity. This factory bounds the fields enumerated in this operation; ordinary mixed preparation handles at most 64 columns and internal deletion at most 85 merged columns. Wider deletion/large publication still requires later streaming coordination; arbitrary-width transactions are not claimed.

The relevant module passes 4/4 default and 56/56 experimental cases: 49-to-48 retained columns, 48-to-47 demotion, multiple fields/NULL, last-group deletion, extension-only/shared LargeValue, unchanged uninvolved columns, early/middle/late cancellation, quota refunds, invalid owners and independent retry. Source file size/epoch, actual source entities/properties and durable roots remain unchanged. The test file stays below 2000 lines. The previous checkpoint's new test borrowed a temporary readRecord buffer; it now retains the bytes through extension decoding. Extension and manifest admissions have separate retained credits. The initial fixture mixed-auto declaration compilation failure is retained and corrected. Raw logs, JSON and binary/source hashes are included. Linux x86_64 only.

Remaining: existing-extension set/remove and coordination with cross-group/other final changes; actual Entity Map deletion in the same transaction as field/directory changes; physical COW registration, atomic Page Directory/Catalog/allocator/descriptor/retirement publication; complete recovery, GC/relocation/reuse and same-executor ROW costs. Nonempty-format and ordinary-write production guards remain. R3.2/R3.3 are unaccepted; all three R5 contracts continue unchanged.

# S2 私有整库克隆与完整主节点成员构建

验收进度保持 **15%**，S2 尚未验收。本检查点只运行模块测试，没有新增性能对比、提交或推送。

`ScanBuildingImageBuilder::cloneWithPrimaryMembership` 通过原生只读句柄打开离线源，并排他创建目标。源与目标合计至多 2 GiB，目标上限由 StorageIO 在每次写入时强制执行；不创建临时磁盘镜像。统一源账户至多 1 MiB，构建器、元数据、IO 固定状态及各源前沿均在相关 IO 前计费。

构建器现已把既有 5/31→15/41 克隆与真实主节点/完整 LabelSet 成员安装连接起来。每次发现一个逻辑分组，释放发现快照，再调用既有元数据协调器，由协调器独立读取该组全部主节点 ID 和完整标签，避免整个构建过程保留每个中间目录版本。包含无属性、无标签节点，并避免终端 uint64 分组溢出。计数与根仅作诊断，结果始终保留 BUILDING，不赋予公共打开或最终发布能力。

真实文件集成暴露了先前通用段校验原型的生产问题：原生共享页池和元数据页池不维护不可变的 envelope 全载荷 CRC，而使用独立校验的 A/B 控制记录及类型化页面。克隆器现在使用既有 codec 解码控制记录，按原生读取器规则选择最高有效序列，并核对 envelope、段、代际、LSN 身份，以及元数据池物理槽。允许一个撕裂的非活跃记录；两份均损坏或所选身份不符时，在修改输入前拒绝。不可变 extent 仍检查完整声明载荷 CRC。页面载荷仍必须由完整目标校验验证，任何这里的 API 都不会清除 BUILDING。不可变载荷损坏夹具也改用正确的 CODEBOOK_EXTENT，不再把非原生布局伪装成共享页池。

另一个首轮集成失败来自测试夹具：从现代头构造旧格式时，遗漏了紧急保留记录从 352 到 336 的移动。夹具现已正确移动，并在调用构建器前验证两个源头；首轮失败 JSON/日志保留。随后真实页池 CRC 拒绝曾在实现过程中观察到，但原始失败日志已被覆盖，此处不将它称为保留的原始证据。

物理顺序复核发现的是头文件注释过时，而非运行时排序缺陷：EntityPageStore 实际按类型化 Entity Map 的逻辑 ID 遍历。没有修改扫描实现；新增真实页面顺序回归在两个配置下均通过，注释也已反映实际契约。

验证通过：隔离格式 33 例、默认格式 12 例，是存在重叠的配置用例数。真实旧格式 wire 夹具含实际持久主节点页；源字节完全不变、源写入次数为零，成员完整镜像通过整图完整性校验，既有目标不被覆盖，严格文件总上限只留下 BUILDING 头，首组发布后取消不会暴露完整库，默认配置构建器在 IO 或创建文件前拒绝。当前改动是内联构建器/codec 及 EntityPageStore 纯注释更正，模块对象已针对此前重建的核心重新编译，精确身份见 receipt.json。没有运行全量单元测试。

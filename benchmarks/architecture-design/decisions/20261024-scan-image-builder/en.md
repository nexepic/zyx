# S2 private image clone and complete primary-membership construction

Acceptance remains **15%**, with S2 unaccepted. This checkpoint runs module tests only; no new performance comparison, commit or push.

`ScanBuildingImageBuilder::cloneWithPrimaryMembership` now opens an offline source with a read-only native handle and creates its destination exclusively. Source plus destination are limited to at most 2 GiB, with the destination bound enforced on every StorageIO write. It creates no temporary disk image. A single source account is limited to 1 MiB; fixed builder/metadata/IO state and each source frontier are admitted before their IO.

The builder connects the existing 5/31-to-15/41 clone with actual primary Node/complete LabelSet membership installation. It discovers one logical group, releases the discovery pin, then invokes the existing metadata coordinator, which independently reads all primary IDs and complete labels. This avoids pinning every intermediate directory version for the entire build. Propertyless/unlabeled Nodes are included. Terminal uint64 groups are handled without overflow. Diagnostic counts and the root remain BUILDING and confer no public-open or final-publication authority.

Real-file integration exposed a production bug in the earlier generic segment-authentication prototype: native shared and metadata page pools do not maintain an immutable envelope payload checksum. They use independently checksummed A/B control records and typed frames. The clone now decodes control records with the existing codecs, selects the highest valid sequence like the native reader, and checks envelope/segment/generation/LSN identity (plus the metadata pool slot). A torn inactive peer is tolerated; two bad records or a mismatched selected identity are refused before changing the input. Immutable extents still require their complete declared payload CRC. Frame payload validation remains the responsibility of full target integrity; no API here clears BUILDING. The immutable-payload corruption fixture now correctly uses CODEBOOK_EXTENT rather than pretending to be a native page pool with non-native framing.

A separate first integration failure was a test-fixture error: constructing a legacy header from a modern fixture omitted the emergency-reserve relocation from offset 352 to 336. The fixture now moves that record and validates both source headers before invoking the builder. The first failed JSON/log are preserved. The later real-pool CRC rejection was observed during implementation but its raw failed log was overwritten; it is not presented as a preserved artifact.

The physical-order audit also found a stale header comment, not a runtime ordering bug: EntityPageStore actually traverses its typed Entity Map by logical ID. The implementation was left unchanged; a new real-page ordering regression passes on both profiles, and the comment now describes the actual contract.

Validation passed: isolated 33 cases and default 12 cases, with overlapping tests counted per configuration. The real legacy-wire fixture contains actual persistent primary pages; source bytes remain identical, source write calls are zero, the completed membership image passes full graph integrity, existing destinations are preserved, a tight total-file cap leaves only BUILDING headers, cancellation after one group exposes no complete image, and default-profile builders refuse before IO or file creation. Current changes are inline builder/codec code and a comment-only EntityPageStore header correction; module objects are freshly compiled against the previously rebuilt cores, with exact identities in receipt.json. No full unit suite was run.

Still required: typed field construction for Nodes/Edges, physical reclamation/compaction and >=10% steady whole-file savings, final complete integrity and publication, persistent scan consumers, mutation maintenance, compatibility and the final A/B/Kuzu performance window. The constructor intentionally leaves every result BUILDING until those gates exist and pass.

# Bounded allocation grants and cache container checkpoint

2026-10-15. Implementation dependencies for S5.3/S5.4; no new fixed delivery is accepted. Overall remains 22/34 (64.7%).

PrepaidMemoryResource admits one explicit finite grant through the existing shared resource account before entering publication/cache operations. All granted bytes, including unused capacity, remain charged. Actual PMR allocation requests consume its capacity with atomic admission, without taking the process resource mutex. Growth overlap is admitted before upstream allocation; upstream failure refunds local admitted usage while keeping the parent grant. The allocator owner retains the account hierarchy. Destroying the allocator with live allocations fails closed. Admitted peak, live usage, capacity and denial observations are distinct from RSS.

BufferPool now routes entry/control-block storage, hash buckets/nodes, and both recency queues through an optional owned PMR resource. Entry and queue publication roll back together on allocation failure, before resident/pin/dirty counters advance. Promotion splices the same queue node without allocating, replacing the former erase/allocate sequence that could leave a broken recency route on failure. Existing generation, private-page, pin, flush and eviction semantics are retained.

PlanCache likewise supports an owned PMR resource for query-text copies, list nodes, index nodes and buckets. Heterogeneous string-view lookup avoids allocating a temporary query key. Cloning completes before old entries are evicted or replaced; a failed index insertion rolls back its list entry. Zero capacity now disables caching without cloning or reading an empty list. This does not account for the heap buffers inside cloned logical operators/expressions, and it is not full plan-memory governance.

Verification: the affected selection passed 190 tests/18 suites, followed by 46 cache/grant tests/three suites after adding owner-lifetime cases: 192 distinct tests, zero failures. Tests inject each first-admission allocation failure and verify empty-state/retry integrity, actual metadata capacity, shared quota, upstream failure, two concurrent consumers, allocator keepalive, zero capacity and clone failure. Only affected objects and the core library were built; no full suite or performance benchmark was run. Two subsequent explicit standard-library include additions passed a standalone warnings-as-errors header compilation. Evidence/identities are in proof.json and the compressed module archive.

These allocator constructors are opt-in. Native StorageIO and QueryEngine still instantiate their caches with the ordinary default resource. Do not claim global cache governance or accept S5.3/S5.4. Choose and integrate a bounded grant policy shared across file aliases, complete codebook payload and plan-node/compile allocation accounting, preserve output/pin ownership, and avoid reserving independent full cache grants per handle. Admission, fallback/eviction and release behavior must be tested at the actual native entry points. Write/maintenance attribution, backlog, partitioned operators and final resource/fault/performance gates also remain open.

# 有界分配额度与缓存容器推进记录

2026-10-15。推进 S5.3/S5.4 的依赖实现，未新增固定交付项验收；总进度仍为 22/34（64.7%）。

PrepaidMemoryResource 在进入发布/缓存操作之前，通过已有共享资源账户申请一个显式有限额度。全部额度（含尚未使用部分）持续计费；实际 PMR 请求使用原子准入消耗块内容量，不取得进程资源互斥锁。扩容先准入新旧缓冲区的重叠峰值，再调用底层分配器；底层失败退还局部使用量，但不释放父级额度。分配器 owner 保留账户层级，存在未释放分配时销毁分配器会失败关闭。准入峰值、使用量、容量、拒绝数均不冒充 RSS。

BufferPool 的页/控制块、哈希桶/节点、两条新旧队列已统一使用可选的拥有型 PMR 资源。分配失败时，页索引和队列共同回滚，随后才发布 resident/pin/dirty 计数。提升热页使用同一队列节点的 splice，不再先删除再重新分配，避免失败后损坏 recency 路由。保留 generation、私有页、pin、flush 和淘汰语义。

PlanCache 的两份查询文本、链表节点、索引节点和桶同样支持拥有型 PMR 资源。string-view 异构查找无需临时分配查询键；先完成克隆，再淘汰/替换旧计划；索引插入失败时回滚链表条目。容量为零时直接关闭缓存，不克隆，也不访问空链表。这尚未覆盖克隆后的逻辑算子/表达式内部堆分配，不能当作完整计划内存治理。

验证：190 个受影响测试/18 个 suite 通过；增加 owner 生命周期用例后，再通过 46 个缓存/额度测试/3 个 suite，共覆盖 192 个不同测试，失败 0。逐个注入首次准入的分配失败，验证空状态/重试、元数据实际容量、共享额度、底层失败、并发消费者、分配器持有、零容量和克隆失败。只构建相关对象及核心库，未执行全量单元测试或性能 benchmark；随后补充的两个标准库显式 include 通过独立头文件警告即错误编译。证据和身份见 proof.json 与压缩模块归档。

这些构造参数仍为显式选择；原生 StorageIO 和 QueryEngine 仍使用普通默认资源构建缓存，不能据此宣布全局缓存计费或验收 S5.3/S5.4。下一步需选择并接通同文件别名共享的有界额度策略，补齐码本载荷、计划节点/编译分配，保持输出/pin 所有权，避免每个句柄独立预留完整缓存额度，并在真实原生入口验证准入、回退/淘汰和释放。写入/维护归属、积压、分区算子及最终资源/故障/性能门禁仍待完成。

# A1 节点列批次到聚合的生产接入

日期：2026-10-12。状态：无分组、非 DISTINCT、直接节点属性的 count/sum/avg 已接入内部列消费者，320 项相关模块测试通过。属于 S1.1/S2.2 的局部实现，不代表完整类型化聚合或阶段验收。

## 链路与访问路径

LogicalPlanReadRuntime 新增内部 NodeColumnReceiver，借用查询局部字段布局和列消费回调。visitOperator 仅在当前直接 NodeScan 子算子使用它，不隐式传给后代算子。普通索引选择仍先于原生列扫描；索引候选与其他后端继续通过原行消费者进入同一个聚合组，不另建独立查询语义。

原生节点扫描在实际扫描谓词字段之外追加聚合字段，重复字段只读取一次。完整 source 矩阵校验、快照引用校验、标签过滤、字节准入、按实体 ID 排序读取和原扫描顺序映射仍由原生产者负责。类型化/标量列过滤结束后直接交付列矩阵、选择向量和原顺序映射；此路径不构造逐节点 values 哈希表与属性缓存，也不读取完整节点。

聚合表达式在初始化时限定为直接相同节点变量的属性引用，或 COUNT(*)/COUNT(n)。字段使用借用 string_view 与数值绑定，元数据 PMR 容量共享现有查询预算。生产者将字段绑定到实际 source 序号一次，跨同次扫描的批次复用；布局不跨查询或缓存计划存活。下游结果仍走原聚合组的拥有化输出与预算转移。

## 准入、语义与所有权

- 仅支持无分组、非 DISTINCT 的 count/sum/avg 组合。复杂表达式、分组、DISTINCT、其他函数和额外参数保留原实现。
- count(property) 必须与数值兄弟聚合共享实际字段；独立 COUNT 字段保留原 presence 探测，避免为计数读取可能很大的无关属性。纯 COUNT 继续走原有路径。
- 扫描 predicates 和输出字段在同一 source 批次读取。混合数字继续使用原累加器，整数/浮点的既有合并方式与输入错误保持；NULL/缺失被 count(property) 和数值聚合忽略，count(*) 计入全部匹配行。
- 消费列时按原扫描顺序迭代，不以属性 lookup 的排序改变浮点累加结果。不同批次不重排，选中行计数仍受 maximum_rows 约束。
- 列及选择向量只在同步回调期间借用。累加器不保存 source 指针，结果不借用输入批次。固定数值/计数累加器没有新增动态载荷，因此复用既有对象准入和组释放计费。
- 新增字段请求的数组容量和动态字符缓冲单独计费。可选绑定元数据无法申请时释放容量并退回原行消费者；列扫描不能建立选择向量时保留原行过滤。真实预算失败、坏列矩阵、取消、分配失败和输入类型错误继续传播，不输出部分聚合。
- 谓词元数据在调用列消费者之前释放，数值绑定元数据在聚合输出之前释放。源列与选择向量仍按实际持有时间计费。调用方拥有逻辑计划、查询预算及累加器，生命周期覆盖同步扫描。

这一步消除了合格输入的逐行哈希表、缓存和表达式求值，但数值累加器依然接收 PropertyValue，不是完全类型化的 aggregate 内核。存储端也仍返回动态列；整数累加溢出规则等既有数值边界需要后续统一处理，不能据本轮回归宣称全部数值边界已验收。

## 正确性修复

新增空输入测试发现原 tryVisitDirectNodeCount 在参数为 NULL 时直接返回成功，遗漏无分组 COUNT 必须产生的零值行。现在显式生成一行 0 并交付原结果回调。必要的 count-only 回归覆盖该行为；其他多个聚合的空输入仍由预建聚合组输出 count=0、sum/avg=NULL。

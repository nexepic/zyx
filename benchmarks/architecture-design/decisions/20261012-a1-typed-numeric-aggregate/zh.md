# A1 类型化数值聚合内核接入

日期：2026-10-12。状态：整数/浮点列缓冲与 SUM/AVG 类型化更新已接入此前的节点列消费者，418 项相关模块测试通过。S1.1/S2.2 仍只完成局部实现，总体 1/34（2.9%）。

## 表示与生产调用链

PrimitiveNumericColumns 为同步源批次建立查询局部、有预算的数值列描述符。只有聚合实际请求的字段会转换，重复引用只转换一次。每个同类型整数/浮点字段拥有连续值数组与 uint8 presence 数组；全部 NULL 字段不分配值数组。混合类型和其他类型保持动态源引用。类型判断在每批进行，不推定动态属性具有永久 schema，也不跨查询缓存字段类型。

当前源仍是 readNodePropertyColumnsSorted 返回的 PropertyValue 矩阵。转换前验证完整矩阵形状与数值绑定，分类每个请求字段，再预留数组、填充值。列生产者尚未直接输出类型化存储数据，原动态矩阵仍存活并计费；本实现有额外分类/转换扫描和缓冲成本，不能据“类型化”名称推定一定更快。

节点列聚合继续按原扫描顺序、原聚合项顺序消费匹配行。类型化字段直接调用 SumAccumulator/AvgAccumulator 的 updateInteger/updateDouble，无需在每个值上经过 PropertyValue 数值类型检查和虚函数 update。非 NULL 的类型化 COUNT 使用实际 CountAccumulator 的行更新，NULL 不计数。动态字段调用同一原累加器。该内部接口只接受工厂创建的对应非 DISTINCT 累加器；逻辑函数与实际对象类型由已有工厂和准入检查保证，不是公开任意累加器扩展接口。

此前 SUM 的整数溢出检查集中在 updateInteger 内，动态与类型化路径共用，避免出现两套数值规则。AVG 仍按每个原始整数转 double 后追加；SUM 仍分开保存整数部分与浮点部分。浮点顺序、NaN、无穷及空值行为保持；不做重排、分块求和或数值近似替换。

## 所有权、预算与失败

- 描述符数组与每列实际数组容量通过同一个 BudgetMemoryResource 计费；列数组共享 owner 内稳定的 resource，不为每个字段另建未计费堆对象。owner 不可复制/移动，数组在批次内拥有数据，动态 fallback 仅借用原矩阵。
- metadata 申请超限时销毁已申请容量并返回未准入，消费者直接使用原动态列。单字段数组申请超限时临时列析构返还部分容量，仅该字段退回动态值；其他字段可以继续类型化。
- 仅数组 reserve 的 MaterializedByteLimitExceeded 被视为可选准入失败。上游 bad_alloc、非法形状、非法绑定及 guard 异常传播。分类与填充的 guard 在该捕获之外，即使 guard 恰好抛出预算异常也不会被误吞。
- 任何转换均先于聚合状态更新；取消或转换分配失败不能发布部分结果。后续累加错误仍使整个查询失败，原行顺序下的错误先后不因按列执行而改变。
- 所有动态源引用在同步消费者退出前失效；不借用存储页或把快照认证替换为类型判断。presence 在当前动态源边界仍合并 missing 与显式 NULL，不声称完成了 A1 的独立三态生产者。

# A1 执行状态分离与后续物理接口边界

日期：2026-10-12。任务：S1.1、S2.1 的状态生命周期部分。状态：查询资源与任务局部绑定在生产运行时完成分离，当前源码 438 项相关模块测试通过。下述物理计划和分组批次接口为后续设计约束，未实现部分明确列出，不据此验收完整 S1.1。

## 当前调用链及实际替换

QueryEngine 的逻辑计划缓存继续保存前端逻辑计划；LogicalPlanReadRuntime 的 executeOnSnapshot 创建查询生命周期，visitOperator 执行算子，最终结果回调进行拥有化。executeWithSnapshotAndInputRow 用调用者的快照重新解析输入；evaluateExpressionWithSnapshot 也创建本次执行资源。

此前 ExecutionState 将预算、实体缓存、输出保留、统计、相关输入和临时属性列视图置于同一结构。本轮拆分为 ExecutionSharedState、ExecutionTaskState 和借用查询资源的 ExecutionState。三个资源创建入口均独立构造 shared 再构造任务执行上下文；所有真实读取、预算、guard、输出和作用域切换使用明确的 shared/task 字段。没有新数据库 backend、没有替代公共 ABI、没有格式变更。

当前每次调用仅运行一个任务，因而原有扫描行数上限仍由该任务统计实施。本轮未增加线程池，没有允许多个任务同时使用非线程安全预算或共享实体缓存。此限制是实际代码边界，不是已经完成并行调度的声明。

## 所有权及生命周期

| 状态 | 实际 owner / 借用 | 生命周期和销毁顺序 | 后续并行要求 |
|---|---|---|---|
| 逻辑计划、表达式 | 调用者/现有计划缓存，执行仅借用 | 完整执行期间不可修改；当前新绑定不进入缓存 | 物理描述符不可变，任务不修改表达式 |
| 快照及 bounds | shared 借用调用者保证存活的对象 | 调用结束前有效；本轮不改变快照打开/pin 协议 | 先证明 snapshot reader 可共享，否则各任务创建同身份读句柄 |
| QueryContext/guard | shared 借用 | guard 失败立即传播；不将取消当作可选预算退回 | 共享取消/首个错误发布协议需在调度前实现 |
| 内存预算及 PMR owner | shared 持有 | 所有任务、批次、输出保留先销毁，预算最后销毁 | 全查询原子准入或单线程代理，不能按任务复制限额 |
| node/edge 缓存 | shared 持有 | 元素与 PMR 容器先释放，再释放 allocator 与预算 | 明确串行缓存访问或任务分片；不得直接并发写当前容器 |
| 最终结果保留 | shared 持有 | 最终化完成/异常释放后退出查询 | 单输出 owner 合并，不能重复计费 |
| 扫描/输出统计 | task 持有 | 本次任务执行期间；返回统计值不保留引用 | 工作量由全查询准入计数限制；任务统计 checked-add 合并 |
| injected_row | task 借用 | 相关子查询作用域保存旧值并恢复；导入行 owner 先于任务退出销毁 | 每个相关任务独立输入，禁止共享可写指针 |
| property_columns | task 借用 | 批次作用域内有效，退出恢复原视图；不进入查询缓存 | 各任务各自批次和 pin，不能借用其他任务复用数组 |
| 扫描游标、选择向量、聚合器 | 当前算子调用栈局部 owner | 原有 RAII、guard、预算与最终 takeResult 协议 | 移入各物理任务实例；阻塞合并状态另置 query/operator owner |

shared 的缓存不是新引入的跨查询缓存；不同查询仍各自持有预算、实体缓存与结果保留。后续进程/数据库级总预算由 A6 处理，本轮不以查询内拆分代替该项。

## 不可变物理计划与绑定身份的设计约束

执行绑定位于优化后的逻辑计划与执行实例之间，沿用既有语义表达式。不可变计划保存数值 slot、类型合同、访问路径选择、算法选择和流水线/阻塞边界；不保存快照 pin、参数值、数组游标、聚合器、可写选择向量或结果。当前 BoundSlotRegistry 的 plan/index 身份用于拒绝跨程序 descriptor，seal 后不可变；实际查询输入适配器仍是查询局部对象，不能直接提升成缓存计划。

物理计划缓存身份必须包含数据库实例身份、逻辑计划/语义版本及 schema epoch；格式或后端读能力变更需拒绝旧描述符。当前 LogicalGraphReadSnapshot 的 fence 不能未经定义就充当独立 schema epoch。快照内 Property token 放在执行解析表，解析表必须绑定 snapshot 身份；缓存中最多保留名字/稳定 schema 描述符，不能持有当前快照 token 或指向页的地址。参数类型若参与内核专门化，执行时验证实际参数并选择语义等价的动态路径，不能因上一次类型推断而接受错误值。

此部分仍需具体物理描述符、schema epoch 接口、缓存失效与跨数据库/快照测试后才可完成；本轮没有改变现有逻辑计划缓存或伪造缓存身份接口。

## 图中间结果的扩展合同

首版平坦批次继续支持当前 scan/filter/project/aggregate；后续接口不得把平坦行定为所有算子的唯一表示。可扩展分组表示由父绑定表、单调子 offset、子结果列、分组身份和显式重复次数组成。每个子记录归属于一个确定父记录/相关组；offset 空区间与 NULL 值不同，重复次数使用有界整数并对乘法/累加溢出报错。数据 owner 与 selection 保留原始物理位置，组标识不是 EntityId，也不能跨 snapshot 复用。

共享父绑定只在同一相关组内建立，两个分支即使父变量名字相同也不能据此交叉相乘。相关子查询的输入组包含外部绑定身份；optional 的无匹配输出由消费语义生成一个 NULL 扩展，并保持未匹配组的原父重复次数，而非无条件将空子列表计为一行。

| 消费者 | 允许直接消费分组的前提 | 必须展开/专门处理的边界 |
|---|---|---|
| filter/project | 只读父字段可按父组一次计算；读子字段按对应子位置计算 | 同时依赖不同相关分支、动态函数或路径时不能错误独立化 |
| COUNT/SUM/AVG | 已验证函数与重复次数规则，NULL 跳过和数值溢出一致 | 浮点乘权重可能改变逐行顺序，初版须按原序消费或拒绝该内核 |
| DISTINCT/group-by | 明确作用在完整可见绑定元组上的键与重复语义 | 不能各列独立去重后组合；未迁移前按原序展开 |
| OPTIONAL/subquery | 组内相关输入和 NULL 扩展规则有明确合同 | 有写入、可观察调用次数或短路行为时保持原执行次数 |
| path | 同一路径序列及重复身份归属于确定组 | 节点集合不能代替路径序列；最终路径必须拥有其数据 |
| sort/limit/skip | 排序键、稳定顺序及重复游标有明确实现 | 首版使用计费展开适配器，不能只截断父组 |
| 输出/Driver ABI | 对用户可见的每一行、重复和顺序显式产生拥有数据结果 | 不公开借用 offset/页指针，不降低现有输出语义 |

实际分组编码及消费者采用需通过代表性多分支/多跳原型的正确性和最终性能窗口验证；本轮仅关闭不能将无条件平坦化固定为架构合同的设计选择，未宣称实现因子化处理。

## 失败、恢复与移除边界

任务异常使用原异常类型直接传播，作用域恢复输入指针与列视图；预算失败不提高上限，不重放已完成 SUM/COUNT/写入。查询 finalizer 仍在成功和异常路径运行。此次仅内存状态重组，没有持久页、恢复信息或 retirement 新增；单文件提交/回收协议保持原实现。

现有 Project 行到 slot 适配器、NodeScan 动态属性列到数值数组适配器和未迁移算子的计费行接口仍为过渡路径。移除条件分别是相应生产者原生输出已绑定列、存储提供适配快照的类型化值 owner、以及对应算子的完整物理消费者接入；不能在只有一个直接 scan 快路径后删除通用语义路径。批次复用与动态载荷 owner 还需扩展，当前完整 A1 验收仍待这些接口及测试。

## 验证和反证

新增嵌套执行测试确认内层预算失败与成功查询不改变外层行和扫描/输出统计；同一 caller-owned snapshot 的内层 injected row 在异常及重新执行后不覆盖外层输入。既有相关子查询、表达式、批次、聚合、取消、预算及拥有化输出模块一并运行，438 项通过。测试目标为当前核心源码的 macOS C++20 构建，测试编译警告作为错误；未据此声称 Linux/Windows 已构建通过。

假设是显式 owner/任务边界能使后续物理实例复用查询资源而不共享游标/相关绑定。这属于生命周期基础改动，本轮不宣称性能收益。反证包括跨任务借用泄漏、多个任务各自消耗完整查询上限、错误时无法恢复输入或共享 cache 并发不安全；多任务执行必须在解决这些问题并通过独立隔离/合并测试后引入。分组表示若在真实分支负载下不能抵消维护成本，保留平坦物理批次并记录拒绝理由。

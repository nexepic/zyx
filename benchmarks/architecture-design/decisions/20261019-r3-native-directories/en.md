# R3.2 shared-map native prerequisite

Parent `9f7733ed`. R3.2 remains in progress; accepted progress stays 13/24. This advances the directory prerequisite after the five payload/gate steps, without accepting native hybrid property lifecycle or R3.3. Registration precedes the change.

The existing B+Tree supports only U64 or EMPTY leaf values. Retain that format and generic entry size: fixed maps encode an ordered key prefix followed by a fixed canonical value suffix in EMPTY leaves. The R3.1 decision now explicitly separates big-endian ordered keys from little-endian record bodies. Logical widths remain owner 12+4, column locator 12+16 and group locator 8+16, before actual packed framing, restarts, internal keys and native allocation. No allocated-space improvement is claimed.

`FixedBTreeMap<KeyBytes,ValueBytes>` encodes/decodes fixed records and performs one bounded prefix lookup plus a lookahead. Two native keys with the same logical prefix are corruption. Full native page authentication, snapshot routing and across-leaf traversal remain in the existing BTreeIndex. The helper checks record width/empty leaf value; typed callers must additionally authenticate locator targets/owner/type/generation and perform global bidirectional integrity. It does not implement a conversion writer, full cost estimator, extension variable-value codec or hybrid graph routing. Returned arrays allocate no heap; cursor and returned-key allocation still require the existing native memory scope, while its callback admits the cursor's boundary key only.

A map replacement must erase the exact old full record and insert its changed full record in one publication. The future owning planner must canonicalize one final replacement per logical prefix per transaction; blindly staging repeated replacements from the same snapshot can otherwise introduce duplicates. No automatic repair or last-wins fallback is added.

NativeGraphWriteTransaction now retains an explicitly requested EMPTY leaf layout for compound staged index updates, both normal planning and fresh-pool rebuild. Default U64 behavior stays in place. Unknown layouts, nonzero EMPTY values, same-index mixed layouts and foreign page stores reject. Whole-tree retirement remains the existing native protocol. This prerequisite neither allocates a new hybrid MetadataPageKind nor changes Superblock version 31/profile 5. The tests persist only existing-format generic indexes with synthetic bytes in a laboratory namespace, not a hybrid descriptor/column format or installed property route.

# A1 immutable property-binding descriptors

Date: 2026-10-14. Status: private execution-layer property descriptors and real snapshot boundaries pass module verification; complete S1.1/S2 remain unaccepted. This is neither a cross-query cache nor a second query executor.

Implementation: `src/query/execution/BoundPropertyBindings.hpp`. Requests contain numeric slots from a sealed BoundSlotRegistry and property names. Construction validates every slot plan/index and key work bound before resolving tokens. Repeated requests for the same slot/key share one descriptor; different slots remain distinct. Request mappings and unique descriptors use PMR containers. Keys are owned rather than borrowed from ASTs, input strings, or rows.

`BoundPropertyId` uses uint32 index/uint64 program identity. Program IDs are process-local, nonreused, and reject exhaustion. Different binding tables for the same slot layout and owners reconstructed at the same address reject old descriptors. The sealed layout is borrowed only during construction; the component copies source slot IDs and retains no registry/snapshot/page pointer. The query budget outlives this noncopyable/nonmovable owner so internal allocator addresses remain valid.

The source identity is the previous record's conservative catalog/page-directory observation, plus supportsPropertyTokenResolution capability. Construction rechecks both before publication to reject changes during resolution. View access validates program, ordinal, source identity, and capability. Changes throw BoundPropertyBindingConflict and require binding against the actual execution snapshot, not replaying consumed rows. Schema identity is neither a data-value cache nor a complete physical-plan cache key.

Resolved tokens must be nonzero. A missing token preserves a view of the owned key and requires name-based access; it does not prove logical NULL/absence. Real overlays can contain uncommitted fields without durable tokens, so this fallback is required. No permanent property type is inferred. Map/entity/dynamic access selection belongs to later physical consumers.

All descriptor/source/key inputs are validated before token resolution. maximumProperties bounds raw requests; maximumKeyBytes bounds raw key work, including duplicates. These are work bounds, not schema limits. PMR separately admits actual vector capacity, key buffers, and temporary deduplication nodes. Lookup temporaries release before publication. Budget pressure, allocator failures, cancellation, invalid tokens/identities, and source errors are not swallowed as token absence. Failure refunds table capacity while existing query owners remain charged. Fixed objects and query/decoder-wide accounting still belong to A6; complete resource integration is not claimed.

All 103 selected tests passed: 11 new component tests, 12 existing slot-registry tests, six real schema/descriptor backend tests, and 74 overlay tests. Coverage includes repeated/distinct slots, key ownership after input destruction, missing tokens/capability, foreign/out-of-range/stale IDs, every catalog identity/domain/revision/capability change, resolver-time identity changes, zero tokens/source errors, validation before resolution, failure/retry at every observed allocation, shared-budget pressure, and cancellation/refunds at every construction checkpoint.

On the real backend, a new catalog view rejects old descriptors while the original pinned source remains valid and reads its old value. Overlay mutation invalidates its old table; rebinding an untokenized staged field preserves name-based access and reads 9. Rollback invalidates source reads. These prove component/source boundaries, not migration of ordinary query pipelines.

Linux/C++20 only; no full suite or benchmark. Baseline remains pushed commit 646298ae; subsequent A1 code/records stay in the working tree.

Scope: current `work` tree at `f090e2b323d2cab845b32202306ed2f1e2151cb4`, including all uncommitted work. This is not a commit, deployment, adoption or completion report. Earlier results and negative evidence remain unchanged.

## Default-path and diff audit

- `ZYX_EXPERIMENTAL_STREAMING_COUNT` and `ZYX_EXPERIMENTAL_BORROWED_GROUP_KEY` default OFF in CMake; the current SCAN build cache has both OFF. Test hooks can explicitly opt in per thread. The default COUNT test and default multi-key control exercise the established paths.
- The joint value/presence provider is not implemented or connected to the executor. The separate native `LogicalGraphBudgetedNonNullProvider` can be explicitly discovered by an external caller, and `BudgetedPresenceScope` adds branches in common storage code; ordinary QueryEngine code does not call it. These are real production source/API changes, not merely test code. ROW refuses only while that experimental scope is active. ABI and zero overhead were not verified.
- Even with both switches OFF, executor structures have extra empty members/local state and the common storage code contains scope checks; test-hooks builds add diagnostics. The audit supports no default use of the experimental algorithms, not a claim that compiled bytes, overhead or ABI are identical.
- The numeric block and joint-window contracts are unconnected research code; they do not establish pruning or production work reduction. Existing direct-column batch lookup scratch is already in HEAD, not a newly completed working-tree optimization.
- The streaming COUNT persistent comparison had instability and small mixed-type regressions; the borrowed-key persistent comparison did not establish stable net benefits and added index memory for unique groups. Both stay OFF. Joint presence is deferred. No candidate failure completes R1 or R2.

## Data and costs

`benchmarks/graphdb-comparison/dataset/generate.py` creates deterministic CSV and manifest hashes without network: small has 23,000 nodes and 86,000 edges; medium has 225,000 nodes and 860,000 edges; holdout has 163,000 nodes and 772,000 edges. The already-observed holdout is not a new blind set. The runner README warns a medium database artifact can use hundreds of MiB. The original formal window specifies single CPU, 64 MiB buffer pool and query budget, 6 GiB address-space and 2 GiB per-file caps, three engines and three processes; its 1200-second process timeout is a limit, not a duration prediction. Current `/workspace` and `/tmp` free space and Kuzu availability were checked; the missing binary/images, not an assumed permission denial, prevent rerunning the old exact window.

The bounded ten-fixture SCAN experiment used 512/1536 nodes, totals 16,121,856 output bytes and took approximately 393 seconds summed fixture-test elapsed times on this machine under contemporaneous build load. It is a small synthetic cost reference only: it excludes some analysis, does not establish cold-cache cost, and must not be extrapolated to medium databases. No large download or restored file was attempted.

## Recommended next action

Use existing R0 evidence that a historic full-node predicate supplied 225,000 candidates while the comparable reference emitted 105,000 to design a snapshot-versioned, conservative predicate-pruning contract and a bounded no-format-change experiment. First establish statistic ownership, updates/delete/type-change invalidation, same-snapshot visibility, lookup/maintenance and build cost, and a disable control; stop if the cost model cannot support amortized work elimination. This is a falsifiable design/measurement step, not a claim that per-query statistic construction or pruning will be profitable. Independently, obtain a small anonymized workload profile: relative frequency of scans, traversals/joins and writes, typical data and working-set scale, plus latency/throughput priorities. Aggregate counts and distributions are sufficient; do not request raw queries, private data or raw tracing. This information informs a representative future validation matrix but is not required to inspect existing code or run bounded semantic tests.

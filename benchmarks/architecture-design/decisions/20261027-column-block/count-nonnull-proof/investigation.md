# COUNT fusion bounded investigation

The prior frozen persistent probe has 12 complete scenarios with three independent processes and six samples per arm. It shows inconsistent net latency: 128-row mixed highest-threshold pooled control/fusion ratio 0.733, with process ratios 0.791, 1.085 and 0.584. These observed elapsed ratios do not identify the cause. Attribution by those values or new instrumented wall-clock time would be unjustified. Raw samples and protocol remain in `../general-count-persistent/`.

Code-level work, not a CPU profile:

- `StreamingPredicateCount` allocates one admitted seen byte per candidate, rejects duplicate ordinals and validates the pinned identity. This is required by the current source contract; removing it requires an independently proven duplicate-free cell-delivery contract, not merely sorted input IDs.
- Every scalar callback validates shape/type, retains bounded cancellation/identity checks, then performs `mark` and predicate work. Text and owning callbacks additionally check identity per delivery. These checks protect lifecycle and error handling; no safe elimination has been demonstrated here.
- `BoundNodeColumnPredicates` emits a NON_NULL term for every range. Before this change the streaming loop calls the generic borrowed comparator for that term on every supplied non-null value. Scalars/text are intrinsically non-null at `accept`; owning values now reject explicit NULL before `accept`. Skipping that tautology removes one generic comparison dispatch per non-null value and term; it does not eliminate input reads, per-row duplicate detection, or all branching. This statement follows directly from control flow, not an elapsed-time measurement.
- The default direct path already writes presence/type/seen/value state and has a typed primitive filter with a type preflight, so it is not a generic boxed-value loop in all cases. The stream path's remaining comparisons still construct PropertyValue for numeric borrowed cells, while mixed-type ordering and NaN semantics require care. This is a candidate for future isolated attribution, not proven to explain observed tail or regressions.
- Both arms consume the same certified scan source; grouped property reading calls `authenticateOwnerRoutes` before `emitColumn`, which batches at most 64 cells with admission and cancellation. The current fusion does not remove page/group authentication, decoding, ID sorting or ordinal setup. Observed local owner-state savings do not establish whole-query savings.

The one change proposed by this slice is generic semantic simplification of redundant NON_NULL dispatch, in the default-off experiment. `protocol.json` was recorded before implementation. Source-level dispatch removal and full scalar-oracle tests are necessary evidence, not proof of performance. No new performance run, production adoption, pruning benefit or formal goal is claimed. Next investigate whether any representative, low-disturbance work attribution can establish that typed predicate dispatch matters; otherwise stop investing in this candidate and return to the previously observed supply/locating work. No persistent-format changes are authorized by this evidence.

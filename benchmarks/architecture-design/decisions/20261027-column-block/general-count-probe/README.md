# Bounded same-path COUNT fusion experiment

This is a synthetic in-memory certified-source fixture, not the historical formal window or a production/storage benchmark. `protocol.json` was saved before execution; `summary.json` records its SHA-256 and process medians. The three `run-*.log` files retain all measured samples, independent complete-result oracle checks and untimed path counters. The coverage-instrumented test executable had SHA-256 `bc004f38f51053cb0f69beec377ed547e880c59ebb62d60a0e341e06e5440f43`.

The test-only thread-local switch disables only the count-fusion branch; it is compiled out when storage test hooks are disabled. Both arms use the same source, query, snapshot, bounds and result consumer. Each result was verified against an independent scan of fixture values. Every untimed observation recorded all input rows in the intended fusion or direct-column path, respectively. The provider's three-row source batches and in-memory map are atypical; both paths incur these fixture costs. No persistent I/O, concurrency, write maintenance, RSS peak or cold-cache cost was measured.

Pooled disabled/enabled median ratios across the 12 cases ranged from 0.9708 to 1.9118; ratios above one favor fusion. The 96-row, pure-integer threshold-10 case was 0.9708 pooled and had per-process ratios 0.7775, 1.6918 and 1.1668. Other cases also show notable process variability. Double versus integer comparisons follow the current type-sensitive PropertyValue semantics; hence the mixed-type threshold 101 case is not zero-selectivity. Pure integer threshold 101 provides the zero-match case. Six timing samples per process/arm are not a basis for P95 or stable production performance claims.

A separate deterministic component test over 512 integer rows and eight callbacks retained 5920 bytes in the prior direct-column owner and 512 bytes in the streaming owner, with equal 264-row counts; this is a component accounting observation, not a complete query allocation or RSS measurement. The fusion adds one byte of seen-state per candidate and no persistent statistics or write-maintenance work; total query allocations and write costs remain unmeasured. No new path is recommended for default adoption from this probe: retain as an experiment until representative persistent-source, workload, allocation and stability evidence exists. No claim is made that R1, the old gate or the Kuzu objective passed.

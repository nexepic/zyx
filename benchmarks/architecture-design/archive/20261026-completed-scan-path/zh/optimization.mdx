# 批量扫描路径架构优化方案

更新：2026-10-26。计划标识：`scan-path-20261023`。**本页记录本轮已完成的实施路线，聚焦当前最高优先级的批量扫描瓶颈。本轮优化路线交付进度为 100%；文档更新与历史诊断不计入实现进度。**

旧计划的提交、导入和实验冷热转换已完成，不再列为待办；旧验收保留在 `benchmarks/architecture-design/decisions/20261023-core-cost-acceptance/`。历史实施完成不表示读取性能达标。后续严格按本页推进，不把旧 P1–P7、阶段报告或实验能力清单重新并入工作队列。

## 1. 本轮目标与范围

唯一主线：**让候选产生、实体/标签验证、属性读取和算子消费形成低开销的完整批量扫描路径**。保留通用属性图能力，以减少每实体重复工作取得结构性收益，不针对查询文本、标签名称、固定字段或 benchmark 数据分布增加分支。

本轮覆盖标签过滤、无标签属性过滤、真实单键与多键分组，以及它们共享的投影/字段供给机制。用户于 2026-10-26 明确取消“必须提升 5 倍”的硬门槛。依据两库各主场景相对同机初始及控制版本的实际收益、完整语义和资源/空间合同进行选型；原始 5 倍失败证据保持不变。超过 Kuzu 仍是目标，必须逐项报告，不能将选型通过等同于已超过 Kuzu。

2026-10-26 用户进一步明确：完成本文优化路线即可交付，不强求当前超过 Kuzu，差距可后续优化。路线交付进度与性能成熟度分别报告；不得把已知回退写成通过，也不得为追赶 Kuzu 无限扩展本轮范围。实验格式仍按扫描收益、转换成本及点查/写入代价显式采用，默认 ROW 格式不自动切换。

本轮用户最新执行要求覆盖阶段计时顺序：已完成一次初始 ZYX/Kuzu 校准，实现期间只运行必要模块测试，不再运行性能测试。S2 候选比较与 S5 综合对照合并到全部优化代码和必要测试完成后的最终窗口。性能证据到位前不提前验收 S2，也不采用默认生产路径；可继续在隔离实验格式中补齐必需生命周期。固定权重、两个候选、原采用门槛、资源上限及 holdout 冻结规则保持不变。

**本轮不开展**独立批量导入重构、普通写事务优化、向量扩维、radix/B+Tree 替换、通用缓存、WAL/LSM、JIT、多线程扩展或整体 backend 重写。现有导入只负责按冻结流程生成真实输入。候选布局所必需的更新、恢复和维护属于本轮；新的 COPY 产品入口不属于本轮。

- 标签查询仍处理 100,000 个属性根、196 批；全节点过滤处理 225,000 个属性根、440 批，实际交付 220,000 个数值字段。直接类型列与 runs 已经生效，不能把增加批接口当成新优化。
- 标签查询属性目录 refill 为 1，游标已复用；不是每实体重新走完整棵目录树。仍存在逐实体记录头/身份/偏移目录检查及字段选择。
- 热读操作窗口主要消耗 CPU；不支持以磁盘等待作为首要原因，但未测硬件 cache/TLB，不排除 CPU 内存停顿。
- 标签过滤与单键分组的三个供给阶段合计约 86%。只消除标签过滤 42.6% 的属性交付成本，其他不变时理论上限约 1.74 倍。因此不能只优化列布局而保留其余供给链。
- 阶段包含消费者回调与分配，不能等同纯解码或纯 I/O；其余部分不等同全部聚合成本。每场景一对控制/采样进程，仅用于粗粒度归因；读取有约 13–17% 未解析 libc 叶样本，不能随意分配给上层函数。
- Kuzu EXPLAIN 显示节点表扫描和所需属性列，未出现额外属性索引；EXPLAIN 不证明 zone-map 实际跳过数量。本次 profile 主要针对 medium，holdout 时延使用既有正式结果，不能声称已完成 holdout 新剖析。

### 2.2 按成本消除组织优先级

以下顺序针对同一条扫描链，不能拆成互不相干的局部调优项目。CPU 占比用于定位，实际提速由端到端计时确认。

| 顺序 | 必须改变的工作 | 实施边界与验证信号 |
|---|---|---|
| 第一 | 减少逐实体属性根定位、记录头/偏移解析和字段交付 | 在同一快照内复用认证与定位；稳定类型字段按块提供给现有类型列。记录属性根访问次数、解析次数、回退比例及分配，不能只增加批次数计数 |
| 同一阶段必须贯通 | 减少索引候选产生后再次逐实体确认存活/标签的工作 | A 复用合法的批内证明；B 从认证成员块产生 ID 和标签选择集合。完整覆盖无属性节点、多标签和删除语义，不以旧字段组的 live 位图替代完整实体集合 |
| 选型通过后 | 完成上述表示的事务、恢复、回收与普通输入采用 | 同根原子发布；验证更新、旧快照和重开，不建立独立一致性体系 |
| 最后 | 检验现有消费者和守护场景的剩余成本 | 在新供给链上重新确认残余成本；没有新证据，不启动聚合内核重写、树替换或通用缓存项目 |

内存只承载有预算的批缓冲和绑定快照版本的短期视图；持久成员/字段块由现有缓存和 COW 管理。不得用启动时全库展开、常驻属性副本或无限增长认证表掩盖存储访问成本。当前证据支持改造扫描表示和访问边界，尚不能证明更换 radix/B+Tree、整个存储引擎或事务机制是必要条件。

## 3. 必须保留的系统合同

- 通用动态属性、多标签、稳定逻辑 ID、缺失与 NULL 区别、类型变化、复杂值和 LargeValue，以及 Cypher、事务、Driver ABI、绑定和既有算子语义不变。
- 严格单文件、COW、A/B Superblock、data-before-root、持久化确认、read-your-writes、旧快照、取消、统一资源预算和安全回收不变。不关闭同步、取消或校验换性能。
- 保留用户已确认的“局部访问校验＋完整 integrity”：访问的页和新路径验证；未访问分支损坏由首次访问或完整检查发现。任何验证复用必须绑定不可变物理版本、generation、快照及适用 I/O epoch，不能只凭逻辑 ID 或指针地址。
- 字段块/内存视图不成为未记账的第二份数据库。持久、瞬时、索引、旧 pin 保留和维护峰值分别核算；不能静默增大已有缓存、查询内存或临时空间限额。
- macOS/Linux/Windows 与 WASM 兼容要求保留；测试平台逐项列出。Linux 诊断观察器不进入可移植生产代码。
- 新格式先更新[存储规范](native-single-file-storage-plan)，明确版本、旧库读取/拒绝、显式转换和失败回退；不得覆盖用户原库。既有实验转换的全库空间、峰值和原子性门槛不得绕过。

## 4. 架构设计方向与选型边界

以下为 S1 已登记、S2 待验证的设计合同，不代表已交付的生产能力。S2 验证后才展开完整生命周期实施。

### 4.1 一个逻辑模型，一套批访问契约

- 稳定逻辑 ID 与物理位置分离；有界分组不等同固定标签表。同一实体多个标签不得造成逻辑重复，类型变化不得变成 schema 错误。
- 批契约包含实体 ID/顺序、可见性、标签成员信息、列类型、缺失/NULL 掩码、必要的选择集合，以及借用数据的 owner/版本/生命周期。
- 能共享的身份、可见性和字段定位证明尽量在块/批边界建立；逐值仍保留实际需要的类型、范围及语义检查。认证标签成员信息必须在创建、删除、标签变化和恢复时与数据原子一致。
- 同一入口供过滤、投影和单/多键分组使用；禁止另建只服务 COUNT 或固定字段的影子执行器。
- 底层向现有类型化批接口交付数据；简单类型不重建通用 PropertyValue 矩阵或逐行属性 map。复杂值、混合类型、缺失字段的回退须有明确边界和成本计数。

### 4.2 最多两个候选，不先承诺列式胜出

比较两个有限候选：A 为现有 ROW 上可复用的块/批定位与认证视图；B 为类型稳定、较密集字段的持久类型化块，稀疏/复杂字段保留通用表示。两者都必须贯通候选与实体验证，不允许拿“纯内存数组”与完整生产查询比较。

复用已有实验布局前，逐项核对其批契约、采用范围和总成本；不得仅因代码已存在就选定。字段宽度、类型稳定性、密度、更新率和实际访问成本驱动选择，不能匹配 `User`、`country`、节点数量或查询文本。选型规则在 holdout 验证前冻结。

### 4.3 更新与维护属于读取设计的一部分

优先验证局部块 COW。只有已证明小更新写放大不可接受时，才比较有界更新层；不得默认叠加新的日志/LSM 子系统。

S1 已冻结：每批最多 512 个实体，源工作区与单块编码分别不超过 1 MiB；每块最多 64 个类型字段和 64 个标签；超限必须保留通用语义，不能截断。字段沿既有通用回退；超 64 标签组现以显式版本化条目保留完整存活位图，并在需要标签条件时从完整主标签集回读，见最新 S2 检查点。持久合并深度为 1，每次维护最多一个块、工作区最多 8 MiB。源工作区同时受调用者剩余查询预算约束；旧 pin 保留版本，不能提前回收。完整合同见 S1 `contract.json`，实施时不得以“自适应”为由突破上限。

字段/成员信息与主数据一次原子发布；失败、取消、崩溃不能暴露部分转换。搬迁与回收通过原版本/所有权机制，不能用独立于事务的数据缓存隐藏一致性问题。布局不合算时保留 ROW，拒绝原因可观察；不能靠放宽空间门槛让 benchmark 强制采用。

### S2：有限选型验证，收益不足先停在此门

在真实持久数据上打通候选 → 可见性/标签证明 → 字段批 → 现有过滤/分组 → owning 输出。包含更新后读取和重开，计时包括实际生产调用链；转换、构建和维护成本单列，不藏进准备阶段。

只做一次有界候选比较窗口，最多两个候选；若发现明确实现错误，允许一次定向修正复核。先在 medium 开发，冻结规则后用 holdout 检验。按用户最新要求，不再以固定 5 倍作为采用门槛；必须有真实端到端收益并同时满足语义、资源和空间合同。若所有候选失败，记录未解决成本，保持阶段未验收，形成受限的设计修订；不得自动扩展其他优化方向或降低门槛。

#### 历史 S2/S3 验收检查点

S2 已依据 2026-10-26 用户明确取消 5 倍硬门槛的指令验收，带来 35% 进度；随后 S3 已验收，S3 阶段进度为 65%。选定修复后的 B：24 个独立进程、960 个正式样本通过完整 oracle，两库八项主场景相对同机初始和 369 控制版本均有实际提升，相对 369 为 1.91–3.84 倍。整库分别节省 17.25% 和 14.57%，预算未扩大。原始两轮未达到历史 5 倍要求的证据不修改；本次直接复用现有计时，不追加基准。Kuzu 仍在全部八项对比中更快。S3 已移除 A 跨批 pin，完成公开生命周期交付；当时 S4/S5 尚未完成；最终交付见第 8 节。新规则及选型证据见 `20261026-user-gate-revision/s2-acceptance.json`。

历史候选 A 使用跨批 ROW 页面 pin 复用定位与解析，未被选中。S3 已移除该跨批 pin；普通 ROW 回退保留既有单页拥有型缓存及逐实体校验，写入纪元失效检查继续保留。B 的有界原生字段窗口独立保留。

真实 holdout 已完成：222,035,968 / 259,915,776 字节，节省 14.57%；公开 SDK 四主场景的完整 CSV oracle 通过，未收集延迟。medium 的 v11 构建暴露元数据容量准备异常安全问题；修复并通过实验 98、默认 3、兼容 3 项相关测试后，v12 从原始输入重新构建后已完成发布：256,507,904 / 309,985,280 字节，节省 17.25%；四个公开 SDK 主场景的完整 oracle 通过。首次正式 S2 性能比较已执行但未达采用门槛；结果见 `results/20261024-work-scan/final-comparison/selection-gate.json`。详细证据及失败历史见第 7 节。

#### S2 的执行顺序与完成证据

1. **先验证公共批边界。** 从 `LogicalGraphReadSnapshot` 到 `DirectPropertyColumns` 及现有过滤/分组消费者建立有界供给；复用既有 snapshot、owner 和 incarnation 机制。批内 ID、可见性、标签证明与字段必须属于同一版本；借用仅在约定回调生命周期有效，返回结果拥有自己的数据。取消或消费者抛错后不得重放已输出前缀；预算不足必须在输出前拒绝或有界缩批。
2. **候选 A 必须减少真实重复工作。** 审查 `visitNativeNodeLabelCandidates`、`readNodeLabelMatchesSorted`、`readNodePropertyCellsSorted` 和 `PropertyCollectionRootScanCursor` 的衔接，记录哪些页定位、身份检查、属性目录解析能够在同一不可变版本内复用。将现有逐实体循环包进新批接口不算完成；如果 ROW 仍须逐实体访问属性根，必须保留该成本并据实评估收益上限。
3. **候选 B 必须覆盖完整供给链。** 持久扫描块同时提供有效实体 ID、标签成员信息与类型字段，无法覆盖的字段走通用 ROW 回退。现有实验格式 13/39 不提供完整标签证明，不能直接当成这一候选已完成。先补齐版本、编码、校验、发布和恢复的 wire 规范，再写入真实文件；显式离线构建独立目标文件，源文件只读，未完成目标不得作为完整库打开。全库稳态空间至少节省 10%，源/目标/临时文件合计不超过 2 GiB；禁止用局部转换通过替代全库准入。
4. **先正确性，后一次候选比较。** 对批边界、标签重叠、缺失/NULL/混合类型、旧快照、更新后重开、预算拒绝和异常取消运行相关模块测试。随后按 S0 登记的四场景、两个数据集、三独立进程及每进程三预热十正式样本完成 S2 比较；这不是重复全量性能矩阵。
5. **交付可审查的选型结论。** 每个候选分别列出端到端 P50/P95、语义 oracle、候选数、实体/属性根访问数、批次数、分配与源工作区、实际采用/回退比例及构建成本。对比冻结基线，解释哪些工作被消除、哪些只是批量封装；不得凭微基准或 CPU 占比推算实际提速。只保留通过门槛且总成本合算的方案进入 S3。

优先级固定为：完整扫描供给链 → 选中方案所需生命周期 → 泛化与回归 → 最终比较。聚合内核、树替换和独立写入优化不因实现方便而插队；只有新证据推翻当前归因时，才记录证据并按第 6 节修订范围。

此阶段不铺开全部迁移/维护功能。通过证明的是方案值得实施，不代表已具备生产安全性；进入 S3 后仍必须补齐全部生命周期。

### S3：贯通生产生命周期

实现最终选定的一条公共批访问路径，移除被放弃的候选分支。登记默认/实验/回退/转换采用条件，让后续生产输入实际能使用新路径，不以 benchmark 私有安装器作为交付。

补齐：插入/删除、增加/删除/改变类型的属性、多标签变化、同事务覆盖、旧快照与 read-your-writes、LargeValue/复杂值回退、局部更新或降级、重组、重开、A/B 发布恢复、字段/成员信息一致性、页搬迁和 pin 释放后回收。明确数据格式与显式转换入口，避免长期维护两套事务或查询语义。

### S4：验证通用性与总成本

只执行受影响模块单元测试和必要集成用例，不运行全量单测；测试真实语义和故障边界，不写仅镜像实现的断言。

- 查询：空输入、全/零命中、缺失与 NULL、混合数值/文本、NaN/溢出、空串/嵌入 NUL、长字段、多键 tuple 和重复语义。
- 生命周期：上述更新、旧 pin、取消、预算拒绝、转换拒绝、部分/完整根写故障、恢复、完整 integrity。
- 泛化：在 S0 预登记至少一组不同字段密度/宽度/类型分布和标签重叠的输入；覆盖更新密集、稀疏字段及数据工作集超过配置缓存预算的情况。不得依据获胜结果挑选输入；不以配置缓存不足冒充物理冷盘测试。
- 总成本：查询、点查/邻接、单属性更新、1000 边批写、转换与维护分别记录；内存和稳态/峰值磁盘计入全部结构、旧版本与辅助索引。已有空间/资源上限保持不变。
- 性能守护：原点查、完整实体、邻接、大字段及写入场景按同口径检查。P50/P95 超过 5% 的退化必须公开解释，修复本轮发现的实现异常，并将仍存在的实验格式代价列为采用限制；仅对可疑项交替复测，保留原始结果，不通过删除慢样本消除退化。

### S5：一次最终统一验收

在代码与必要测试冻结后运行一次约定矩阵，不每轮重跑。主场景和守护沿用原语义、线程/预算与热缓存定义；三独立进程、每进程三预热十正式样本，输出逐进程及合并 P50/P95、样本、失败和 N/A。无稳定新变化不重复全矩阵。

报告：冻结起点 ZYX、最终 ZYX、同条件 Kuzu；查询结果 oracle；候选/实体/属性根/批工作量；CPU 与等待边界；转换采用率、构建与维护成本、稳态/峰值空间、实际验证平台。不能把嵌套 timer 相加，不能把 sizeof 累计当 DRAM 流量，不能把进程 RSS 高水位或文件轮询当精确峰值分配。

用户最新要求明确以完成本文优化路线作为交付标准，不强求当前超过 Kuzu。100% 对应路线实现、必要测试、基准对照及文档交付；不表示全部性能指标通过。5% 守护阈值仍用于揭示采用代价：未通过的点查/属性及回退场景保留失败事实，限制实验格式采用，不改写为通过。默认 ROW 不自动切换；Kuzu 与进一步性能优化列为后续工作。

## 6. 推进纪律与停止条件

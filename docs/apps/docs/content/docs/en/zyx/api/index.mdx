# API Reference

ZYX exposes a modern C++ API plus language bindings built on the stable Driver ABI.

## Which API to use?

- **C++ API** (`include/zyx/zyx.hpp`) — Use when developing in C++20. Offers type-safe values, RAII transaction management, and a fluent `QueryBuilder`.
- **Node.js API** (`npm install zyxdb`) — Use when developing in Node.js. Async interface with prebuilt platform binaries.
- **Python API** (`pip install zyxdb`) — Use when developing in Python. Provides Pythonic interface with context managers, iterators, and pandas integration.
- **Driver ABI** (`include/zyx/zyx_driver_abi.h`) — Use for Rust, WASM, and future bindings. It exposes opaque handles, explicit lifecycle management, nested value traversal, and stable `zyx_driver_*` symbols.

### Driver ABI

The Driver ABI is the stable C-facing runtime boundary used by language bindings and WASM. Its public contract lives in `include/zyx/zyx_driver_abi.h`, and exported symbols use the `zyx_driver_*` prefix. New C integrations should use the Driver ABI directly, while most application code should prefer the C++, Node.js, or Python APIs above.

## Design Conventions

- Query execution returns a `Result` or Driver ABI result handle. Callers iterate rows explicitly.
- Transactions are available in three forms:
  - **API-level explicit transactions** — `beginTransaction()` / `zyx_driver_txn_begin()`
  - **Read-only transactions** — `beginReadOnlyTransaction()` / `zyx_driver_txn_begin_read_only()`
  - **Cypher transaction statements** — `BEGIN` / `COMMIT` / `ROLLBACK` within `execute()`
- When no explicit transaction is active, `execute()` auto-commits write queries and uses a read-only fast path for reads.

# Scan Supply Architecture Optimization Plan

Updated: 2026-10-26. Plan ID: `scan-supply-20261026`. Status: V0 accepted, V1 pending. **Cumulative progress is 15%; documentation, old test reruns and diagnostics that fail quality gates earn no implementation credit.**

This is the sole active optimization roadmap. The former `scan-path-20261023` text is preserved under repository `benchmarks/architecture-design/archive/20261026-completed-scan-path/`. Historical evidence remains intact. Old stage numbers, 100% status, waivers and timing order do not govern this plan. Update this plan and the decision record before expanding its scope.

## 1. Objective and core problem

Reduce work per useful field in complete queries and substantially narrow the Kuzu gap. Diagnose all-node property filtering first, cross-check label filtering, and validate generality with single-key and multi-key aggregation. Beating Kuzu remains the long-term objective; no unmeasured speedup is promised and the old fixed 5x gate is not reinstated.

**Core hypothesis: typed column interfaces still carry substantial fine-grained location, authentication, resource-management and delivery work. Amortize that work at block, batch and snapshot boundaries.** Confirm this with current-version attribution and public end-to-end comparisons; it does not establish physical layout as the root cause.

New interfaces, cache entries, counters or isolated function fixes do not substitute for architectural gains. Necessary correctness fixes remain mandatory but are not standalone performance milestones.

## 2. Facts and evidence limits

- Historical formal medium all-node filter: ZYX 232.544 ms, Kuzu 1.153 ms; all eight primary gaps span approximately 15.2–201.7x. Repository evidence: `benchmarks/architecture-design/decisions/20261026-roadmap-delivery/`. Read timings belong to archived c8b37bc3 binaries, not a fresh measurement of HEAD.
- Current column batches group at most 64 owners, still call admission per value and build temporary position/value arrays. Query admission invokes guard checks and budget updates. Their causal CPU share is unknown.
- Metadata cache hits still involve lookup, locking and LRU; I/O mutation epochs invalidate caches/proofs. Locks do not establish contention, and mixed-write invalidation does not explain every read-only gap.
- Native columns, runs, batch proofs and cross-group directory read-ahead already exist. Inspect adoption before implementing duplicate wrappers.
- Preliminary evidence: `benchmarks/architecture-design/decisions/20261026-architecture-validation/`. Existing module binaries passed 113/25/89 rerun tests and 30 public outputs passed complete oracles. Sampled/control medians were 635.385/405.104 ms, approximately 57% disturbance: inadmissible for precise attribution or selection. Unknown libc/vdso samples remain unresolved.
- Historical integrity, conversion, write and snapshot evidence applies to its recorded versions; acceptance is not inherited by new candidates.

|---|---|---|---|---|

| Label property filter | 238.214 / 6.237 | 38.2x | 155.730 / 5.254 | 29.6x |

Documentation cleanup does not require repeating the existing initial baseline.

### 2.2 Order for validating the core problem

1. **Establish where time goes.** Separate candidate/label generation, property location/authentication, field delivery, filtering/aggregation and result materialization. High counts do not establish time shares. Report cost per input entity, useful field and batch, alongside actual reads.
2. **Remove systematic per-entity administration first.** A batch interface may still perform per-value admission, checks, mapping and copying. Make fixed administration scale with batches or necessary pages, while necessary decoding scales with useful fields.
3. **Then determine whether layout limits the ceiling.** Enter V2 contiguous field blocks only when group-level random location and page distribution dominate the low-overhead supply path. If operators dominate, improve typed consumption; larger groups cannot solve operator costs.
4. **Reject marginal work using an upper bound.** If removable work occupies fraction p of total time, eliminating it entirely yields at most `1 / (1 - p)` speedup. A 10% share permits only about 1.11x. Derive p from credible attribution. If the ceiling cannot meet the frozen target, address the shared supply path or revise the design instead of accumulating micro-optimizations.

## 3. Architecture boundaries and change order

Retain the single file, COW, pinned snapshots, atomic root publication and public API/ABI. Retain B+Tree point/location responsibilities while reducing repeated tree entry during scans. Do not automatically switch default ROW storage.

Prioritize the storage-to-operator batch contract and implementation, then evaluate layout. Generic optimizer replacement, WAL/LSM, backend rewrites, JIT, SIMD, parallel expansion and independent import/vector/adjacency redesign are outside scope. Expand only through a documented revision when attribution demonstrates a shared foundation blocks all candidates.

### 3.1 Separate three granularities

| Granularity | Meaning | Treatment |
|---|---|---|
| Persisted field group | 64 consecutive entity-ID slots, possibly sparse; one machine-word bitmap | Retain initially; small size alone is not a defect |
| Scan window | Cross-group location, authentication, reading and reuse | Amortize within access order and memory bounds |
| Execution batch | Rows consumed by filtering/aggregation | May span multiple persisted groups |

Sixteen groups supplying up to 1024 rows is an experimental option, not a prescribed optimum. Compare density, field width, selectivity and budgets; report peaks and fallback. Repeating old calls inside a larger loop does not qualify. Changing persisted capacity requires codec, bitmap, point-read, update, reclaim and migration evidence; do not simply change 64.

### 3.2 Target batch contract

Explicitly carry entity IDs/order/uniqueness, snapshot and source identity, visibility and label selection, field types and missing/NULL masks, selection vectors, ownership/lifetime, budget ownership and fallback state.

Borrowed views remain within valid pins and invocation lifetimes; escaping outputs own their data or extend their owner explicitly. Reuse proven order/identity within its authority, never across invalid snapshots or uncontrolled writes. Preserve fallback for mixed types, complex values, transaction overlays and sparse fields. Fallback cannot replay an emitted prefix.

### 3.3 Code boundaries and required changes

These are current entry points, not prescribed future filenames. Confirm real adoption along the call chain; unused new interfaces do not qualify.

| Responsibility | Current entry points | Required evidence |
|---|---|---|
| Candidates, labels and batch identity | `include/graph/storage/LogicalGraphNodeScan.hpp`, `src/storage/relocatable/backend/RelocatableStorageBackend.cpp` | Avoid unnecessary candidate/selection generation; public queries adopt reusable snapshot, order and uniqueness proofs |
| Group directories, membership and fields | `include/graph/storage/relocatable/property/HybridPropertyReadContext.hpp`, `HybridPropertyValueReader.hpp` | Continuous cursors and authentication reuse reduce repeated location; bounded fixed-width reservation replaces per-value admission |
| Typed columns and consumers | `src/query/execution/DirectPropertyColumns.hpp`, `LogicalPlanReadRuntime.cpp` | Filtering/grouping consume typed runs with fewer intermediate arrays/generic values; complex fallback stays correct |
| Pages and resources | `src/storage/StorageIO.cpp`, `src/query/QueryGuard.cpp` and existing budget accounts | Lifecycle justification for amortized caching/checks; complete memory accounting, corruption detection and cancellation |

For each candidate, the V0 decision records the confirmed hotspot, operations and complexity to remove, affected contracts, module test selection, end-to-end threshold, point/write/space ceilings, fallback and stop conditions. Mark unquantified hotspots unverified; they cannot justify layout replacement.

## 4. Stages and delivery gates

Fixed weights: V0 15%, V1 30%, V2 25%, V3 20%, V4 10%. Award cumulative progress only on stage exit. Do not commit merely to inflate percentages. Authorized milestone commits/pushes include evidence; merging main is not automatic.

| Stage | Cumulative exit progress | Current state |
|---|---|---|
| V0 Attribution and freeze | 15% | Passed; see scan-supply-v0 decision |
| V1 Supply path | 45% | Pending |
| V2 Layout decision | 70% | Pending |
| V3 Lifecycle and generality | 90% | Pending |

### V0: Current attribution and experiment freeze (15%)

Freeze source, options, binaries, inputs, queries, oracles, threads and budgets. Reuse validated input where possible; confirm equivalent semantics and timing boundaries for formal comparisons.

Inspect all-node and label paths, native/fallback fractions, candidate counts and useful fields. Inspect Kuzu plans and observable work; EXPLAIN does not prove actual block skipping.

Observe native field reading, supply plus operators, and complete public queries with identical fields, visibility and result semantics. Layer experiments locate costs; subtracting times does not establish exact causality.

Collect CPU leaves/stacks where available, allocations, directory accesses, decodes, admission callbacks, cancellation checks, copies and invalidations. Distinguish counters from measured traffic: sizeof is not DRAM traffic; cache misses are not physical disk waits.

Pair sampled and unsampled runs with alternating order. Target at most 5% observer disturbance; reduce frequency or split observations otherwise. If noise prevents classification, mark evidence uncertain and exclude it from selection. Unavailable hardware counters are reported, not grounds to disable correctness protections.

Exit: reproducible cost model, evidence-quality statement and prioritized removable work. Preregister candidates, outcome thresholds and resource ceilings using the valid baseline/model, constraining both end-to-end gain and point/write costs. Never lower thresholds after results. Without credible attribution, fix observation before changing formats.

### V1: Low-overhead end-to-end scans with retained layout (30%)

Reserve fixed-width budgets per bounded batch; admit variable-sized allocations using actual sizes before allocation. Preserve overflow, release, exception and nested-call accounting.

Place cancellation, timeout and resource checks at boundaries with explicit maximum work, retaining large-value checkpoints. No disabled limits or unbounded cancellation latency.

Reuse query layouts, buffers and selections; avoid repeated sorting/mapping for certified ordered unique sources; defer generic values and full entities.

Advance directory and field-page cursors across groups, reusing authentication and bounded views. Inspect existing eight-group directory windows and single-page cursors, proving actual reductions in location/rereads.

Let filter/count/aggregation consume typed runs directly, reducing repeated temporary words/ordinal/destination copying. Necessary copies require an ownership rationale and work counters.

Exit: native/fallback adoption and before/after work evidence, relevant modules and complete public results pass. Connect candidate production, membership/field supply and consumption; removing a few calls is insufficient. Targeted performance evidence may be collected in the final window; do not benchmark every edit.

### V2: Layout decision and minimum complete candidate (25%)

At most two candidates: A is V1 with retained layout; B is a local contiguous field-block design. Implement B only if A's remaining dominant cost is group location, page distribution or decoding and the cost model supports substantial potential gain.

B specifies block size, types/NULL/sparsity, ID location, visibility, update granularity and maintenance. Base plus bounded delta is only an option: define merge reads, delta bounds, consolidation triggers, old snapshots, atomic publication, recovery and reclaim together. An update-free array scan cannot win selection.

If A meets preregistered benefit/cost gates and evidence does not justify B, a documented retain-layout decision completes this stage. Do not change format for progress. If both fail, preserve failure and revise the design; neither declare performance success nor add unlimited candidates.

Version/page-bound cache reuse covers in-place writes, page reuse, cross-file and invalidation cases. Keep checksums and corruption detection; do not just delete epoch checks. Report opening/full-authentication separately from hot queries and preparation.

### V3: Lifecycle, generality and adoption cost (20%)

Relevant module tests cover missing/NULL, type changes, deletion/labels, complex/large values, native/ROW mixtures, read-your-writes, old/new snapshots, budget pressure, cancellation, non-replaying fallback, faults and reopen. Add meaningful regressions at changed fault boundaries; never weaken oracles.

Use real persistent dense, sparse, mixed-type, skewed and untuned holdout inputs. Freeze selection rules before holdout. Exercise repeated updates, long-lived pins, maintenance after pin release, space recovery and working sets beyond cache. Record read deterioration, version retention, write amplification, consolidation and memory peaks.

No enlarged budgets or hidden conversion. Guard point/full-entity/adjacency reads, property updates and batch writes. P50/P95 above 5% versus same-window control triggers review, not automatic proof of stable regression. Fix repeatable material regressions or restrict adoption explicitly; no default promotion.

Code files must not exceed 3,000 lines. Split by responsibility, updating source lists and generators so regeneration preserves the limit. Historical source evidence may be archived losslessly, never rewritten. Verify semantic preservation with affected modules; splitting alone is not a performance gain.

Run relevant module tests only, never the full unit suite. Preserve Linux/macOS/Windows and existing WASM contracts; list executed platforms and do not claim unexecuted validation.

### V4: Frozen formal comparison and architecture decision (10%)

After source and necessary tests stabilize, run one formal window: four primary queries, both datasets and necessary guards; three independent processes with three warmups and ten measured samples each. Report per-process and pooled P50/P95, failures and complete oracles. Compare same-machine frozen ZYX control and Kuzu with equivalent threads, output consumption and semantics. During development use only question-driven targeted diagnostics, not repeated full matrices; retest failures narrowly.

Account separately for open/authentication, conversion, maintenance, space, RSS and memory accounts. Process wall minus query time is not precise I/O attribution. Sampled binaries cannot supply formal acceptance timings. Identify changed binaries/inputs; never describe composite measurements as one uniform campaign.

Exit: choose retained layout, local layout replacement or a foundation-design revision with evidence, compatibility/migration and adoption limits. Report 100% only when all exits pass; separately report performance gates and Kuzu attainment. Documentation, functional success and old roadmap completion cannot replace new performance acceptance.

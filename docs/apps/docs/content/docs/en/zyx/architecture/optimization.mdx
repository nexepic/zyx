# Core Performance Refactoring Plan

Updated: 2026-10-22. Plan ID: `core-cost-20261022`. **This is the sole active optimization checklist. Implementation progress is 85%; P1/P2/P3/P4/P5 are accepted and the Kuzu performance objective is unmet.**

Eliminate the work amplification behind order-of-magnitude gaps and meet or exceed Kuzu on core workloads with equivalent semantics, durability, and resources. Code, tests, or archives do not substitute for that objective. Previous tasks, completed items, chronological logs, and percentages have been removed from this plan. Existing capabilities, failure evidence, and format contracts remain valid and must not be deleted with the old checklist.

## 1. Scope and invariants

Implement only three connected paths: **incremental metadata commit, directly typed scans, and bulk import reusing those mechanisms**. Memory views support the first two; they are not a separate general caching project.

- Preserve the general property graph, dynamic properties, multiple labels, stable logical IDs, and existing Cypher, transaction, QueryBuilder, GDS, Vector, Driver ABI, and binding semantics. Vector dimension expansion is out of scope.
- Retain strict single-file storage, COW, A/B Superblock, data-before-root, and durable acknowledgement. Do not obtain speedups by disabling synchronization, weakening validation, adding threads, or using unlimited caches. WAL, group commit, LSM, JIT, and wholesale backend replacement are out of scope.
- Preserve snapshots, read-your-writes, old pins, relocation, safe reclamation, cancellation, and unified resource accounting. Retain existing sort and DISTINCT/UNION spill; operators without spill must fail within explicit bounds.
- Never overwrite published physical pages. Keep logical IDs, physical locations, generations, and snapshot identities distinct. Specify any format change in the [storage specification](native-single-file-storage-plan) first, including versioning and old-file rejection/migration; never overwrite user files.
- Preserve macOS/Linux/Windows portability and the WASM path; list actually tested platforms. Independent platform release gates belong to [release follow-ups](native-remaining-work-roadmap); Linux results do not establish three-platform acceptance.
- Run only necessary affected-module unit tests, not the full suite. `--file` is not a test filter: use named suite/test filters. Documentation-only changes require documentation checks only.

## 4. P0: Freeze measurement and cost contracts

### 4.1 Correct comparison conditions

Freeze actual source, build options, engine/probe SHA, Kuzu version, CPU/storage, threads, memory limits, datasets, and schema/indexes. Use medium (225,000 nodes, 860,000 edges) and independent holdout (163,000 nodes, 772,000 edges). Never select data based on optimized results.

- Complete private-copy creation and file synchronization before timing. Align preparation across engines and distinguish warm caches, reopen, and genuinely cold caches; reopening alone is not cold-cache testing.
- Queries must return equivalent values, multiplicities, NULLs, and row counts. Writes must have equivalent operations and transaction boundaries and include durable acknowledgement. Report operation, commit, and end-to-end boundaries rather than selecting the shortest measurement.
- Report both production bulk import and an equal-commit-boundary control. Include parsing, data/index construction, commits, and agreed final durability. Different COPY and transaction boundaries do not measure equivalent underlying storage work.
- Record unsupported cases as N/A; retain timeouts, resource rejection, and errors. A core workload without an equivalent measurement remains unaccepted; do not remove it or substitute an easy winner.

### 4.2 Attribute costs before changing structure

Use bounded profiling on one representative path per class: ordinary country filter/real grouping, single-property SET, and bulk import. Separate user CPU, kernel CPU, and waiting; measure route visits/construction, decoding, allocation/copying, computation, page writes, and synchronization. Use sampling or exclusive phase timing; never add nested timers. Explain tracing overhead against an untraced control and exclude diagnostic latency from formal scores.

Record `M` (total routes), `k` (changed routes), tree height, unique and repeated page accesses, actual COW pages, metadata bytes, synchronization counts, and peak memory. Reads also record candidates, actual entities/fields, batches, and intermediate objects. Check fixed `k` at small, medium, and large metadata sizes, including height changes and split boundaries; this is a mechanism check, not another full benchmark matrix.

P0 produces named cost budgets, equivalent query/write contracts, correctness oracles, and one corrected baseline. Freeze these six primary workloads: ordinary label filter, actual grouping, multi-key grouping, single-property SET, 1,000-edge batch, and full import. Guard against regressions with point lookup, full entities, adjacency, no-op, deletion, and sparse/large properties.

## 5. Accepted incremental-commit contract

P1/P2 are complete. Preserve sorted/deduplicated final changes, changed-path radix COW and one copy per shared ancestor. Capacity and publication share the modification plan. Ownership checks touched pools; intrusive free-pool capacity skips full pools. Retired frames wait for the oldest pin. Post-publication handoff allocates no memory; missing coverage or a mismatched source rebuilds complete reachability.

Keep the approved local-access validation plus complete-integrity contract. Accessed pages/new paths are validated; fresh unvisited corruption is discovered on access/full integrity. Preserve snapshots, atomic A/B publication, data-before-root, recovery and refunds. Initialization, explicit migration and full checks may traverse globally; ordinary commits must not reintroduce full collections or periodic whole-graph reclamation.

Evidence: `20261022-core-cost-routes/` and `20261022-core-cost-ownership/`. One fixed change across 3/300/900 Catalog leaves visits 2/4/5 source route frames, six ownership visits each, and zero ordinary full traversals. End-to-end gains remain P7. B+Tree replacement is not a current task or automatic scope expansion.

## 6. Accepted immutable-view and candidate contract

P3/P4 are complete. Hot bootstrap/radix/Catalog/Allocator reads borrow immutable pages within existing 128-entry/1 MiB cache, budgets, snapshot and I/O epoch limits. Writers use private COW; escaping results copy/transfer ownership as needed. The 99.34% reduction in fixed-page copy counters is not a latency result.

Labels reuse existing B+Trees, atomic token cardinalities and Entity Map. Record/key widths and at most 64 actual candidate locations choose the path. All-node labels scan sequentially; candidates authenticate primary/all labels. Optional cost sampling may fall back only before visitor emission. Multi-label batches fit existing entity-cache bounds to avoid repeat decode.

Evidence: `20261022-core-cost-views/` and `20261022-core-cost-labels/`. Medium filter/group reduce 225000 scanned nodes to 100000 authenticated candidates; 100000 fields remain and now enter typed columns under P5. Old pins, overlay, deletion, rollback, reopen and affected modules were checked. Final lifecycle/performance gates remain P7.

## 7. Accepted direct typed batch contract

P5 connects production ROW selection → direct typed columns → filter/project → actual single/multiple-key grouping → owning output. Numeric bits and synchronous text views enter admitted typed storage; complex values/LargeValues/legacy adapters retain explicit owning fallbacks. Primary workloads do not construct complete PropertyValue matrices or row property maps. Authenticate immutable native identity at batch boundaries while preserving dynamic overlay and batch owner/incarnation checks.

Short-text kernels preflight types/lengths before consumption. Preserve missing/NULL, empty/embedded-NUL text, mixed-type fallback, complete tuples, numeric types/overflow, NaN and DISTINCT. Partial COUNT merges logical values, never cross-batch dictionary IDs. Charge temporary tables and permit admission fallback only before aggregate effects. Four short strings bound cancellation work to 256 text bytes; do not extend this contract to unbounded strings. Results own their data.

Evidence `20261022-core-cost-direct/`: 263 necessary module tests pass. One unchanged traversal-optimizer assertion also fails against the frozen baseline and is recorded separately. Medium filter/group each emit 100000 typed text cells with zero owning fallback in 196 batches. Filter count updates decrease 12500→196; group updates decrease 100000→1568 with unchanged oracles. There are still 100000 selected ROW roots.

A bounded same-executor ROW/compact-field prototype retains Release identities and all samples. It isolates synthetic in-memory representation, excluding actual directories, IO, space and update lifecycle; it grants neither persistent adoption nor Kuzu acceptance. No persistent layout changed. If P7 proves field positioning remains dominant, continue within this core scope. A new layout still requires a prior storage-spec revision and dense/sparse access, random gather, bounded updates, demotion, deletion, old pins, reclamation and file-growth comparison. A prototype without production consumers/lifecycle earns no extra progress.

## 8. P6: Bulk import reusing the new mechanisms

Confirm dominant import costs in P0. Reuse incremental commit and existing bulk APIs, merge entity/property changes by page, and build indexes from sorted batches where appropriate instead of per-row lookup/update and repeated publication. Do not create an import backend inconsistent with online storage.

Register memory limits, batch size, transaction boundaries, scratch usage, failure visibility, recovery, and cleanup. Include all indexes, constraints, and final durability. Over-memory input must use existing supported bounded mechanisms or fail explicitly; do not expand this into a general external-sort rewrite. Verify query results, node/edge counts, and index validity after import.

## 9. P7: Material gains and final objective

### 9.1 Measurement windows and acceptance

Run the complete matrix once for the corrected P0 baseline and once after final P7 freeze. During implementation prefer counters and module tests; allow one bounded prototype diagnostic per core route when deciding whether to invest in its complete lifecycle. Add targeted measurements only for new failures or contradictory evidence; never rerun the matrix after every commit.

Use at least 3 independent processes with 3 warmups and 10 measurements per query process. Import once per process, with at least 3 independent imports. Preserve per-process and pooled P50/P95, every sample, correctness, CPU, I/O, memory, and file growth. The maximum of 3 imports is not a reliable tail percentile. Write counts follow the frozen contract; preparation and verification have explicit excluded boundaries.

**Structural improvement gate:** on both datasets, single-property SET, ordinary label filtering, and actual single-key grouping must each achieve at least 5-fold P50 speedup over the corrected ZYX baseline. This is a target to validate, not a promise or existing result. Small gains require further dominant-cost investigation; counters cannot substitute for latency.

**Kuzu objective gate:** on both datasets, all six frozen core workloads must have final ZYX P50 no higher than the equivalent Kuzu control; reliably estimated query/write P95 must also be no higher. Equality means parity, not superiority; superiority requires consistently lower results across independent processes. Judge import using the equal-transaction control while also displaying production COPY results. Missing, failing, or slower core cases leave the objective unmet and P7 incomplete.

Guard workloads should not regress by more than 5% in P50/P95 against the corrected baseline. Investigate excesses with targeted confirmation; fix stable regressions. Use all preregistered processes, retain slow samples, and never use cross-process extreme envelopes or average speedups to hide individual failures. Increasing resource limits is not acceptance.

### 9.2 Lifecycle and final evidence

Affected modules must cover old pins and post-release reclamation, reopen, fault injection, allocation failure, cancellation, corruption, indexes/constraints, overlays, and cross-path equivalence. Measure space with long-lived snapshots and after they drain; a short plateau is not indefinite steady state. Mechanism tests verify scaling and actual work, not merely mirror implementation.

Preserve source/library identity, commands, input SHA, mechanism counters, necessary tests, raw samples, failures, and limitations in a new directory under `benchmarks/architecture-design/decisions/`. Do not commit large databases or build products; provide reproducible input generation and execution. Formal evidence must not exist only in ignored output or temporary `/workspace` paths.

P7 synchronizes actual changes into the [storage specification](native-single-file-storage-plan) and [capability matrix](native-capability-acceptance-matrix), and publishes per-workload before/after/Kuzu tables. **Mark this plan 100% only when mechanisms, correctness, structural gains, the Kuzu objective, and regression guards all pass.** Otherwise retain incomplete status and identify the next evidenced core cost; reporting the gap is not completion.

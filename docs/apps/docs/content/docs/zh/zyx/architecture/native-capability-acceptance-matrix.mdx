# 原生能力验收矩阵

> 本文是[原生单文件存储重构方案](native-single-file-storage-plan)的 C0 台账。它是验收记录，而不是愿景功能清单。公开契约有具名 native 验收测试时可标为 `NATIVE_COVERED`；`IN_PROGRESS` 只记录尚未闭合的最终门禁；只有 C0 consumer audit 确认仍有实际 legacy owner 或 specification source 时才使用 `HOLD_FOR_PORT`。已物理退休的 fixed-record、segment-chain、外置 WAL 和旧 Vector 实现不再是可保留的 fallback。

2026-10-22 导航更新：本表保留带日期的消费者与合同证据，不是当前任务清单。当前任务与验收唯一以[核心性能重构方案](optimization)的 P0–P7 为准。历史状态须按实际源码复核，不重复建设已有能力。

## 状态词汇

| 状态 | 含义 | 删除规则 |
|---|---|---|
| `NATIVE_COVERED` | native 实现及其公开行为已有具名验收证据。 | 只有所有依赖行与三平台门禁均通过后，才可考虑退役。 |
| `IN_PROGRESS` | 已有 native 路径，但契约、性能、事务、恢复或平台门禁尚未完成。 | 保留 native owner、公开行为契约和验收证据；仅当 audit 仍确认必要 specification 时保留旧测试，不得把已退休实现重新加入构建。 |
| `HOLD_FOR_PORT` | C0 audit 证明某个 legacy tree 仍提供实际行为、测试、公开 API 或必要 consumer。 | 禁止删除；必须先迁移该仍存在的行为与测试。 |
| `UNSUPPORTED` | 不属于支持的公开契约。 | 记录决策，且只有 C0 证明不存在 public consumer 后才可删除。 |

## 验收记录规则

任何仍存在的 legacy source/test 退役前，对应能力记录必须明确以下全部信息：

- 可观察的公开契约，包括结果、错误、顺序、事务可见性和资源上限；
- storage-neutral 的 native owner；不得以物理 Segment 位置作为公开 identity；
- 一个或多个通过 production source set 运行的具名 native test 文件；
- 平台、crash/recovery、性能与四维覆盖率门禁；以及
- 若有，则记录在这些门禁通过前仍作为 specification 的 legacy source/test family；若 implementation family 已物理退休，则记录由 native owner 承接的公开契约与验收证据，不得为了未闭合门禁重新创建旧 family。

当前树的 fixed-record、segment-chain、外置 WAL、旧 dictionary/index/state/traversal 和旧 Vector
implementation family 已完成物理退休；`cmake/SourceSets.cmake` 的 retired-path guard 禁止它们重新进入 native
source/test allowlist。它们尚未关闭的 C0-C7 门禁只能由当前 native owner 的功能、故障恢复、规模、coverage 和三平台证据关闭，不能以恢复旧源码或旧白盒测试代替。

新增 Cypher clause、function、procedure、C++ API operation、Driver ABI operation、binding 或管理命令时，必须先增加一行记录。广义的“测试套件通过”不能替代具名契约行。

## Procedure 级台账

`NativeProcedureManifest` 是当前 native procedure 的唯一事实来源；其 transaction mode 是公开执行契约的一部分：

| Mode | Procedure | 必需证据 |
|---|---|---|
| `NPTM_OVERLAY_SNAPSHOT_READ` | `algo.shortestPath`、Vector query | graph traversal 使用 overlay read-your-writes。graph overlay 未改变时，Vector search 使用 transaction-owned pinned derived generation；发生 graph mutation 后，使用有界 exact final-state overlay scan。storage-neutral checkpoint 会在 exact mapping/delta 遍历、ANN expansion、refinement 与 overlay candidate 中检查；cancellation 不会返回 partial result，也不会修改 pinned generation。测试覆盖 autocommit isolation、rollback、commit/reopen、timeout 和 exact-overlay boundary。 |

## 完成标准

只有每一个已支持的 clause、function、procedure、C++ API operation、Driver ABI operation、binding operation、algorithm 和管理命令都具有同等精度的独立记录时，C0 才完成。Driver ABI resource-group ledger 和当前 language-binding surface ledger 现已穷尽，C++ `QueryBuilder` 和 native-procedure sub-ledger 也已有明确 checkpoint。更宽的 family-level ledger 在 Cypher clause/function、剩余 C++ API 和 algorithm 拥有等价记录前仍刻意不完整：它现在保护 legacy specification，但不授权进一步删除。

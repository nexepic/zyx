# 架构调整与通用性能实施方案

更新：2026-10-18。**本页是后续架构调整和性能优化的唯一实施入口。已验收进度为 31/34（91.2%）；各阶段见第 5 节。剩余 S2.5、S3.5、S6.2 未验收，不能据此宣称已超越 Kuzu。文档同步不计为新增实现完成。**

## 1. 范围、决策和文档优先级

### 1.1 已确定的边界

- 继续使用 **COW 与 A/B Superblock**。不引入 WAL，不把 WAL 或跨事务 group commit 混入普通优化；改变提交确认协议需另立设计。
- 保持通用、嵌入式、严格单文件：持久数据、恢复信息及查询落盘空间均由同一个数据库文件管理，不产生数据库 WAL/SHM/临时 sidecar。
- 保留稳定 EntityId/PageId、逻辑与物理位置分离、快照与 read-your-writes、统一分配、搬迁、旧版本安全回收、显式 codec、完整性校验及公共 API/Driver ABI。
- 保留现有语句级 IR、Expression、逻辑计划与有收益的缓存/选择访问/批处理；不恢复已退休的存储或物理执行器，不另起一套完整数据库 backend。
- **A3 是布局设计与准入验证，不是全面列存替换授权；A4 也必须先解决一致性协议，再决定物理布局。**
- LLVM 是条件性实验，不是必选依赖。先完善非 JIT 执行；WASM 保留非 JIT 路径。
- 不针对查询文本、数据集名称、固定答案或 benchmark 特定规模建立快路径。通用成本模型可以使用实际基数、类型、字节数、页数和选择率。
- 生产代码保持 macOS/Linux/Windows 可移植；用户本轮指定 Docker/Colima 隔离评估，实测为 macOS 宿主机上的 Linux ARM64 容器；历史 macOS 数据单独保留。**只执行相关模块单元测试，不执行全量单元测试，覆盖率不是门禁，不 commit、不 push。** 不因仓库通用模板或归档要求改变此约束。

历史执行约束（2026-10-11，性能运行和提交策略由下段覆盖）：**实现期间不运行性能 benchmark，也不启动仅为 benchmark 而进行的构建或计时预检；完成优化代码与必要模块测试后，再统一进行最终性能对照。** 已有基线保留。S0 的未完成性能归因和 S2–S5 的性能准入部分顺延到最终性能验收窗口，先完成设计、实现及正确性/恢复/资源测试；依赖真实性能数据的布局采用决定保持待验证，不提前宣布收益或完成对应验收项。本约束覆盖下文历史阶段采样安排，34 项分母不变。

用户最新执行约束（2026-10-15）：**从远程 `work` 分支开展工作；优化开始前完成一次性能基线并与 Kuzu 比较，迭代期间不频繁运行性能测试，全部优化完成后统一运行最终对照；只执行必要的相关模块单元测试，不执行全量单元测试；每次已验收进度增长后提交并推送，每轮报告进度。** 本次运行环境为 Linux x86_64，历史 macOS/ARM64 证据单独保留。下文历史“不 commit、不 push”不再适用。

## 2. 当前事实和收益假设

当前链路包含 QueryAST、Expression、LogicalOperator 和 LogicalPlanOptimizer；逻辑 Runtime 直接执行计划，主要行表示仍使用字符串键哈希表。已有 EntityRef 延迟物化、选列读取、选择向量和有界批次，不应重复实现。

属性按 owner 集合组织，普通属性 mutation 请求替换完整集合；大集合可能整体编码到 LargeValue。普通邻接为全局 key-only B+Tree，通常要取 Edge record 才得到邻居/type。普通写事务使用图根 fence；安全但可能令不相交写冲突。排序有预算限制，尚不能据此宣称已有通用落盘执行。

## 3. 架构工作包 A1–A7

每项设计交付必须含：当前调用链、目标接口及所有权、数据/快照身份、失败状态、必要时的字节布局和版本、恢复与回收状态、替换边界、模块测试清单、性能假设及反证条件。以下是必须遵守的目标合同；具体 ABI/codec、块大小和成本参数须在 S1 的决策记录中定案，不能在编码时私自猜测。

本页是实施路线和设计准入合同，不是已验证的最终架构。S1 对下述问题逐项给出具体决策、证据或明确的后续实验；影响正确性和核心接口的未决事项必须在对应生产实现前关闭。设计时保留职责清晰、成本可控的目录层次，不以减少层数本身作为重构目标。

### A1：绑定后的执行表示与物理计划

保留前端与逻辑 IR，在其后新增执行绑定/物理规划边界。变量名在绑定时变为槽位；属性使用可校验的 token/描述符，明确 schema epoch 与计划缓存失效。静态可知类型使用类型化内核，动态/混合类型保留有语义等价性的回退。

执行批次包含类型化列、presence/null 信息、选择向量、EntityRef 和可变长载荷 owner；定义借用范围、批次复用、pin 生命周期、输出顺序和重复行。物理计划明确访问路径、连接/聚合/排序算法、流水线与阻塞物化点。先做非 JIT scan/filter/project/aggregate，再迁移 join、sort、unwind、procedure/subquery 及 mutation 的读侧；不能让这些路径静默绕回未计费的旧行表示。

公共 QueryResult/Driver ABI 在输出边界生成拥有数据的结果。过渡适配器必须列出使用位置及移除条件；不长期维护两套独立查询语义。空值、数值/类型规则、可选匹配、路径、相关子查询、取消及错误与当前公开合同一致。

**图中间结果合同**：类型化批次不等于图查询中间结果已高效。S1.1 必须决定共享父绑定、子结果分组及重复次数如何表达，哪些算子消费分组/因子化表示，哪些位置必须展开为平坦行。明确 DISTINCT、聚合、OPTIONAL、相关子查询、路径和最终输出的语义与所有权；不能把有相关性的分支误当独立笛卡尔积。允许首版使用平坦批次，但须给出具体适配边界和分组表示扩展方式，不把完全展开行固定为所有算子的唯一合同。是否实际引入因子化执行由代表性分支/多跳原型决定，不预设复制 Kuzu 的全部连接算法，也不能用这一缺口解释无连接扫描的全部差距。

**执行状态合同**：在 A1 区分不可变物理计划、查询共享状态、任务局部游标/批次/聚合状态及阻塞算子的合并状态；定义取消、错误、快照 pin、预算和输出顺序的归属。首版可单线程，但任务状态不能隐含为全局单例或不可分割的算子状态。O7 再决定并行实现和调度粒度，不能把基础状态分离拖到 O7。S1.1 交付状态/生命周期表及上述接口边界；这不要求提前引入线程池或调度框架。

### A2：属性增量修改合同

内部请求支持按键 set/remove，显式保留完整替换操作。不能混淆单键 SET、map 合并、完整 map 替换和 REMOVE 的现有语义。同事务多次修改可折叠最终持久状态，但每条语句的 overlay/read-your-writes 必须正确；大值引用不得跨失效生命周期借用。

仅为变化的字段计算索引、约束和统计增量；无需改变的字段不应无条件删建索引。创建后删除、值未变化、属性删除、类型变化、索引键碰撞和最终失败均有确定行为。属性、派生索引、统计与实体状态在同一 COW 发布点生效。

A2 可先使用当前存储布局实现，不能把“接口只传一个字段”当成“底层已局部写入”。两者分别测量。

### A3：面向通用图属性的分组分块布局

**目标：改善跨实体少字段扫描，并保留高效点读、小更新、动态属性和完整实体读取。不是把所有属性无条件变成稠密列。**

1. 按有界实体范围/槽位组织组；Node/Edge 身份空间分开。稳定 EntityId 与内部 slot 分离，删除/复用有 generation 和存活信息。标签仅为成员关系，不按每个标签复制属性，不因加标签搬迁整实体。
2. 组内属性块以 PropertyKey/token 标识；密集字段使用紧凑值数组与位图，稀疏字段使用有序 slot/value 或紧凑 presence/rank。保留混合类型及属性缺失语义；不能用观察到的一个样本推断永久 schema。
3. 有直接的实体/字段定位，也有该实体实际字段的枚举路径。完整节点读取不能遍历全库属性 token 或扫描整个组。必要元数据必须计入空间、读取和 COW 成本，避免为每个 entity-property 再建独立树。
4. 大值使用独立 LargeValue 引用，变长普通值采用有界局部载荷。组大小、压缩块、页及更新单位分别定义；修改一个值不得重写整组或无关大值。优先验证页级 COW 的直接更新；不预设新增多层 delta/LSM、冷热迁移和后台自动布局切换。
5. 每个逻辑属性在每个快照中只有确定的权威版本。若允许列块和稀疏扩展区共存，组描述符必须无歧义地决定归属；扩展区不是第二份完整副本。布局转换与回收在同一可恢复协议内完成。
6. 查找不得绕过快照/owner/generation 校验；组分裂、槽位复用、大值替换、失败发布、搬迁和整组删除必须明确旧版本可达性。首次实施限定少量编码，阈值来自通用空间/访问成本，不使用 benchmark 名称或特例规模。

S1.3 必须提交访问路径与成本表：单实体单字段、完整实体、跨实体少字段扫描、单字段修改、删除/回收各自经过哪些目录/描述符/数据页，哪些页会 COW。分别列出定位、字段枚举、presence/type、分配和索引元数据；给出其随实体数、实际属性数、字段种类和页大小增长的成本关系，并以实测页数/字节数核验。不得只统计属性载荷，或通过新增昂贵的成员目录掩盖扫描收益。

分组准入还必须覆盖随机交错的实体形状、与标签无关的插入顺序、大量仅出现一次的字段、持续类型变化及删除后的稀疏组。明确元数据增长边界、分裂/重编码触发条件及其最坏前台工作量；完整实体读取和局部修改的成本需与现有布局同时报告。没有可接受结果时保留原布局，不因“列式”名称推定其更优。

**准入流程**：先完成现有行布局对照，再实现完整生命周期原型，最后决定是否切换。沿用旧原型读取代码前，必须补齐图目录接入、索引维护、不可达子块/root/LargeValue 退役、重开和失败恢复，不能把实验载体当生产引擎。

必测：单/多字段范围扫描、随机单字段、随机完整实体、邻居属性读取；稀疏/稠密字段、混合类型、多标签、宽实体、大值；set/remove/类型变化、导入、删除、长快照及持续更新。记录端到端延迟、读取/写入字节、峰值内存和稳态空间。任何明显点读/更新退化都须解决或形成明确产品取舍，不得只用平均扫描收益覆盖。

若原型不满足第 6 节门槛：拒绝该原型，保留生产格式，给出成本归因和修订方案；S3 的生产接入项保持未完成。不得为得到 100% 静默跳过 A3，也不得为了执行清单强行采用退化布局。

### A4：直接邻接访问与可信派生布局

逻辑批次能提供 EdgeId、NeighborId、TypeId 和必要可见性信息，保持方向、重复边、自环、类型过滤、continuation 和 overlay 语义。权威 Edge record 仍定义边身份/拓扑；覆盖数据是受协议维护的派生表示，不是可独立更新的第二份权威。

设计必须先回答：哪些认证允许查询直接信任邻接字段；哪些校验在加载/发布/完整性扫描执行；遗漏成员如何发现；损坏、错 generation 和不一致如何报告。不能在尚未证明新合同前删除现有主记录回查；checksum 通过也不等于索引与实体一致。

S1.4 交付故障模型和校验责任表，分别说明页级字节/格式/身份校验、事务原子维护、跨结构完整性检查承担的保证与发现时机。逐项处理 torn write、错误 owner/generation、邻接字段不一致和遗漏成员；不能承诺普通局部读取能发现所有全局不一致。若采用由原子维护建立一致性、查询在有效快照下信任覆盖字段的协议，须明确适用前提及完整性扫描职责；相对当前逐条回查改变的错误检测时机必须同步到公开合同、规范和故障测试。未获准前保留现有行为。

在同一逻辑接口下比较两种候选：共享 Packed B+Tree 的覆盖 entry；多个节点共享、按方向/类型组织的分段邻接块。均应支持低度数共享空间、超级节点、在线修改、原子双向维护、搬迁与回收；不为每个节点建立根/独占尾页。端点/type 若当前 API 不支持修改，不为测试新增公开语义。

覆盖树若已满足目标，优先较小改动；分段方案只有在收益抵消维护/写放大后才采用。对照必须含无属性遍历、类型过滤、多跳、随机插删、热点/幂律度数、自环多边和长期空间，避免只测顺序导入。现行 key-only 文件在版本切换前保持原语义。

### A5：事务隔离与冲突粒度

首先从公开合同和现有测试定义隔离级别，不自动宣称 serializable。记录事务快照、读依赖、实体/属性写意图、唯一性及范围/谓词依赖、schema epoch。根据选定隔离级别验证幻读、write skew 等结果；不能仅检查写集合后宣称串行化。

目标是不相交修改无需因整组图根变化无条件失败；相交写、约束冲突、节点删除与创建关联边仍必须检测。通过验证后在最新根上重建候选，并原子发布；提交门可以串行化，不能持有旧页面指针直接覆盖新版本。ID lease、重试、读写叠加、无确定结果的提交及资源归还需明确状态。禁止仅删除全局 fence。

S1.5 必须写明所承诺的隔离级别、允许/禁止的并发结果，以及冲突检测键、验证时机、重试边界和验证成本；未定案不能开始放宽生产 fence，不能默默降低已有保证。区分逻辑读写冲突与物理页共享：不相交实体/字段可能位于同一 COW 页，必须定义在最新版本上的重建/合并或保守拒绝规则，不能覆盖对方修改。使用双事务交错案例验证唯一性、端点删除、write skew、范围读及同页不相交写。

### A6：资源所有权与文件内落盘执行

统一 query/batch/operator 的预算、pin、可变长数据和取消语义；计入容器实际容量及持有资源，不仅统计逻辑行数。预算超限应选择受支持的落盘路径或明确失败，不能静默截断结果/吞掉损坏错误。

增加数据库/进程级资源协调：定义并发查询、缓存、写事务私有页、维护任务及可选代码缓存的计费归属，避免共享资源重复计费或漏计。S1.6 给出总限额、子预算申请/归还、压力下等待/驱逐/spill/失败的顺序、取消释放和避免资源等待死锁的规则；各查询分别未超限不能成为进程总内存无界增长的理由。资源约束针对可计费分配，RSS 与外部运行库开销仍单独报告。

先实现排序 run 与归并，再实现可分区的聚合/哈希操作；列出暂不支持落盘的算子和返回错误。复用单文件分配基础，但现有 bulk scratch 不等于已具备查询 spill。持久 scratch 登记、所属查询、释放、崩溃清理、磁盘不足及共享句柄必须定案。

明确区分逻辑只读事务与物理只读文件。逻辑只读事务不修改用户图数据；在可写文件上是否允许分配查询 scratch，须由独立内部权限及生命周期协议明确授权，不能绕过用户 mutation 禁令。物理只读文件不能写 scratch；严格单文件约束下，超内存且无可用执行路径时明确失败。临时页不属于普通用户数据根，定义独立可达性、活动查询 pin 和安全回收身份，避免被无关长快照无谓保留；scratch 分配/释放与用户提交不得丢失彼此的 allocator 更新。崩溃后可回收临时数据，但不得误回收用户数据或仍有活动 owner 的页。

维护预算分别约束前台、后台回收与整理。长快照阻止回收时提供可观察的积压与限额，不能无界增长或破坏仍被引用的页。

### A7：格式演进与实施边界

逐项定义新增 root/页类型/描述符、codec 字段/位宽/字节序、版本、可达性、原子维护、retirement 及 integrity walker。采用已有 namespace 和共享 allocator，新增枚举使用跨平台前缀。版本切换必须有明确旧文件拒绝测试；不要读取归档中的版本号直接写入代码。

维护“已实现 / 待验证 / 已拒绝 / 已替换”决策记录。A3/A4 当前只确定目标，不声称 codec 已定稿。每次采用布局后同步本页决策与格式规范的相关节，移除相冲突的未来路线禁令，同时保留旧证据。

当前新格式拒绝旧文件的开发期策略保持不变；它不是永久兼容承诺。S1.7 必须定义稳定格式承诺的触发条件、envelope/Superblock/局部 codec 兼容矩阵及不支持组合的拒绝行为。稳定版本发布前须确定迁移方式、旧文件保护、容量需求、验证和失败恢复；本轮交付此发布前提及版本边界，不默认实施迁移器或承诺具体发布日期。不能以本轮无需迁移为由，让后续格式演进没有明确责任。

上述样本数是起始采样规模，不保证 P95 精度。S0 预先规定进程内/进程间汇总方式、控制波动评估、尾延迟估计方法及定向补测的停止条件/时间预算；同一进程内样本不能假装成独立进程。记录每进程结果和不确定性，不能只合并全部样本隐藏进程差异。保护场景接近阈值或尾延迟不稳定时，只增加受影响场景的独立轮次/持续采样；预算耗尽仍不确定就保留不确定结论，不能重复测到通过为止。

### 6.2 代表性矩阵

至少包含：命中/未命中点查、随机单字段/完整实体、标签/type 稀疏与稠密过滤、单/多跳及超级节点、DISTINCT/真实 group-by/sort/Top-K、参数查询、动态属性、宽行/大值、逐条小写/批量写/混合读写、长快照、删除整理、超过查询内存预算及持续更新。规模、度数、字段稀疏度、类型和选择率至少有未用于调优的留出组合。A3/A4 原型要用同一已改进的执行器/载体对照，避免混入 A1 收益。

正确性检查实际 ID、值、类型、NULL/缺失、顺序要求及重复次数，不只比行数或 checksum。Kuzu 不支持的场景记 N/A，不填 0；类型转换、schema、索引、绑定层、durability 不等价时单独披露，不能用于严格胜负声明。

### 6.3 准入规则

- 正确性、原子发布、恢复、快照、预算和资源清理必须通过。只跑受影响模块的必要测试，不跑全量单元测试；覆盖率可辅助诊断但不是准入指标。
- S0 预登记主要目标、保护工作负载和资源上限，禁止看结果后更换成功指标。默认期望主要瓶颈场景 P50 至少降低 10%，且跨进程可重复；保护场景 P50/P95 不应出现超过 5% 且超出控制波动的稳定退化。接近阈值或控制波动过大时结论为不确定，定向补测；这些是本方案决策阈值，不是对所有负载的性能保证。
- 内存上限不提高；峰值 RSS、查询内存、读写字节和稳态文件空间分别报告。超过 5% 的稳定资源增长必须解释并纳入准入决定；A3/A4 不得以不受控写放大、空间或点读退化换扫描速度。若需要突破保护阈值，先提交具体取舍并由用户确认，不静默放宽。
- 机制性收益（例如 CPU/分配下降）但端到端收益不确定时，如实标记，不宣布提速；不要为凑比例积累复杂度。拒绝无收益机制并保留原实现，不要求每个正确性修复都达到 10% 提速。
- 提前区分性能改动与基础合同/接口改动。10% 是主要性能实验的默认目标，不机械要求每个基础提交提速；基础改动按明确的依赖能力、语义/生命周期测试、复杂度和保护场景成本验收，并记录后续收益由哪个任务验证。不得在实验失败后将性能改动改名为基础建设逃避准入，也不得仅因刚好越过阈值就接受不必要的长期复杂度。
- 与 Kuzu 持平或更快是同语义、同资源核心工作负载的目标，不承诺所有负载全面超过。S6 必须列出尚存差距；完成文档清单不等于性能目标自动达到。

### 6.4 必要模块测试

A1：表达式类型/NULL/溢出、重复行、ORDER BY、optional/路径、子查询、mutation 读侧、取消、预算、结果所有权。A2/A3：最终态、旧快照、索引/约束、大值复用、删除/槽位复用、重开、故障发布和回收。A4：方向、自环、多边、type、continuation、overlay、索引不一致/损坏。A5：不相交/相交写、唯一性、端点删除、约定隔离级别、重试及不确定提交。A6：低预算、spill、磁盘不足、取消、异常、read-only 和进程崩溃后清理。

复用实际存在的 GoogleTest suite，实施时先查询用例名，使用明确 filter。`scripts/run_tests.sh` 的 `--file` 只限制展示，不限制测试；禁止只传 `--file` 误跑全量。格式/写入模块运行对应故障注入测试；文档修改只运行链接/MDX 验证。不得通过删除断言或改变预期掩盖实现缺陷。

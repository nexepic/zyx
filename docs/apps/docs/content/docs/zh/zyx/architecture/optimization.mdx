# 扫描数据供给架构优化方案

更新：2026-10-27。计划标识：`scan-supply-20261026`。状态：V0–V4 已验收，候选按明确场景限制采用，Kuzu 目标未达到。**本轮累计进度为 100%；文档编写、旧测试复跑和未通过质量门槛的诊断不计入实现进度。**

本页是后续优化的唯一执行路线。旧 `scan-path-20261023` 正文已归档到仓库 `benchmarks/architecture-design/archive/20261026-completed-scan-path/`，历史证据保留。旧阶段编号、100% 状态、阶段性豁免和计时顺序不适用于本计划。若新证据需要改变路线，应先更新本页及决策记录，不静默扩大范围。

## 1. 目标与核心问题

目标是降低完整查询中每个有效字段的处理成本，显著缩小与 Kuzu 的差距。以无标签属性过滤为主诊断查询，标签过滤交叉验证，单键和多键分组验证通用性。超越 Kuzu 是长期目标；本计划不承诺未经测量的倍数，也不恢复旧的固定 5 倍门槛。

**核心假设：扫描虽然已有类型化列接口，但数据定位、认证、资源管理和中间交付仍包含大量细粒度工作。应改变这些工作的组织方式，让成本在块、批和快照边界摊销。** 这是假设，必须通过当前版本的归因和真实端到端对照确认，不能据此直接宣称磁盘布局是根因。

禁止以增加接口、缓存条目、计数器或修复若干局部函数代替架构收益。必要正确性修复仍要完成，但不单独计作本轮性能里程碑。

## 2. 已知事实和证据边界

- V0 冻结控制的列批路径按最多 64 个实体组织字段段，逐值调用资源准入并构造临时位置/值数组；查询层准入回调包含查询检查和预算更新。工作区候选正在改变这些行为，尚不能作为已验收结果。单项管理工作的实际耗时占比仍未确定。
- 元数据缓存命中仍涉及查找、锁和 LRU；I/O 修改纪元变化会使缓存/证明失效。锁存在不证明竞争，混合写入失效不能解释全部纯只读差距。
- 原生列、runs、批内证明、跨组目录预读已存在。必须先核实现有路径，避免重复包装已有功能。
- 冻结边界及收益门槛以 `20261026-scan-supply-v0` 为准；B 的补充入口证据见 V2。早期高扰动诊断保留在历史证据中，不用于当前选型。50 ms 叶子采样的全节点/标签采样与控制中位比为 0.9571/0.9700，但仅有 208/71 个独立样本，不能解释为精确函数耗时比例。
- 旧完整性、转换、写入和快照证据仅说明相应版本行为。旧阶段完成不能继承为新候选通过。

### 2.2 核心问题的验证顺序

1. **先证明时间花在哪里。** 区分候选/标签产生、属性定位与认证、字段交付、过滤/聚合和结果物化；计数多不等于耗时占比高。记录每输入实体、每有效字段、每批次的成本，以及实际读取量，避免只看总时间。
2. **优先消除成体系的逐实体管理工作。** 即使接口叫 batch，内部每值准入、检查、映射和复制仍可能让列扫描退化成高成本逐行执行。目标是固定开销随批次数或必要页面数增长，必要的数据解码随有效字段数增长。
3. **再判断物理布局是否限制上限。** 若低管理成本供给仍被组级随机定位和非连续页面支配，才进入 V2 的连续字段块。若成本主要在算子，则优化类型化消费；不能用扩大组大小解决算子问题。
4. **用收益上限排除小修小补。** 若可消除部分占总时间比例为 p，即使将其完全消除，理论加速上限也只有 `1 / (1 - p)`。例如 10% 的开销最多带来约 1.11 倍。p 必须来自可信归因；若上限不足以满足冻结目标，应扩大到共同供给路径或修订设计，而非堆积零散微优化。

### 2.3 已确认的工作量与尚未证明的根因

V0 的全节点路径有 225,000 个候选、440 批、3,516 次组/成员解码、3,437 次列解码和 83,614 次元数据缓存命中。分层实验中，220,000 个字段值触发 220,880 次准入；标签路径的 100,000 个字段值触发 100,880 次准入。**批接口没有把资源管理工作充分批量化，这是本轮首先消除的结构性重复。**

字段供给加回调的包含区间较大，但回调包含谓词计算，不能称为纯存储耗时；缓存命中次数也不能直接换算成锁竞争或磁盘等待。当前证据不支持“64 太小导致数百倍差距”“换树即可解决”或“必须推倒重来”。保留布局的完整供给链候选已验证且收益不足；当前布局 B 仍必须按 V2 的工作量、完整结果和端到端门槛验收。

## 3. 架构边界与变更顺序

保留单文件、COW、固定快照、原子根发布和公开 API/ABI。保留 B+Tree 的点查/定位职责；减少连续扫描重复进入目录，而非先替换树。默认 ROW 格式不自动切换。

优先重构存储到算子的批契约及其实现，其次验证布局。通用优化器重写、WAL/LSM 替换、全 backend 重写、JIT、SIMD、多线程扩展、独立导入/向量/邻接重构均不在本轮。只有当前归因证明共同基础阻碍所有候选时，才提交明确设计修订扩大范围。

### 3.1 三种粒度必须分离

| 粒度 | 当前含义 | 本轮处理 |
|---|---|---|
| 持久化字段组 | 连续 64 个实体 ID 槽，可能有空洞；位图可用一个 64 位字表示 | 先保留，不能仅因数字小就改格式 |
| 扫描窗口 | 跨组定位、认证、读取与复用的范围 | 依据访问顺序和内存预算摊销工作 |
| 执行批次 | 过滤/聚合消费的数据范围 | 可跨多个组，不必与存储组相等 |

跨 16 组提供最多 1024 行只是可测候选，不能写死为最佳参数。比较密度、字段宽度、选择率和预算，记录峰值与回退。扩大扫描窗口必须消除真实重复工作；简单循环调用旧接口不算优化。改变持久化组容量需要编码、位图、点查、更新、回收及迁移证据，不直接修改常量 64。

### 3.2 目标批契约

批必须明确携带：实体 ID/顺序与唯一性、快照和来源身份、可见性及标签选择、字段类型与缺失/NULL、选择集合、数据 owner/生命周期、预算归属和回退状态。

借用视图只在有效 pin 和调用生命周期内使用；输出必须拥有数据或明确延长其 owner。来源已证明的排序/身份条件可复用，不跨快照或不受控写入复用。混合类型、复杂值、事务覆盖层和稀疏字段保留通用回退；已输出前缀不能因回退被重放。

### 3.3 代码落点与必须交付的变化

以下为现有入口，不规定未来拆分后的文件名；先沿真实调用链确认采用，不能只添加无人调用的新接口。

| 责任边界 | 当前入口 | 需要证明的变化 |
|---|---|---|
| 候选、标签与批身份 | `include/graph/storage/LogicalGraphNodeScan.hpp`、`src/storage/relocatable/backend/RelocatableStorageBackend.cpp` | 候选与选择集合只生成必要次数，公开查询实际采用；快照、顺序、唯一性证明可复用 |
| 组目录、成员与字段供给 | `include/graph/storage/relocatable/property/HybridPropertyReadContext.hpp`、`HybridPropertyValueReader.hpp` | 连续游标与认证复用减少重复定位；固定宽度准入由逐值转为有界批预留 |
| 类型列与算子消费 | `src/query/execution/DirectPropertyColumns.hpp`、`LogicalPlanReadRuntime.cpp` | 过滤及分组贯通类型段，减少中间数组与通用值；复杂值回退正确 |
| 页面和资源边界 | `src/storage/StorageIO.cpp`、`src/query/QueryGuard.cpp` 及现有预算账户 | 每项缓存/检查摊销均有生命周期依据；不漏计内存、不削弱损坏检测和取消语义 |

V0 决策记录必须列出每项候选的：已确认热点、预期消除的操作及复杂度、受影响合同、模块测试选择、端到端收益阈值、点写/空间上限、回退与停止条件。尚未量化的热点标记“待验证”，不得作为布局替换依据。

### V0：当前版本归因与实验冻结（15%）

1. 冻结源码、编译选项、二进制、输入、查询、oracle、线程及资源预算。优先复用已验证输入，正式对照重新核对双方语义和计时边界。
2. 对全节点过滤及标签过滤分别检查实际执行路径、原生采用/回退比例、候选及有效字段数量。检查 Kuzu 计划与实际可观测工作；EXPLAIN 不等于实际跳块数量。
3. 分别观测原生字段读取、字段供给加算子、公开完整查询。保持相同字段、可见性和结果语义；分层实验仅用于定位，禁止简单相减宣称精确因果。
4. 采集 CPU 热点与调用栈（可用时）、分配、目录访问、解码、准入回调、取消检查、复制量、缓存失效。区分工作量计数、实际字节流量与推测；sizeof 不是 DRAM 流量，缓存未命中不是物理磁盘等待。
5. 采样与未采样配对，交替顺序。建议以不超过 5% 的扰动作为归因质量目标；超出时降低频率/拆分观测。若噪声使该门槛无法判定，结果标记不确定，不用于选型。不可用的硬件计数如实标记，不因此关闭正确性保护。

退出：给出可复现成本模型、证据质量说明及最应消除的工作；冻结候选、结果阈值与资源限制。性能阈值依据当前有效基线和成本模型设置并记录，必须同时约束端到端收益和点写代价，不能测完后降低标准。没有可信归因时继续修复观测，不进入格式改造。

### V1：保留布局，贯通低管理成本扫描（30%）

- 将固定宽度字段预算按有界批次预留；可变长值在分配前按真实大小准入。检查溢出、释放、异常和嵌套调用，不通过漏计内存提速。
- 将取消、超时与资源检查放在有明确最大工作量的边界，保留大值处理检查；不得关闭限制或引入无界取消延迟。
- 查询内复用布局、缓冲区及选择集合；可信有序唯一来源避免重复排序/映射；延迟构造通用值和完整实体。
- 以连续游标跨组推进目录和字段页，复用认证与有界页面视图；核对既有八组目录窗口及单字段页游标，证明新增方案实际减少定位/重读。
- 让过滤/计数/聚合直接消费类型字段段，减少临时 words、位置数组和目标列之间的重复搬运。必要复制需有所有权理由与计数。

退出：公开路径原生采用与回退计数、各项重复工作前后对照、相关模块及完整结果校验通过。仅消除几个函数调用不足以退出；必须贯通候选产生、成员/字段供给与算子消费。定向性能证据可复用最终窗口，不每次修改都测性能。

#### V1 的实施顺序和逐项验收

按下面的依赖顺序实施，共同构成一个候选；不能只完成第一项就宣布架构优化完成。

| 顺序 | 实现要求 | 必须保存的验证证据 |
|---|---|---|
| 1. 明确批身份和资源所有权 | 沿公开查询追踪已有身份、排序、快照证明；复用已证明条件，确定每份缓冲区的预算账户及释放方 | 真实采用路径、旧批 ID 失效、重入及旧快照测试；不重复新增已有证明接口 |
| 2. 按有界类型段准入 | 固定宽度或已知大小的段在输出前统一准入；大值、溢出及异常保持检查 | 相同值数下准入次数从逐值转为逐段；预算拒绝无部分重放，释放后账户恢复 |
| 3. 复用扫描工作集 | 分别处理目录、成员页与字段页，避免交替访问相互驱逐；查询内复用可安全复用的布局和缓冲区 | 定位、解码、页读取及分配次数前后对照；小预算回退，纪元变化、页面复用及损坏检测 |
| 4. 类型段直达算子 | 过滤、计数、分组优先消费类型列和选择集合；仅在确有需要时构造通用值 | 与通用路径完整结果一致；NULL/缺失、NaN、混合类型、取消以及复杂值回退；列采用和复制计数 |
| 5. 连通与审计 | 在公开入口验证以上变化共同生效，列出仍然逐值执行的工作及必要原因 | 全节点与标签过滤、单键与多键分组的完整 oracle；工作量、内存峰值和剩余成本清单 |

代码已写入、文件拆分完成或单个模块通过均只记为实施状态。未经最终同窗口对照，不宣称达到 2 倍或超越 Kuzu。V1 可先用正确性与工作量证据验收；V2 的性能选型结论和 V3 的性能守护可与 V4 共用一次正式窗口，在证据齐备前保持待验收，不能为了阶段顺序额外反复跑全矩阵。

#### 已实现的保留布局修订（A2，历史状态）

A2 已把有界目录游标、定长叶键及字段读取状态放到查询/固定快照生命周期，借用完整验证的冷 ROW token/偏移目录，并修复逐实体存在性探测重复创建上下文。后续共同执行路径已同步借用有序认证 ID，避免每个实体重建临时引用；无序、复杂值与普通扫描仍保留回退。定长键的 32 字节上限不是实体组容量，持久组仍为 64。

### 5.1 冻结验收清单与交接要求

- 收益：八项主查询的控制/候选加速比几何平均至少 2 倍，两个数据集的全节点过滤分别至少 2 倍。2 倍只是本轮最低实质收益门槛，不代表已消除数量级差距。
- Kuzu 目标单列：八项主查询的候选 P50 均不高于 Kuzu，才按登记口径报告达到目标；同时披露 P95 和进程离散程度，不用平均值掩盖落后项。
- 资源：单线程，查询物化预算与 BufferPool 各 64 MiB，地址空间上限 6 GiB，文件限制 2 GiB。主查询/守护 P50、P95、内存峰值或文件增长超过登记的 5% 复核线时，解释原因并验证是否可重复；不静默放宽限制。
- 调优只用 medium 或独立合成样例；候选进入 holdout 前冻结选择规则。初始 holdout 基线已知这一事实必须保留。
- 每次交接记录：源码提交或未提交改动范围、当前候选、已通过和未运行的模块、原始证据目录、剩余阻碍及下一项操作。V1 验收适用于其登记版本 `e5e48d50` 及对应二进制；当前 B 与后续候选不继承这些测试结论。
- 如果 A 未达收益门槛，先检查公开路径是否采用、管理工作是否真正减少以及剩余主导成本。仅在定位/页面/解码证据满足 V2 条件时实施 B；若算子消费仍主导，则继续改造共同执行路径。无法满足门槛时修订设计并保留失败结果，不将文档完成记作性能完成。

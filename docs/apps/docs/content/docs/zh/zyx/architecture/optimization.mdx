## 2. 已知事实、核心假设与证据边界

已知事实：当前读取路径已有类型化列、批准入、认证 ID 借用、页复用和字段共享页，不能再以新增这些名称当作新优化。medium score 页已经从 3437 降至 859，组与 score 页并集从 3443 降至 1718，仍存在数量级差距。

当前源码揭示一个值得验证的共同结构问题：列数据先按实体和 64 实体组定位，再生成小段序号/数值，经回调组装查询列，最后执行过滤。主要入口：

- `include/graph/storage/relocatable/property/HybridPropertyValueReader.hpp`：`readSelected`、`emitColumn` 按组生成 ordinals/words，按类型、缺失和 NULL 切段。
- `src/query/execution/DirectPropertyColumns.hpp`：`appendScalarRun` 逐单元写数值、类型、状态和 written 标志，执行边界与有效性检查。
- `src/query/execution/read_runtime/NodeSupplyAndSorting.inc`：接收供给、组装并 seal 查询列，然后调用谓词过滤。
- `src/storage/relocatable/property/property_read/SelectedColumnSupply.inc`：源端批形状、顺序、快照及原生/ROW 路由。

**核心假设：存储已经具备列表示，但执行契约仍要求重复定位、整理和物化，简单分析查询因而支付了多层通用属性读取成本。** 假设不是最新版本的耗时归因。消除中间物化后若定位或解码仍主导，应转向对应层；不得为了预定方案忽视结果。

旧 63.97% 供给边界比例来自字段共享页前的候选，且是墙钟区间归因，不是当前 CPU 占比。旧分配次数也不能套用到当前版本。Kuzu EXPLAIN 不是实际跳块或算子耗时证据。没有可信测量时不得宣称“64 太小”“BTree 是根因”或“必须换 backend”。

因此，当前优先验证的是**扫描输入裁剪、按块摊销定位与认证、列式算子贯通**的组合。不能把复制或回调当作已经证实的主导根因，也不能把剩余 42.83% 全部算到聚合器。元数据借用量不等于复制量：已有工作计数中的约 135.76 MB 是逻辑借用尺寸，实际记录的固定元数据复制约 246 KB。

R0 已完成冻结、合格的粗粒度归因、工作量计数、Kuzu 输入核对、尾延迟复核及收益门槛登记，并通过真实持久数据上的可回退实验建立因果证据：批内复用预算内临时分组键，使多键查询分配次数从 125998 降到 26618，减少 99380 次；完整结果一致，37 项相关测试通过。证据见 `key-scratch/experiment-receipt.json`。它仍逐行序列化与哈希，不代表列块架构完成或等比例加速。

R0 的退出依据明确为合格的粗粒度成本模型、可验证的工作量消除、未解决风险和实施前门槛；不再要求所有微观耗时比例先精确测出。细项耗时和 P95 具体原因仍未解决，保留至后续验证，最终 Kuzu 与尾延迟验收条件不变。这里的 10% 表示归因与验证阶段完成，不表示性能目标完成 10%。

## 3. 目标、范围与优先级

最终目标：在相同语义、资源和结果消费条件下，八项主查询均达到或超过 Kuzu；同时验证生命周期和采用代价。阶段性架构收益与 Kuzu 目标分别报告，禁止把阶段完成包装成追赶成功。

第一优先级是存储—执行器之间的列块契约及其完整实现；第二是证实仍昂贵的扫描定位与列块目录；第三是类型化过滤、计数和分组直接消费。实现顺序由 R0 归因决定，不能无条件串行重写三层。

不预先扩大 64 实体逻辑组，不预先选择大块格式、换树、LSM、WAL 重写、JIT、SIMD 或多线程。逻辑组、物理页面、扫描批和算子批是不同粒度；需要改扫描粒度不等于必须改持久格式。只有证据证明共同基础阻碍目标时，先修订本页并登记依据，再扩大范围。

### 底层改动的决策边界

| 层次 | 首选验证方案 | 何时才扩大改造 |
| --- | --- | --- |
| 扫描规划 | 将可证明安全的谓词与所需列传递到扫描端，用可见版本对应的统计裁剪无效块 | 缺少可信统计时先完整扫描；收益确立后再决定统计持久化及更新维护方式 |
| 存储读取 | 跨多个 64 实体组的扫描窗口、连续列访问、块级认证凭证；保持逻辑组身份 | 只有计数证明现有布局强迫大量重复页访问/解码且窗口无法消除，才试验新物理列块或目录 |
| 执行器 | 类型化块、选择向量、延迟物化，过滤计数直接消费，分组复用类型化键表示 | 如果边界外成本仍主导，再针对已定位的计划、键构造或聚合路径改造 |
| 持久化与后端 | 保留已有事务、恢复、页管理及通用回退合同 | 更换 backend、树或事务框架必须先证明局部合同无法支持目标，并提供迁移与写放大对照 |

64 是逻辑分组粒度，不是所有计算必须以 64 为单位。先把扫描窗口与逻辑组解耦；不把加大实体组当作默认方案。当前证据支持验证接口和访问方式的改造，尚不足以支持推倒整个数据库。

### R0：先把当前成本定位清楚

1. 冻结当前引擎、构建配置、数据、查询、完整 oracle、资源限制和对照；确认当前正式二进制对应实际源码。复用已完成的持久镜像，单列准备成本。
2. 复用已通过门槛的边界和调用栈证据，继续在 medium 全节点过滤上分解：解析/计划/准备、候选与可见性、组/列定位、页面获取与认证、解码、供给适配与查询列组装、谓词/聚合、结果输出。标签过滤交叉验证；多键分组核对共同瓶颈和额外算子成本。
3. 同时记录 CPU 与墙钟、逐次样本、候选数、实际值数、元数据访问、解码数/字节、复制字节、分配数/字节、回调数、准入数及回退次数。区分逻辑读、BufferPool 命中、系统读与实际磁盘 I/O；嵌套区间不得重复相加。
4. 观测进程与无观测控制交替执行；默认观察扰动目标不超过 5%。超标时该观测不能用于百分比归因，改用低频采样或不计时工作量；不能放宽门槛迁就工具。没有 perf 时检查其他可用手段，明确栈、硬件计数或 I/O 证据缺失，不能虚构。
5. 基于 `tail-review.json` 复核 medium 两项 P95 回退并记录未解决原因：记录调度/缺页/CPU与墙钟差异，区分固定工作量膨胀和时间波动。只定向重测问题，不跑完整矩阵。
6. Kuzu 使用相同数据与查询核对计划、实际输入/输出行数、列访问和剪枝条件。PROFILE 仅用于解释，观测查询不能与无观测正式时间直接比较。

本机已尝试用户态硬件指令计数，`perf_event_open` 返回 ENOENT，记录见 `perf-counter-availability.json`。不能假装有指令/周期数据；可以用定向、不计时工作计数继续缩小范围，不为补证据反复跑全矩阵。

退出材料必须回答：当前最大的可消除成本是什么；证据质量如何；候选能消除哪些工作；预计端到端上限是否值得改造。用有依据的成本比例建立条件性模型，不能用“差距 100 倍”推导“优化空间 100 倍”。若只能证明局部小成本，应改变方向，不能进入大规模实现。

R0 未退出时，允许针对已确认的工作量热点开展可回退的小范围实现实验，以完整结果、相关模块测试和确定性工作计数验证假设；实验不计阶段进度，不视为 R1/R2 完成。精确耗时归因和尾延迟仍保留为未解决事项，最终 Kuzu 验收条件不变。

### R1：最小完整垂直实验

先验证全节点数值过滤计数，查询仍走公开接口和正常快照。目标是让算子直接消费已认证的类型化列块或有界解码块，减少 `emitColumn → appendScalarRun → seal → filter` 的中间重组。

列块契约必须明确：值类型与编码、行号映射、presence/NULL 位图、选择位图、快照和代次、缓冲区所有者、借用有效期、资源账户、取消检查位置、回退协议与错误传播。借用失效后不得继续消费；回调重入或异常不能重放已交付数据。预算必须在分配或交付前准入；允许按块摊销，不允许删除认证、取消或限额。

包含正常持久数据和更新后数据；不只实现无更新的内存数组循环。可采用借用视图或有界解码缓冲区，不强求“零拷贝”标签。对齐、多类型及生命周期不允许借用时，应清楚计入必要复制。

扫描端同时验证通用谓词下推与块裁剪：统计必须对应当前可见快照，更新/删除/类型变化后能够安全维护或失效。不能证明块内没有匹配时必须读取；NULL、缺失、混合类型、NaN 及比较边界遵守现有查询语义。不依赖特定标签或数据分布。记录裁剪前后候选、跳过块数、实际解码值数及统计维护成本，并用禁用裁剪的同路径结果交叉校验。避免把按块认证改成每个值重新扫描认证集合；同时保留旧快照和取消的正确性。

退出：完整结果相同、相关边界测试通过，且确定性计数证明整类重组/复制/逐值管理被消除或显著减少，而不是工作转移到另一层。实验失败要保留；禁止继续增加缓存层掩盖未减少的工作。

### R2：通用扫描与算子贯通

将已验证路径扩展到标签过滤、分组计数、多键分组。保持列式输入、选择向量和必要的延迟物化贯通，避免每层退回通用逐值属性对象。

若 R0/R1 显示重复定位仍主导，验证顺序扫描游标或列块目录，目标是让定位和认证主要随块/页数量增长；不得先假设新目录必然更快。物理布局调整需要明确读写成本、迁移和回退，不以扩大组大小代替证据。

若主要残余在分组算子，核对键构造、哈希、比较、字符串表示和分配后再选型。

已有分配采样提供了具体候选：`current-work/allocation-attribution.json` 中多键查询 493 个每 256 次分配的样本里，有 392 个紧邻预算资源的调用者是 PMR 字符串扩容，向上的调用栈还包含 `appendDistinctUint64`，表明分组键序列化是具体排查点；`src/query/execution/read_runtime/AggregateOperator.inc` 的通用多键路径逐行构造字符串键后查找分组。采样是分配次数而非耗时或字节比例，优化前须定向验证该路径的命中与成本。优先试验类型化复合键和无分配的临时查找，仅为新分组保存拥有的键，保留 NULL、类型比较、碰撞、资源预算和回退语义。不得按这四条查询文本、标签名或数据内容硬编码快路径。

退出：四类查询共享通用契约；密集/稀疏、缺失/NULL、混合类型、无序或重复请求及复杂值的回退语义完整。工作量对照必须包含快路径命中和回退比例，不能只报告理想分支。

### R3：生命周期、写入与空间代价

针对实际改动边界运行必要模块测试：旧/新快照、多轮更新、删除与标签变化、类型变化、复杂/大值、读己之写、取消、预算拒绝、重入、异常、原子发布、恢复、重开、旧 pin 释放后的回收及物理空间复用。不得为通过测试削弱 oracle。

覆盖超缓存工作集、稀疏/倾斜合成数据与未用于新候选调参的 holdout。已有 holdout 已被观察，须如实注明，不称其为盲测；若需新的盲测集，R0 时冻结后封存，不能测后选择。

记录打开/认证、离线转换、维护、峰值RSS、各资源账户、文件增长、写放大及旧版本保留；不能把逻辑回收当作文件截短。旧候选已有建边写入字节 +5.95%/+8.97% 和重复写延迟回退，新候选不能默认继承豁免。定位共同引擎与布局各自贡献，必要时用“同引擎、不同布局”定向隔离。

不跑全量单测。代码文件最多 3000 行，运行源码尺寸检查；保留 Linux/macOS/Windows 与 WASM 合同，未执行的平台不得写成通过。

### R4：一次正式窗口，清楚区分成功与失败

源码与必要测试稳定后执行一次同机三方窗口：当前冻结 ZYX、新候选、Kuzu；两库四项主查询，三独立进程、每进程三预热十正式样本，轮换执行顺序。固定单线程、CPU亲和性、64 MiB BufferPool、ZYX 64 MiB 查询物化预算、6 GiB 地址空间、2 GiB 文件限制；保留默认查询超时及原有语义。Kuzu 参数、结果消费与线程设置单列。

完整 oracle 校验全部样本；分别报告每进程中位数及汇总 P50/P95，不挑最好进程、不删除离群点。与旧时间跨窗口相减不能宣称新收益。守护与采用成本复用此窗口，失败只定向复核，不反复跑全矩阵找一次达标结果。

在 R0 退出、R1 实施前登记并冻结阶段性显著收益门槛、稳定性规则和预算；必须由成本模型支撑，至少同时约束总体几何平均和两库全节点过滤，不能只挑获益最大的查询。无法支撑质变目标时先修订设计，不以任意较小收益替代目标。

R0 已预登记阶段性显著收益门槛，详见 `benchmarks/architecture-design/decisions/20261027-column-block/intermediate-gates.json`：新候选相对同窗口当前控制，八项查询 P50 的几何平均加速至少 1.5 倍，且两库全节点过滤各至少 1.5 倍；汇总 P50 与三个独立进程 P50 的中位数均须满足。该目标不是收益预测，也不替代八项超越 Kuzu 的最终条件。

**本计划最终 100% 的性能条件固定为：八项主查询候选 P50 均不高于 Kuzu；候选 P95 相对 Kuzu 超过 5% 必须复核，可重复重大尾退化未解决不得验收。** 同时相对当前 ZYX 控制，主查询/点查/完整实体/邻接/属性修改/空操作/批量建边的 P50/P95、RSS 或文件成本超过 5% 必须复核。可重复重大退化必须修复，或在实施前冻结的采用范围内明确限制；不能测后缩小范围制造100%。

若未达到 Kuzu 条件，报告实际收益、剩余差距和阶段进度，保持 R4 未完成；旧的“方案完成但目标失败也记100%”不再使用。保留失败记录，按证据修订本页后再立项，不无限追加未经登记的候选。

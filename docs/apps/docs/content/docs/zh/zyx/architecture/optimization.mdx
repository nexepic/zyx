# COW 图数据库性能重构实施方案

更新：2026-10-22。计划标识：`cow-performance-20261019`。**本页是当前优化的唯一实施入口。新路线 R0–R7 共 24 项，已验收 21/24（87.5%）。按用户最新要求继续完成全部未完成项；原固定五项 R3.2/R3.3/R5.1/R5.2/R5.3 仍按既定合同推进，性能准入不提前计数。R7.3 仍是整体 100% 所需的最终收尾项。**

**最新验收（2026-10-22）：** R1.3／R2.3／R4.3／R5.2／R5.3已按完整窗口和最多两轮控制验收，总进度21/24（87.5%）。R3.3字段删除保护仍待关闭，R7.2／R7.3未验收；不把候选拒绝算作生产完成。默认格式31 ROW保持，覆盖／分段不自动采用，Kuzu目标未达到。详见`20261022-r7-five-path-admission/`及页末记录。

目标是在保留现有公开能力的前提下，减少每次查询和更新所需的定位、解码、转换、物化及元数据维护工作。保留现有引擎，进行有证据支持的局部结构性重构；不整体重写 backend，不承诺所有负载超过 Kuzu。

已完成的 S0–S6 为 **34/34**，只代表上一轮交付。其完整中英文文档、旧存储规范、发布导航和机器进度已按原始字节归档到 `benchmarks/architecture-design/archive/20261019-completed-s0-s6/`，`manifest.json` 保存来源和 SHA-256。旧 A/O/S 编号、过程百分比和当时的待办不再驱动实施。历史采用/拒绝记录仍是证据，不自动授予新布局生产准入。

## 1. 固定边界与执行规则

### 1.1 产品、持久化与兼容性

- 保持通用属性图、动态属性与类型、多标签、稳定逻辑 ID、现有 Cypher/QueryBuilder/GDS/Vector/Driver ABI 和语言绑定行为。只改变内部表示，不顺带删减能力或改变查询语义。
- 保持严格单文件：持久数据、恢复信息和支持的查询 scratch 均由同一数据库文件管理，不新增 WAL/SHM/临时 sidecar。
- 保留 COW 与 A/B Superblock。保持 data-before-root 和 durable acknowledgement；不引入 WAL、跨事务 group commit、不关闭同步或减少持久化保证。若未来小事务瓶颈证明需要改变协议，另立提交与恢复设计，不混入本路线。
- 保持逻辑/物理身份分离、快照、read-your-writes、完整性认证、统一分配、搬迁及安全回收。逻辑 ID 不复用；物理页/槽复用须验证身份与 generation。
- 公共功能兼容不等于文件字节兼容。当前开发期策略仍是新格式新建、旧格式明确拒绝，不自动迁移或删除用户文件。新增 codec/root 之前先更新[单文件存储规范](native-single-file-storage-plan)及兼容矩阵，不能悄悄改写旧版本含义。迁移器不在本轮必做范围；稳定格式发布前仍须确定迁移与备份合同。
- 保持 macOS/Linux/Windows 可移植及 WASM 非 JIT 路径。实际验证平台单独记录，Linux 成绩不能充当另外两平台实测。

单文件是物理包装，COW/WAL 是持久化机制，行列布局和批执行是访问机制。Kuzu 0.11 起使用单个主文件，但可创建 `.wal`、`.shadow`、`.tmp`（见[官方说明](https://kuzudb.github.io/docs/developer-guide/files/)）；不能用文件数量解释扫描差距，也不能由“用了 WAL”推断查询性能。

### 1.2 实施与文档职责

实施开始时核对远程 `work` 与本地改动；快进更新或在隔离工作树推进，不能 reset/stash 覆盖用户修改。冻结实际源码而非只记录 HEAD。每轮报告已验收任务、证据和剩余问题；提交/推送遵循会话中有效授权，不从历史批准推导任意新载荷授权。

只运行必要的受影响模块单元测试，不执行全量单元测试，覆盖率不是门禁。开发期间采用短小正确性/机制检查，不频繁跑 benchmark；完整规模正确性、长时间资源检查与正式性能对照集中在实现完成后的最终窗口。文档修改仅验证文档。`scripts/run_tests.sh --file` 只限制覆盖率展示，不能单独用它限制测试范围。

本页管理顺序、任务状态和准入；[单文件存储规范](native-single-file-storage-plan)管理现行格式；[能力矩阵](native-capability-acceptance-matrix)管理消费者和语义证据；[发布事项](native-remaining-work-roadmap)管理独立发布边界。设计决策放在 `benchmarks/architecture-design/decisions/`，本地原始结果放在被忽略的 `benchmarks/architecture-design/results/`，正式证据不能只存在于被忽略目录。

## 3. 目标结构与共同合同

```mermaid
flowchart TD
    Q["解析、绑定、逻辑与物理访问选择"] --> E["预算内批执行"]
    E --> O["结果所有权边界：API / Driver ABI"]
    E --> A["存储批接口：扫描、选列、批量点读、邻接"]
    A --> V["固定快照与事务内修改视图"]
    V --> D["属性子块、邻接、索引、大值"]
    D --> C["统一页管理、COW 与 A/B 发布"]
```

这些是职责边界，不要求新增同等数量的包装对象或第二套完整执行器。以下合同适用于所有阶段：

1. **身份与生命周期**：描述符包含足以验证的数据库/快照/布局/属性身份；批行引用检查 owner 与 incarnation。计划绑定和执行 pin 分离，明确 schema/布局变化的失效规则。借用值不能越过页 pin、批复用或事务生命周期；需要逃逸时复制并转移预算。
2. **语义**：保留缺失/存储 NULL/有效值的内部区别及现有 Cypher 映射、类型比较/哈希、溢出、重复次数、别名、ORDER BY、OPTIONAL、路径和关联子查询。易变表达式及副作用的求值次数不能因批处理、重试或下推改变。
3. **唯一权威与原子可见性**：属性、实体、派生索引、邻接、统计及退役信息按现有合同共同发布。物理页映射更新不能替代语义版本推进；当前图根 fence 不含所有物理目录，新增布局必须更新正确的语义 fence。
4. **错误边界**：仅对事先定义的可选优化额度拒绝回退。损坏、取消、I/O 错误和已开始输出后的失败不得捕获后重放输入或当作“无数据”。预交付拆批必须不重复输出，不改变错误语义。
5. **资源**：计入容量、嵌套载荷、索引、缓冲、pin 和逃逸输出，使用现有账户，不重复收费或提前退款。可计费内存与 RSS 分开。锁内不得等待必须靠同一锁释放的资源。
6. **有界工作**：列出单次定位、重编码、分裂、回收和重试的工作上限。不能将前台开销无限转移后台，也不能依赖无限增长的缓存、delta 链或日志。

## 4. 必须落实的实现合同

### 4.1 R1：贯通存储生产者与批消费者

复用现有 `BoundNodeScanBatch`、批身份、绑定程序和预算设施，扩展同一内部批合同。分别定义范围扫描和随机 gather，保留输入 ordinal、重复 ID、缺失实体及结果顺序；不能强迫点读扫描整组。批次由字节和行数双重限制，宽行/大值可缩小批次，不能固定大 reserve。

常见整数/浮点/布尔及字符串路径直接产生可被下游消费的数据；字符串先采用明确 owner 的偏移/字节区或等价有界表示。字典编码是条件性实验，不同字典的编号不能直接比较。动态复杂值保留等价且计费的回退。不得仅把 PropertyValue 数组再次复制成类型数组就宣布消除转换。

第一条必做贯通路径为 scan → filter/project → aggregate → owning output，覆盖数值过滤、字符串过滤、真实单/多键 group-by、COUNT DISTINCT 和空输入。分组键必须作为完整 tuple 比较；聚合状态的 NULL、数值类型、合并与错误规则沿用现有语义。不得把各列分别 DISTINCT 后组合成错误分组结果。

随后接入 Top-K/sort、join/expand 的适用批边界，并登记 UNWIND、procedure、subquery、mutation 读侧及其他消费者的批路径或有界适配器。每个保留适配器写明触发条件、数据所有权、预算、成本计数和退出条件。普通扫描过滤聚合不能整体退回旧行路径而声称贯通；复杂路径可以暂留明确适配器。已有 sort/DISTINCT spill 要继续可用。

平坦批为必做基线；因子化/分组中间结果、并行执行、SIMD、JIT 不作为这一阶段依赖。将来采用时另验重复次数、相关性和任务局部状态，不能用改变线程数掩盖单线程数据路径成本。

### 4.2 R2：精简读取元数据与认证路径

先按点查、扫描、邻接 gather 列出 token → owner/目录 → 路由 → 页 → 值的实际链路，区分调用次数、唯一页、缓存命中、codec 解码、校验字节、复制和 I/O。核查已有缓存及路由复用，禁止叠加含义重叠的缓存。

同一快照内按页归并定位、复用游标和已认证不可变页，恢复原 ordinal。缓存键覆盖数据库身份、逻辑页/路由身份、generation 与解析上下文；缺失结果只有在明确有效期时才缓存。文件增长、另一个合法句柄发布、搬迁、页复用和旧快照均有失效/隔离测试。文件大小检查只能在有等价边界与并发证明后合并，不能直接删除。

首次加载必须完成当前格式要求的认证；owner/generation/范围验证不能因缓存命中丢失。点访问验证已访问对象，完整 integrity 检查验证全局不一致；明确缓存期间外部破坏在哪个后续认证/完整性阶段发现，不承诺每次逻辑读取检测所有介质变化。

目标是让顺序扫描的定位工作趋近所访问的组/页，避免对每个值重复下降相同目录；保留随机点读的有界定位能力。R2 本身不改持久格式，若确需格式变更转交 R3/R4 的版本合同。

### 4.3 R3：有界混合属性子块与字段更新

**生产切换有条件，完整生命周期原型和成本验证必做。** 复用已有字段 set/remove、map 合并/完整替换和 overlay 语义；本轮解决其下层仍可能完整集合编码的问题，不重复实现字段暂存。

- 逻辑实体分组、物理页、压缩块和 COW 更新单元分别定义。旧 A3 的 64-ID 组只是已有候选，不是新性能结论；R3.1 用成本记录明确组容量、子块大小、稀疏阈值和单次工作上限，编码前关闭这些未决项。
- Node/Edge 分开；标签只表示成员关系。稠密且类型适合的字段进紧凑列，稀疏/混合类型进有界扩展；动态类型不变成永久 schema。每个 owner/token 在快照内唯一归属，扩展不再保存完整第二份行。
- presence、NULL、类型、存活信息必须明确编码。实体有实际字段枚举路径，完整读取按实际字段工作，不遍历全库 token 或整组全部字段。避免每实体/字段独立树和稀疏组独占大尾页。
- 大值独立存储且认证；小字段更新复用未变引用。选列读取不能解码无关大值；修改一值不能无条件重写整组/完整大集合。无需变化的索引不删建；no-op、类型变化、REMOVE、整 map 替换分别验证。
- 数据子块、归属描述符、成员枚举、图路由、索引、语义 fence、分配/退役在同一发布协议内切换。稳定逻辑页不代表语义版本不变。旧快照保持旧布局；重开、搬迁、删除和发布失败都有精确可达性与回收规则。
- 先用少量明确编码与显式有界转换。不得引入自动布局抖动、无界增量链或整容器重写作为默认更新。超出编码/容量条件时保留可用行布局，不丢字段。

R3.1 必须提交访问/成本表：单实体单字段、完整实体、N 实体 f 字段扫描、单字段修改、删除/回收，各自读取和 COW 哪些页。计入目录、owner 枚举、presence/type、部分填充、分配器、索引与旧版本空间。逻辑字段数 F、实体数 E、组数 G、组内字段种类 K 的增长关系要明确，尤其避免 O(E×K) 的稀疏成员元数据。

验证稠密/稀疏、独有字段、随机交错形状、多标签、持续变型、删除后稀疏组、宽实体/大值及邻居属性 gather。与同一批执行器下的现行行布局比较，不能把 R1 收益算成布局收益。原型缺少图路由、双向生命周期、退休或完整成本时不得生产准入。失败可完成比较项 R3.2，不能自动完成生产项 R3.3。

### 4.4 R4：有界 COW 写入与维护

复用当前不可变分支共享和回收批次机制。事务内同页/同树路径修改尽量合并，最终编码与索引更新基于实际变化；已经发布或被读者引用的页面不得原地修改。字段接口、实际页重写量和发布总量分别测量。

保持“写候选数据及元数据 → data fence → 写非当前 A/B 槽 → superblock fence → 确认”的顺序。恢复选最新有效根，处理 torn write、失败 sync 和不确定提交；有效根选择不代替全库 integrity。ID 预留、普通提交与维护发布分别计数，不把多次内部发布隐藏成一次廉价事务。

列出 catalog、allocator、页映射、索引、路由和 retire queue 的实际修改集合。目标是工作随变化页和必要共享路径增长；不对每次小写执行与无关存量成比例的重建。若某路径仍需全局扫描，必须登记触发条件、上限及为什么不能增量化。

前台/维护分别设页数、字节或时间预算，并报告积压、最老 pin、可复用空闲页和尾部可裁剪页。长快照阻止回收时提供背压/明确资源拒绝，不能回收活页或无界增长。碎片整理、物理搬迁和尾部缩文件分别验证；文件长度不等于活数据大小。不得用提高内存/文件额度、无限延后清理或强行要求每次关闭所有退休量为零来制造收益。

隔离合同保持现状。复用已验证的受限 blind rebase；不得仅删除图根 fence。若后续扩大范围，需另记录读/缺失/范围/约束/schema/端点依赖、验证点及重试上限；同页不相交写须在最新页重建或保守拒绝，不能覆盖对方修改，不能自动重放有副作用的语句。通用多写者和更强隔离级别不计入本轮承诺。

### 4.5 R5：邻接与访问计划

先定义可被批消费者直接读取的 EdgeId、NeighborId、TypeId、方向、可见性和 continuation 合同。保留多重边、自环、类型过滤、overlay 和顺序语义。对照为当前 key-only 树加已实现的批量主记录复用。

先比较覆盖 B+Tree 与共享分段邻接，不恢复退休的 per-node root/delta 实现。主 Edge 仍是拓扑权威；派生数据可直接读取的前提是原子维护、身份认证和明确的故障检测合同。必须逐项规定合法 checksum 但错误 endpoint/type、缺反向项、重复/孤儿项、陈旧 generation 在普通读取、提交还是 integrity 阶段检测。替代协议通过前保留当前主记录检查。

候选涵盖创建/删除、双向邻接、主记录、类型索引、统计、旧快照、重开和退役，不能只接读路径。覆盖树已满足目标时优先较小改动；分段方案必须抵消新增目录、更新和空间成本。随机插删、热点/幂律度数、超级节点和多跳是保护场景。

在既有优化器上补充实际需要的标签/type/属性选择率、度数分布或有界估计；明确统计身份、更新/失效、误差和退化策略。规划不能扫描全图收集统计。选择索引/gather/扫描、过滤时机、连接与扩展顺序时计入候选数量、列宽、页数、物化和内存成本；未知或陈旧统计保持安全且稳定的计划。只把受证明的语义等价重写下推，特别保护 LIMIT、OPTIONAL、NULL、重复及易变表达式。

### 4.6 R6：资源、生命周期与可观测性

复用现有资源协调和 scratch 实现，将新批、缓存、算子状态及输出纳入同一账户。批量预约可以摊销计费，但持有的容量必须持续收费，取消和异常必须归还。输出存活时间可以长于事务；零复制导致长期 pin 时须有有界复制/拒绝策略。

维持文件内 sort 和 DISTINCT/UNION spill。明确新批消费者是否支持它们；不支持落盘的 group-by/hash join 在超额时清楚失败，不能宣称通用外存执行。新增这些 spill 算法属于后续独立扩展，不以本轮 100% 暗示完成。

逻辑只读事务仅可在既有内部权限允许且文件可写时使用 scratch；物理只读绝不写 scratch。临时页使用查询 owner 与独立生命周期，不被无关用户长快照保留；scratch 与用户提交共享 allocator 更新不得互相覆盖。验证取消、磁盘满、崩溃重开、并发别名和 cleanup 重试。

扩展已有 EXPLAIN/PROFILE，显示实际访问路径、批/行适配器及原因、估计/实际行数、选择率、读取/解码/校验量、物化与预算峰值、spill 和发布阶段。指标注明单位、累计/峰值、包含范围和是否嵌套；关闭 instrumentation 的正式计时独立进行。

拆分超大实现文件时按绑定、算子、存储访问、预算与发布职责拆分，保留单一实现所有者。拆文件不是性能成果，不新增长期并行 backend；移除旧适配器前证明所有消费者已替换，并保留必要语义测试。

## 6. 验证与准入

### 6.1 基线、采样和工作负载

R0 冻结源码清单/dirty diff、构建选项、依赖、二进制 hash、硬件/OS、线程、buffer pool/查询预算、数据 seed/hash、格式、schema/索引、入口及结果消费方式。已有基线只有身份与条件全部一致才可复用，否则优化前补一次。保留正式对照二进制，不能从改过的源码重建后冒充 before。

R7 冻结后先完成必要正确性，再统一计时。基础热态每场景至少 3 个独立进程、3 次预热和 10 次测量；R0 预登记聚合方式、P95 不确定性、补测条件与总时间预算。小样本不保证尾延迟精度，不能反复测到通过。冷态、fresh-open、warm 分开；重启进程不等于清除 OS cache。同机交错运行来源，写案例从相同逻辑基线恢复，固定 open/commit/close 和 durability 的计时边界。

描述符绑定的目录 integrity 原型现按既有固定 map 流式校验：逐组检查64个 primary／存活位置，owner selector、列 presence、extension 归属及组计数必须一致；通过全 map 基数核对排除未登记 group 中的孤立目录项，无需全库 ownership 集合，逻辑键重复在回调前拒绝。inline canonical 及单字段 LargeValue 载体均不构造 PropertyValue；当前大值认证仍通过既有 read API 物化编码体，必须计入完整缓冲开销，流式大值校验及完整 Page Directory／退役版本遍历接入尚未完成。该只读原型不回收存储，也不启用非空布局路由。

当前原生页另有反向核对：每个 live typed slot 必须等于描述符绑定的 group／column／extension 精确 locator（含 slot generation），SlottedPage 空闲字节必须与 Page Directory 一致；目录正向遍历不可见的合法校验和重复物理记录会被拒绝。空页可在描述符移除后保留复用，存在 live 记录却没有描述符则拒绝。这仍是逐页原型，未安装完整全库恢复／回收流程。即便私有列图像为空，writer 也必须先复核源 fence，才能把语句视为已提交的 no-op。

逐页反查还可在认证不可变 manifest／引用完整身份后输出 LargeValue 引用，不读取正文；共享同一值的多个 owner 分别输出。回收必须合并全部 ROW／native 来源，出错丢弃不完整访问结果，并在退役前复核完整引用快照的 fence。测试覆盖同一64KiB账户下两个 owner 共享超过64KiB的编码值、回调中断退款重试，以及错误 manifest 哈希在输出前拒绝；此引用提供器尚未接入全局回收器。

独立字段 LargeValue 已补齐带账户的准备逻辑：单字段 PMR 编码与既有载体逐字节一致；基于真实源 pin 的内容索引查找保留正文认证和逐字节比较，共享引用不重复创建值，不同 token 不复用同一载体。新值仅提出同批 ID 及数据／manifest 页数，不消耗 ID、不写文件。编码体和引用随提案保留账户，额度拒绝、取消及异常可退款重试。仍须在最终 writer 中复核来源和复用引用，并将数据／manifest／内容索引／字段引用同批发布；不能据此验收 R3。

转换协调器已接入上述提案：在获取 writer 前附着内容索引，writer 内仅使用受 fence 保护的源 pin；超出字段页容量的 extension 转为真实单字段引用。已发布的合法单字段载体可复用；同一私有批次中新建的相同完整载体按字节合并，并由同一 MetadataWriteBatch 预留连续 ID，不把整个多字段 ROW 载体当成单字段值。引用编码、插槽追加及物理 owner 绑定各自保留必要缓冲预约。最新25个受影响模块、30个 suite 默认316/316、实验389/389通过（含8项既有去重／内容索引测试）；仅 Linux 验证，拒绝后源文件、根、ID及旧快照仍不变。此时大值仍是私有提案，尚未分配数据／manifest 物理池或进入最终发布；现有私有字段／索引池计数不包含这些待分配的大值池，完整成本必须另计。

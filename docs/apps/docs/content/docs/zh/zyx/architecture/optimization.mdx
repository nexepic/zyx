# 核心性能重构实施方案

更新：2026-10-23。计划标识：`core-cost-20261022`。**本页是唯一有效的优化实施清单。当前实施验收 100%；P1–P7 已完成。性能与 Kuzu 差距按实测报告，不代表已超越。**

本次验收遵循用户 2026-10-23 的最新要求：完成本页实现及必要验收，最后客观列出优化前／后／Kuzu 结果，不强制性能超过 Kuzu。完成率表示实施与验收工作完成度，不表示达到指定倍率；原 5 倍与 Kuzu 目标保留为实测观察，未达成必须明示。已有源校验、持久化、资源与空间门槛不放宽。

## 1. 聚焦范围与不变量

本轮只推进三条相关路径：**增量元数据提交、直接类型化扫描、复用上述机制的批量导入**。内存视图是前两条的配套机制，不另建通用缓存工程。

- 保留通用属性图、动态属性、多标签、稳定逻辑 ID，以及现有 Cypher、事务、QueryBuilder、GDS、Vector、Driver ABI 和绑定语义。向量扩维不在本轮范围。
- 保留严格单文件、COW、A/B Superblock、data-before-root 与 durable acknowledgement。禁止用关闭同步、降低校验、增加线程数或无限缓存制造提速。本轮不引入 WAL、group commit、LSM、JIT 或整体 backend 重写。
- 保留快照、read-your-writes、旧 pin、页面搬迁、安全回收、取消和统一资源预算。现有 sort、DISTINCT/UNION spill 不得丢失；不支持 spill 的算子须明确有界失败。
- 旧物理页不可原地修改。逻辑 ID、物理位置、generation 和快照身份不能混用。任何文件格式变化先更新[存储规范](native-single-file-storage-plan)，明确版本与旧库拒绝/迁移行为；不覆盖用户文件。
- 保持 macOS/Linux/Windows 可移植及 WASM 路径；实际验证平台单列。跨平台发布门禁归[发布事项](native-remaining-work-roadmap)，不得用 Linux 成绩冒充三平台验收。
- 只执行必要的受影响模块单元测试，不执行全量单测。`--file` 不是测试过滤器，必须使用具体 suite/test 过滤。文档变更只检查文档。

## 2. 剩余核心问题与证据边界

| 剩余问题 | 当前证据 | 接下来必须减少的工作 |
|---|---|---|
| 字段读取与表示 | P4 后 medium 过滤/分组仍需读取 100,000 个字段；独立 CPU 样本中解码、校验、身份检查和对象操作共同占用时间 | 字段定位、重复解码、通用值到类型列再回到行对象的转换 |
| 批量导入闭环 | 原修正基线 medium/holdout 导入约 276/214 秒；新路径尚无最终时延验收 | 逐行查改、重复发布、重复索引构造，以及批大小/临时空间/恢复成本 |

P1–P4 已验收的机制不再是待办。独立 CPU 归因见 `benchmarks/architecture-design/decisions/20261022-core-cost-read-cpu/`：热读以用户 CPU 为主，尚有约 28–29% 未归因/内部 libc，不能把全部时间归到目录。固定复制计数是 `sizeof` 总和，不是 DRAM 流量；内部 timer 不得相加。候选数量和复制量下降不等于达到 Kuzu 时延。

剩余源码锚点：`PropertyCollectionRootStore.cpp`、`PageBackedGraphReadAdapter.cpp`、`DirectPropertyColumns.hpp`、`LogicalPlanReadRuntime.cpp`，以及普通/批量写入协调器。正式基线以 `20261022-core-cost-p0/` 为准，历史 R7 成绩不能替代本轮基线。

| P1 | 变化路径驱动的路由更新 | 25% | 已验收 |
| P2 | 增量空间规划、原子发布和局部正确性证明 | 15% | 已验收 |

P0–P6 的已验收权重保持不变。P7 按本次新要求核验实际公开转换、完整目标的原子发布／拒绝、空间与资源准入、必要模块测试及最终客观报告；全部完成后获得最后 10%。仅改文档不增加进度，性能没有达到倍率不冒充已达到。

每轮报告：当前百分比、消除的工作、必要测试、剩余缺口和 Kuzu 目标状态。依用户授权，**仅进度增长时提交并推送远程 `work`**；进度不变不提交、不推送。先检查远程和工作树，不 reset/stash 覆盖用户修改。

只完成上述固定 P7 清单，不增加后续优化分支。全库空间至少节省 10%、预算、校验与持久化仍是采用硬条件；未通过就保留 ROW，不为强制采用而新增跨事务全库迁移协议。

## 4. P0：冻结测量与成本合同

### 4.1 修正比较条件

冻结当前实际源码、编译选项、引擎/探针 SHA、Kuzu 版本、CPU/存储、线程、内存预算、数据和 schema/index。主数据沿用 medium（225,000 节点、860,000 边）与独立 holdout（163,000 节点、772,000 边）。不得依据优化后结果选择数据。

- 私有副本在计时前完成文件复制和同步；两引擎准备一致，明确热缓存、重新打开与真正冷缓存的区别。只重新打开不称为冷缓存。
- 查询返回相同值、重复次数、NULL 和行数；写入使用相同操作与事务边界，计时包含 durable acknowledgement。区分纯操作、提交、完整端到端时间，不能只选较短者。
- 导入分别报告“生产批量导入”和“相同提交边界对照”；包含解析、数据/索引构建、提交及约定的最终持久化，不把 Kuzu COPY 与不同事务边界当作严格等价的底层对比。
- 不支持记 N/A；超时、资源拒绝和错误保留。必须比较的核心场景若无法等价测量，保持验收未完成，不删项或换成容易获胜的场景。

### 4.2 先定位再改造

每类只选择一个代表路径做有限剖析：普通 country 过滤/真实分组、单属性 SET、批量导入。区分用户 CPU、内核 CPU、等待；独立统计路由访问/构造、解码、分配/复制、算子计算、写页和同步。使用采样剖析或互斥阶段计时；不可相加嵌套 timer。追踪开销用不带追踪的控制说明，不作为正式延迟。

登记 `M`（总路由数）、`k`（修改路由数）、树高、唯一访问页、重复访问、实际 COW 页、元数据字节、同步次数、内存峰值。读取登记候选数、实际实体/字段数、批数和中间对象数。以小、中、大三个元数据规模固定 `k` 做机制检查，包含树高度变化和分裂边界；不把它变成全矩阵性能测试。

P0 输出具名成本预算、等价查询/写入合同、正确性 oracle 和一次修正后的基线。默认主场景固定为：普通标签过滤、真实分组、多键分组、单属性 SET、1,000 边批写、全量导入。补充点查、完整实体、邻接、no-op、删除、稀疏/大字段作为回归守护。

## 5. 已验收的增量提交合同

P1/P2 已完成，不重复实施。普通提交以排序去重的最终变化集合驱动 radix COW，变化叶与共享祖先各复制一次；估算和发布复用修改计划。所有权只检查变化池，空闲池链表/容量计数跳过满池，退休帧按最老 pin 代际回收。发布后交接不申请内存，缺少证明或源身份不一致时全量重建。

后续工作必须保留用户确认的“局部访问校验＋完整 integrity”合同：实际访问页和新路径完整校验，未访问分支的新损坏在首次访问或完整检查发现。旧快照、原子 A/B 发布、data-before-root、故障恢复与退款不可回退。首次建库、显式迁移、完整检查可以全量；普通提交不得重新引入全量收集或阈值触发的全图回收。

机制证据：`20261022-core-cost-routes/` 与 `20261022-core-cost-ownership/`。固定单项修改、3/300/900 个 Catalog 叶时，路由源帧为 2/4/5，所有权访问均为 6 次，普通全图遍历为 0。正式时延收益仍由 P7 验证。B+Tree 替换不属于当前待办，不自动扩大范围。

## 6. 已验收的读取视图与候选合同

P3/P4 已完成，不另建缓存或标签索引。热查找借用不可变 bootstrap/radix/Catalog/Allocator 页；保留既有 128 项/1 MiB 缓存、预算所有权、快照和 I/O epoch。写者继续私有 COW，逃逸结果按需要复制并转移预算。固定页对象复制计数下降 99.34%，不是时延结论。

标签访问复用既有 B+Tree、原子 TokenCardinality 和 Entity Map；按记录/键宽及最多 64 行的真实页局部性选择路径。全覆盖标签保持顺序扫描；候选仍验证主标签与所有标签。采样只用于成本判断；额度不足的回退必须发生在输出前，不能输出后重启扫描。多标签批不超过既有实体缓存上限，避免重解码。

证据：`20261022-core-cost-views/` 和 `20261022-core-cost-labels/`。medium 的过滤/分组从 225,000 个扫描节点降至 100,000 个认证候选；属性读取仍有 100,000 个，现已按 P5 直接入列。旧 pin、overlay、删除、rollback、重开及受影响模块已检查；最终生命周期与性能门槛由 P7 统一验收。

## 7. 已验收的直接类型化批合同

P5 已接入生产 ROW → 直接类型列 → filter/project → 单/多键真实 group → owning output。数值位与短生命周期文本视图直接进入有预算的类型列，复杂值/LargeValue/旧适配器保留具名 owning fallback；主场景没有完整 PropertyValue 矩阵或逐行属性 map。原生不可变身份在批边界认证，mutable overlay 动态检查与批 owner/incarnation 不可省略。

短字符串 kernel 先验证类型/长度再消费；缺失/NULL、空串、嵌入 NUL、混合类型回退、完整 tuple、数值类型/溢出、NaN 和 DISTINCT 语义保留。批级 COUNT 按逻辑值合并，不使用跨批字典 ID；瞬时表计费，额度回退只发生在聚合状态修改之前。每四个短字符串最多 256 字节的取消工作边界不扩大为任意长度字符串。返回值独立持有数据。

证据 `20261022-core-cost-direct/`：263 项必要模块测试通过；一个冻结基线上同样失败的、未修改的遍历优化器断言已单列。medium 过滤/真实分组各 100000 个文本直接入列、零 owning fallback，196 批；过滤计数更新 12500→196，真实分组更新 100000→1568，oracle 一致。字段根选读仍为 100000 次，不宣称已消除。

同执行器 ROW／紧凑字段块的历史合成原型仅隔离内存表示，不含真实目录、I/O、空间或生命周期。其样本保留为诊断证据，不能授权持久格式采用、增加进度或证明 Kuzu 目标；本轮实验格式的实际采用边界见第 9 节。

## 8. 已验收的有界导入合同

P6 复用现有公开批接口、区间 ID、按页实体/属性写入、有序索引修改及增量提交，不另建 backend、不提高额度。空插入目标也保留每种记录类型的完整性证明，绑定包含 generation 的精确物理 COW 根；本句柄维护，外部根变化必须失效。不能将“没有缓存目标”等同于“从未检查”。

同一已打开文件身份与数据库 ID 的句柄共享发布屏障/快照登记，guard 仍归本 registry。外部发布后先丢弃旧控制页缓存，再以持久根和全部 pin 重建缺失的本地分配/退休证明及 metadata ID 上界；自身所有发布同步源身份，普通单写句柄继续增量路径。打开/恢复不得回收其他句柄的旧快照。保留账户、取消、约束、索引、故障退款及 data-before-root。

证据 `20261022-core-cost-import/`：262 项模块测试通过。65 行整页批连续三轮，缓存命中 3、实体目录与全量 metadata 遍历均为 0；公开 API 1000 节点＋1000 边仅两个 ID 区间，重开后索引、分组及拓扑正确。其他句柄删除、20 次交替发布、驱逐旧记录缓存后旧 pin 读取、排空/完整检查均通过。单次输入/批大小/最终持久化边界仍按 P0 冻结合同，导入吞吐尚未正式验收。

## 9. P7：最终实施验收

### 9.0 固定验收清单

- [x] **公开 ROW→冷热混合布局转换。** 显式 `stageHybridPropertyConversion(..., coldRowRemainder=true)` 通过原 Native 协调器读取普通 ROW 源，不直接安装夹具；每组保持 64-ID／4096-membership，每次最多 8 组，共用 1 MiB 转换账户。
- [x] **完整指定目标先准备、后准入、一次发布。** 复用原私有 COW 字段／目录／LargeValue／metadata 规划，不引入跨事务中间根。指定 cohort 的所有组完成后核算整个数据库的稳态分配、退役／旧 pin 峰值及文件长度；只有全库至少节省 10% 且峰值在限额内才切换 A/B 根。拒绝、取消、额度失败与崩溃不得留下可见前缀。
- [x] **真实转换后的生产消费与生命周期。** 已补齐 Node／Edge 源、过滤／真实 group／长 ID 冷点查／重开、冷热修改／整列降级／LargeValue 同批发布、backend sealed 创建／删除、逆转换保留其余组、旧 pin、GC／字段池搬迁及退役、取消重试、A/B 部分／完整恢复与 integrity。
- [x] **最终必要模块验证。** 包含上述公开转换用例、既有生命周期／cohort／目录／格式回归和默认格式拒绝；不运行全量单测，不声称未执行的平台通过。
- [x] **最后一次统一性能矩阵与归档。** 沿用 P0 输入、oracle、三独立进程／每进程三预热十测量、原持久化及资源合同，输出全部场景的优化前／后／Kuzu、P50/P95、CPU／I/O／内存／文件观测与限制。

完整目标是本次显式指定 cohort，不是强制把任意大库全部转换。空间准入始终按整个数据库计费，不能将 cohort 自身节省比例冒充全库节省。窄数据或大库中的小前缀可能不具备采用资格；此时保持 ROW 是正确结果，不绕过门槛。若要另做跨事务的全库迁移工具，属于后续单独设计，不纳入本次固定验收。

### 9.1 不变的安全与资源合同

保留局部访问校验＋完整 integrity、data-before-root、原源 fence／实际 Entity／竞争 ROW、原代次／manifest、sealed 创建凭证、全部字段类型、旧 pin 与账户退款。普通变更全批保持 64 实际变化／迁移 owner、64 user replacements、64 总列计划；不按 namespace 或组重置额度。转换保持每组 4096 memberships、最多 8 组、共用 1 MiB；维护仍使用原有独立有界账户。

格式默认 5／31、显式实验 13／39，不能据实验功能宣称默认库自动采用。缺少空间准入时公开冷发布在 I/O 前拒绝。无 LZ4 时仍有 RAW 功能回退与空间判定，不承诺同样节省。4096 字节缓存的完整查询使用原有有界复制回退，不提高缓存或弱化校验。

### 9.2 性能只按实际结果报告

保留六个核心场景及全部回归守护，导入分别展示相同 1000 行事务边界对照和 Kuzu 生产 COPY；不把不同边界混为一谈。展示逐进程与合并 P50/P95、全部样本、失败与 N/A，不删除慢样本。三个导入的最大值不是可靠 P95。历史 CPU 归因不能冒充新 profile；文件峰值轮询不能冒充精确空间 census。

原 5 倍结构收益、Kuzu 优势与 5% 回归线均逐项对照并报告；本次完成不以达到倍率或超过 Kuzu 为前提。出现语义错误、安全／资源问题或稳定回归仍须修复，不能用新的完成定义掩盖。

### 9.3 最终交付

最后两项完成后标记实施验收 100%，按用户规则执行一次提交与推送到远程 `work`，随后停止，不追加优化任务。100% 不表示性能超过 Kuzu或所有数据库都会采用冷布局。

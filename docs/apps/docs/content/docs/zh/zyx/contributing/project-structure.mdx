# 项目结构

ZYX 是一个 C++20 嵌入式图数据库。当前存储实现是原生可重定位单文件格式；已退役的 fixed-record `FileStorage`、`DataManager`、segment-chain 和外置 WAL 实现不在源码树中，也不是兼容路径。

## 公开接口

- `include/zyx/zyx.hpp` 是 C++ 嵌入 API。
- `include/zyx/zyx_driver_abi.h` 是稳定的 C Driver ABI，Rust、Python、Node.js 和 WASM binding 都经由它接入。
- `bindings/` 包含各语言适配层。修改公开 ABI 时必须同步保持其所有权和生命周期契约。

## 原生运行时

| 区域 | 位置 | 职责 |
|---|---|---|
| Core | `include/graph/core/`、`src/core/` | Database 生命周期、Transaction、Value 和公开操作协调。 |
| Storage 边界 | `include/graph/storage/`、`src/storage/` | 逻辑图接口、backend 选择、跨平台 I/O、storage format 检查和 transaction overlay。 |
| 原生存储 | `include/graph/storage/relocatable/`、`src/storage/relocatable/` | 可重定位 page、directory、COW publication、A/B Superblock、integrity 检查、maintenance、index 和 LargeValue。 |
| Query engine | `include/graph/query/`、`src/query/` | Cypher parser、planning、optimization、逻辑 read/mutation runtime、procedure 和算法。 |
| API 与 CLI | `src/api/`、`src/cli/` | C++ API 实现、Driver ABI 和命令行接口。 |

`StorageIO`、`PreadHelper` 和 `PwriteHelper` 是 native 文件 I/O 的平台抽象边界。不得新增仅适用于 POSIX 的存储路径；必须继续支持 macOS、Linux 和 Windows。

## 测试和应用

- `tests/src/` 包含单元和组件测试；`tests/integration/` 包含端到端覆盖。CMake 会发现 `test_*.cpp` 并构建一个 `zyx_test_suite` 可执行文件。
- `apps/cli/` 是 CLI。`apps/benchmark/`、`apps/compare_benchmark/` 和各 calibration application 都应走当前公开/native 路径。
- `benchmarks/graphdb-comparison/` 包含外部对比 harness 及其 Python 测试。

新增测试必须观察公开行为或当前 native owner。不要重新创建已经退役的 fixed-record 实现细节测试。

## 构建和文档

- `CMakeLists.txt` 定义项目和 targets；`cmake/SourceSets.cmake` allowlist 当前 source，并拒绝已退役的存储路径。
- `scripts/` 包含 build、test、binding、release 和 parser generation 工作流。
- `docs/apps/docs/content/docs/en/` 和 `docs/apps/docs/content/docs/zh/` 分别是英文和中文文档根目录。修改面向贡献者的架构或行为时必须同步更新两者。

提交存储改动前，开发过程中运行相关的 focused test，并在最终验证运行 `./scripts/run_tests.sh --quick`。格式和迁移验收标准参见[原生单文件存储重构方案](/zh/docs/zyx/architecture/native-single-file-storage-plan)。

### Admitted binding relocation: d68459f6

Windows ordinary output stops immediately after DirectPropertyColumnsTest, before the next BoundProjectionReferencesTest suite completes; no full termination stack is in this log. The previous 17 isolated PlanCache cases now all pass, so this must not be re-labelled the old PlanCache crash.

Source review finds another actual termination hazard: internal records contain `std::pmr::string` and implicitly move during vector growth. MSVC's allocator-less string move is declared noexcept yet calls `_Alloc_proxy`; a rejecting PMR resource can therefore terminate instead of propagating bad_alloc. See [MSVC xstring](https://github.com/microsoft/STL/blob/main/stl/inc/xstring), allocator-less move and `_Construct_empty`. The runner reports MSVC 14.51.36231. The source reference establishes the implementation mechanism, not an exact native stack for this run.

Slot, property and parameter records now preserve the original allocator during copies. MSVC iterator-debug relocation deliberately copies these small bounded compiler records so a later failure leaves the old entries intact; other STLs/release retain their prior move path. Slot hash keys are constructed directly using allocator-aware piecewise construction, removing the unnecessary intermediate string. No public result representation or ABI is changed. A new every-growth-failure test checks all allocation failure positions, existing names/IDs, retry, live upstream bytes and complete refund. Native confirmation that this eliminates Windows exit 3 remains outstanding.

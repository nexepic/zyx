# LOAD CSV URI and path lifetime

The macOS full sharded CI failed `ChargesHeaderMapLinksAndBucketsBeforeConstructingRows` at the CsvReader field-vector limit instead of at its required conversion-stage rejection; the separately isolated run passed. `scripts/run_test_shards.py` sets TMPDIR to a deeper private shard directory, and the fixture derives its absolute file URI from TMPDIR. The test's budget boundary did not include the variable URI/path lengths. In the previous implementation URI, resolved filesystem path and source path remained live and charged for the entire reader lifetime after the file had already been opened.

The runtime now creates the reader in a nested scope, destroys those no-longer-used URI/path temporaries, refunds exactly their charge, and sets the reader's buffered-byte limit to the then-available budget before parsing headers. The path validation and file open still occur while the path charges are retained. The input-row charge is preserved. No query limit, map-conversion rejection assertion, path validation or callback behavior is weakened.

The existing test adds a 96-character directory component to exercise the sharded-path condition even when run alone; the original budget formula, error-stage assertion, zero-delivery check and successful retry remain. A paired Linux incremental link used the same test objects and same production archive in both binaries, replacing only LogicalPlanReadRuntime.cpp.o with builds of the pre-change and post-change source. The old code failed the target because field-vector admission occurred first; the new code passed. The new binary passed the CsvReaderTest and LogicalPlanLoadCsvRuntimeTest suites, 68/68. Their XML files are in recovery/evidence/2026-11-04/csv-path-lifetime-{red,green}.xml and csv-lifetime-regression.xml.

This is a same-input, single-production-translation-unit comparison using earlier incremental objects; it is not a clean full build or native macOS/Windows CI. A hooks-disabled syntax check of the changed runtime also passed. Other platform budget and prefetch issues are not resolved by this change.

# Native selected-property admission check

The exact-once fake-reader test added in d95d2adb was part of the projected-property ownership/charge handoff work. Its fixture defaulted `enable_property_read_admission` to false and that test did not change it; the originating patch does not state why. A separate existing fake-reader test, `PrefetchRetriesRetainPendingRowsAndPreservePartialCachesAndOrder`, explicitly covers pressure retries without admission. Neither test was removed or weakened.

Native snapshots advertise property read admission and transaction overlay snapshots report their base capability. The existing `NativeSnapshotAdmissionAndPrefetchPreserveRetryOrderAndCancellation` tests node and edge callbacks, rejection/retry and logical values. This checkpoint adds a separate native ROW test using six distinct 3,000-byte strings, 4,096-byte tight and 100,000-byte ample logical materialization limits. It checks a source callback rejects a two-owner read before admitted source bytes exceed 4,096; the query returns each distinct value once; selected-value decode count is six; source admission occurs; and the observed execution-local logical budget peak remains within each limit. Linux observed logical peaks were 3,537 and 23,810 bytes respectively.

The two named native tests passed 2/2 using a separately rebuilt test translation unit linked with prior incremental production objects (XML: recovery/evidence/2026-11-04/native-selected-admission-linux.xml). This is neither a clean same-tree build nor macOS/Windows validation. The counter is selected values decoded, not a per-owner physical disk-I/O trace; the logical peak is not an independent allocator or RSS peak. Passing this admission-capable native test does not repair or prove the non-admission fallback, which retains the separate red evidence in 2026-11-04-prefetch-no-admission.md. No existing test, memory bound, or assertion was removed or relaxed.

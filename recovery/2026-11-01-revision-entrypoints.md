## Additional evidence: derived and low-level Property batches

At 9a3260a0 the direct `EntityPageStore` derived-state overload supplements missing graph intent and missing changed-owner keys from actual logical entity/Property plans. The existing entity-plus-derived-index case now asserts one graph increment; a new direct derived Property test asserts the graph and owner revisions in the same publication. Default planner selection passed 49/49 (`/tmp/zyx-derived-intent.xml`, excluding the separately known real-pool-growth failure).

At fb524073 the metadata graph coordinator establishes its graph revision before encoding owner entries whenever explicit changed-owner intent or `logical_graph_change` is present. The extended `NativeGraphPageTransactionPublishesEntityAndPropertyDirectoriesTogether` test carries owner-only intent through the low-level coordinator and verifies both versions; a same-tree focused selection passed 4/4 (`/tmp/zyx-owner-intent.xml`). Typed raw page/route methods may also serve physical maintenance, so callers must identify semantic intent and exact owners; merely observing a replaced page is insufficient.

Repository search found a separate streamed **edge write** entrypoint; the similarly named NodeStream in `src/api/DatabaseImpl.cpp` is result delivery, not a node write. Bulk node inserts appear to pass through normal mutation executor/planner, but full higher-level ingestion call graph and token behavior remain to verify rather than declaring a dedicated node streaming path absent.

At 4fc196ec, same-tree default selection passed 29/29 (`/tmp/zyx-bulk-vector.xml`): all 27 `NativeGraphWritePlannerVectorTest` cases, `GroupsBulkNodeInsertionsByBoundedEntityPageTargets` with new assertions for one graph/schema increment on 600 nodes and an old pin, and `StreamedEdgePublicationAdvancesGraphAndNewSchemaRevision` including reopen. API `DatabaseImpl` bulk node writes call `createLogicalNodes`; the backend converts them to `LogicalGraphMutationBatch` and invokes the normal executor. This is evidence for that bulk path, not proof about every higher-level importer or direct raw vector operation. Direct vector net-noop classification remains unresolved.

## Direct entity and typed Property route entrypoints

At e1b11535, `EntityPageStore::allocate`, `append`, and `insert` explicitly mark logical graph changes at the same metadata publication; `update` compares the typed Node/Edge record and marks only a real change. `erase` uses the existing graph batch. `evacuate`, pool reclamation and other physical maintenance remain unmarked. The explicit semantic mode of `RelocatableMetadataStore::upsertEntityPropertyLocations` stamps every caller-supplied changed owner and converts supplied erasures into versioned tombstones; default mode remains a physical route primitive. Callers must supply only semantically changed owners when choosing that mode. Other raw metadata defaults remain unresolved for concurrent semantic use.

Same-tree default validation after test-data correction 550216bd: 95/95 selected tests (`/tmp/zyx-direct-entity2.xml`), including direct create/append/insert/update/noop/delete and old snapshots, direct typed Property semantic upsert/deletion/tombstone, low-level changed-owner publication, and the planner group. The first run was 94/95 because the fixture ignored two arguments and the intended changed record was actually identical; the corrected test varies a real label.

At b971bb8f, mixed core and test objects were rebuilt together; 14/14 selected tests passed (`/tmp/zyx-current-mixed.xml`) for ROW/column roundtrip, changed-owner ABA, blind rebase, vector/property snapshot, streamed edge and direct batch/index tests. That mixed result predates e1b11535 and must be rerun for the later source.

At a6e776a4, explicit logical Property route publication validates each input sequence and merges changed live routes with deletion tombstones in directory-key order. The lower-level contract requires the caller to name only actual semantic changes. Same-tree default selected coverage passed 121/121 (`/tmp/zyx-route-order.xml`), including two owners where the erased key sorts before the updated route, old pin, and prior direct entity/index/batch tests. The conservative physical fence remains active. The current mixed/default results do not close standalone raw vector/page/root semantic-intent audit, full SCAN or broader end-to-end acceptance.

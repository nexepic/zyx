## Additional evidence: derived and low-level Property batches

At 9a3260a0 the direct `EntityPageStore` derived-state overload supplements missing graph intent and missing changed-owner keys from actual logical entity/Property plans. The existing entity-plus-derived-index case now asserts one graph increment; a new direct derived Property test asserts the graph and owner revisions in the same publication. Default planner selection passed 49/49 (`/tmp/zyx-derived-intent.xml`, excluding the separately known real-pool-growth failure).

At fb524073 the metadata graph coordinator establishes its graph revision before encoding owner entries whenever explicit changed-owner intent or `logical_graph_change` is present. The extended `NativeGraphPageTransactionPublishesEntityAndPropertyDirectoriesTogether` test carries owner-only intent through the low-level coordinator and verifies both versions; a same-tree focused selection passed 4/4 (`/tmp/zyx-owner-intent.xml`). Typed raw page/route methods may also serve physical maintenance, so callers must identify semantic intent and exact owners; merely observing a replaced page is insufficient.

Repository search found a separate streamed **edge write** entrypoint; the similarly named NodeStream in `src/api/DatabaseImpl.cpp` is result delivery, not a node write. Bulk node inserts appear to pass through normal mutation executor/planner, but full higher-level ingestion call graph and token behavior remain to verify rather than declaring a dedicated node streaming path absent.

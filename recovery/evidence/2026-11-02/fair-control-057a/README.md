# Owner cleanup cost: isolated control, 057a8563

This is a new narrow experiment, not the unavailable dfd0e33d historical baseline. Both binaries use the same 057a Release -O3 hooks-off core and same harness object, on Linux x86-64 / Clang 19.1.7 with CPU affinity 0. The control substitutes one backend object differing only by disabling the call to reclaimDeletedPropertyOwners after a successful delete; it does not reclaim owner tombstones, is behaviorally different, and is not production code. The enabled binary retains the normal bounded cleanup. The control is not merged into the source branch. `nm` found the cleanup reference in the normal backend object and none in the experimental control object.

Each fresh database starts with 64 owners and performs 128 cycles of deleting one owner and creating a replacement with a 256-byte property; all 64 surviving values, all deleted nodes and an integrity scan are checked after timing. There are no long-lived snapshot pins or concurrent clients in this experiment. Twelve alternating AB/BA paired rounds per variant completed with no failed checks. Pair throughput means 170.325/s control and 158.846/s enabled (enabled minus control -11.479/s; paired 95% t interval [-15.648,-7.310]); deletion mean 2.942 vs 3.343 ms (difference +0.400 ms; interval [0.312,0.489]); deletion p95 per-run means 4.386 vs 5.388 ms (difference +1.003 ms; interval [0.755,1.250]). This is observed overhead for this delete-heavy workload, not a claim of historical regression, general production overhead, speedup, or semantic equivalence. Final file size was 1,572,864 bytes in each short run; this is not evidence that long-run space is bounded or that cleanup shrinks files.

Initial control compilation failed because a copied source lost a relative include path; adding the original backend source directory to the include search path compiled successfully. `control.patch`, successful build command/log, harness, runner, raw per-run logs and results are included. Temporary run databases were created only under script-owned temporary directories and removed after the checks.

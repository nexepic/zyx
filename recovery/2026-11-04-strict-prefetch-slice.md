# Strict admission prefetch slice — incomplete

User authorized dropping compatibility for backends that cannot admit selected property payloads before reading. This candidate changes only the batched property-prefetch path in PlanInspectionAndBatching: it rejects a non-admitting source before node/edge column access and removes that path's owning-vector fallback. A new unsupported-source test showed the baseline read and delivered one row; the candidate rejects before source property read or delivery. The existing tight/ample exact-once fake test now explicitly enables its supported admission capability and passed alongside the new test (2/2). These Linux binaries link the rebuilt runtime/test objects against an existing incremental archive, not a clean same-tree build.

The admission-capable DirectEdge test fixture was then made the default, while the unsupported test opts out explicitly. Rebuilding the 14 directly including test translation units and running the full DirectEdge test suite produced 183/191 pass. The earlier fixture-default-false run produced 141/191. The eight remaining failures involve error/read ordering, malformed cardinality, point-versus-column count and public visitor read-ahead checks; none of those assertions or budget limits were changed. Their real contracts must be preserved or explicitly strengthened rather than weakened to make the suite green.

This is not a complete strict admission contract: other query paths still have fallbacks; selected source-wire admission is not decoded-heap admission; native still decodes an owner twice on a failed batch at 6000 bytes; edge and overlay semantics, strict partial ownership, Windows budget failures and ASan RSS remain unresolved. No platform CI, performance result or full-suite success is claimed. Do not push as a completed fix.

This is not a clean full build, a native-platform result, or proof that every remaining fallback and native retry has been fixed.

# Revision codec work in progress

This branch is an isolated implementation workspace based on `5d75600c`; it is not ready to merge or push. The Superblock now has independent nonzero graph/schema revision fields in checksummed payload bytes. The temporary version constants distinguish this experimental layout from this baseline's existing variants; they are not the lost final format version, and the final latest-format-only policy still requires unifying/removing old selectors and migration paths. No graph/schema publication, owner revision, snapshot binding, ABA protection or recovery integration is implemented by this checkpoint. Do not rely on the constant initial revisions for conflict checking.

An independently built codec test passed its new revision round trip and nonzero checks. The entire Superblock selection ran 16/17: the existing `IsolatedCompactCohortRejectsPriorPrototypeSlotsWithoutMigration` hardcodes the old default version 31 and fails against the new prototype version. Do not blindly update that test; revise it only as part of establishing the final single latest format and its unsupported-format tests. Full suite has not been run on this branch.

A further local prototype adds explicit graph/schema intent to `MetadataWriteBatch`: each candidate increments the corresponding revision once, rejects uint64 overflow, and preserves revisions without an intent. The narrowly isolated scripted-allocator test passed 1/1, but was linked with the baseline core archive for unrelated dependencies and is not an integrated same-tree validation. No production callers mark intent yet; snapshot fences are still physical. More work is essential before merging.

Added a same-batch publication test that expects old root/revisions after a prepublication interruption and new root/revisions after publication. Added guards rejecting revision marks after publication. The test and implementation pass syntax checking, but have not yet been run in an entirely same-tree linked binary. These are still infrastructure only, not transaction or owner-ABA integration.

The ordinary ROW Property planner now passes explicit graph-change intent for plans that are not `EPRMPK_NO_CHANGE`, and the common graph metadata batch marks that intent before publishing. A new backend test checks graph revision advancement, same-value stability, an old physical snapshot and reopen. The two modified production translation units and backend test passed syntax-only compilation; this slice has not yet been built or executed against a coherent complete tree. It is intentionally incomplete: node/edge creation/deletion, scalar indexes, streamed writes, hybrid/SCAN paths, schema changes, snapshot fence use, owner revisions and ABA remain unwired. Do not merge this branch as a functional revision implementation.

An owner-revision codec prototype packs the 64-bit field into the Property entry's previously constrained generation-high and free-byte words, preserving the 32-byte entry and 126-entry page. Point, sorted and traversal conversions carry it. A codec round-trip test has been added and modified translation units pass syntax checks, but it has not run in a same-tree build. This remains incomplete and unsafe to use for ABA: no writer stamps the revision, no empty-property tombstone is represented, zero owner revisions are still accepted for baseline callers, reclamation and hybrid/SCAN are not integrated, and the storage layout and format selectors remain provisional.

At `4c663527`, the clean `build-coherent` same-tree build initially failed at final link because `ZYX_BUILD_APPS=OFF` excluded REPL symbols required by tests. Reconfiguring `ZYX_BUILD_APPS=ON` and incrementally rebuilding succeeded. A 72-test focused run on the resulting same-tree binary passed 67 and failed 5: the two owner ABA tests, graph fence/config test, schema identity test, and the historical hard-coded format fixture. `RowPropertyPublicationPersistsLogicalRevisionOnce` passed; Property directory codec 9/9 and MetadataWriteBatch 26/26 passed. Unknown-format rejection remains covered and passes. This does not satisfy latest-only, schema publication, owner tombstone or ABA requirements.

A subsequent prototype propagates schema-change intent from System Catalog creation of new property/schema tokens and creation/deletion of index/constraint definitions through the native transaction to the same metadata write batch. Configuration-only writes do not mark this intent. A new backend test checks new binding advancement, unchanged values/configuration, old snapshot and reopen. The modified planner, commit, catalog and test translation units passed syntax checking, but a coherent rebuilt binary has not yet run this test. Streaming token publication, rollback/failed statement behavior, schema identity use and owner ABA remain unverified and unwired. This branch remains unsafe to merge.

At `4bb327ec`, a same-tree two-job incremental build of `zyx_core` and the isolation test object succeeded. A freshly linked test executable passed `RowPropertyPublicationPersistsLogicalRevisionOnce` and `SchemaRevisionTracksNewBindingsButNotConfigurationOrExistingValues` (2/2). This validates the ordinary ROW and normal Catalog-intent examples only. Streaming bindings, rollback/failed statement behavior, actual schema identity, ordinary graph fence, owner revisions/tombstones and ABA remain unwired; the branch is not mergeable.

A further unverified ROW-only prototype now keeps a Property-directory tombstone on semantic transition to an empty collection, stamps explicitly changed owner keys with the batch graph revision, preserves unrelated owners' revision, and compares the owner revision for bounded blind writes. Ordinary location lookups hide tombstones while the dedicated revision lookup retains them. Codec validation accepts nonzero-revision tombstones without changing record size. The modified translation units passed syntax-only checks; no same-tree build or runtime test has yet established this works. Graph changes outside ROW property plans, owner deletion/recreation and cleanup, hybrid/SCAN, low-level callers, schema identity and whole-graph fence are still not integrated. It must not be merged or used as a complete ABA fix.

Same-tree `f4a02922` focused run: 15/18 passed, including both previously failing ROW owner ABA cases, ROW revision/reopen, schema revision example and 9/9 leaf codec tests. Three other blind-write cases reached integrity checks but failed because the scanner compared a physical route against a structure with an implicit zero owner revision. The following WIP change compares the exact physical fields separately and bounds the owner revision by the pinned graph revision; it still requires coherent retesting and does not establish complete ABA coverage.

## Windows termination

Both the isolated process and the ordinary suite terminate in `NativeReadSessionTokenBudgetTest.OwnedCanonicalPropertyCodecMatchesExistingWireAndRollsBackFailure`. The ordinary suite recorded 38 failing case endings before termination at 370/603 suites; this is not a complete suite result. Its stress run passed 6/6. The 29 isolated budget failures are a subset, not 29 additional failures.

The codec allocates map-ordering scratch from the caller's exhausted PMR resource. MSVC's allocator-only vector constructor is `noexcept` but allocates its iterator proxy. A denied proxy allocation therefore terminates instead of reaching the codec's prefix rollback. Microsoft's upstream `stl/inc/vector` allocator-only constructor and `_Alloc_proxy` support this mechanism; the exact CI executable stack remains unsymbolized. The uploaded artifact could not be downloaded because the configured proxy returned HTTP 403; that operation was stopped, without an alternative-route attempt.

The fix selects a fallible empty count constructor, retaining all actual allocations and charges. The same allocator-only pattern was audited in production PMR-vector paths and changed consistently. A cursor of non-default-constructible frames uses the fallible empty initializer-list constructor instead. An initial build exposed the count constructor's default-construction requirement for that cursor; this was corrected, not hidden. Existing range and nonempty count constructors are unchanged. The regression enumerates every nested-map scratch rejection for both `bad_alloc` and `ResourceAdmissionDenied`, checking unchanged prefix, exact refunds, canonical output and retry.

Two other Windows fixture defects have independent evidence:

* The bound CSV test formed `file://C:\...`, whereas the existing parser requires local drive URIs of the form `file:///C:/...`. The test now uses generic separators and the correct prefix, preserving import-root checks.
* The reopen resource test inspected usage while its moved-from result was still alive. Windows reported exactly 48 additional bytes, matching the three live iterator proxies. It now checks both live result owners, then destroys the moved-from source before checking the sole retained owner and final refunds. No budget was changed.

## Crash-child runtime isolation

The ASan gate passed 710/711 cases. The failed vector-manifest crash case did not reach its durable marker; its child had already terminated with signal 9. No ASan/UBSan memory violation was reported. The assertion obtains that status before destructor cleanup, so the ordinary intentional cleanup kill does not explain it. Signal 9 alone cannot identify OOM or its sender.

POSIX previously used `fork` and ran arbitrary C++ directly in the child. This inherits the parent's heap, sanitizer runtime and possible thread-held locks. The harness now uses `posix_spawn` and the existing child command dispatcher, matching Windows' fresh-process behavior. Child coverage output is directed to `/dev/null`; publication hooks, markers, kill points and recovery assertions remain unchanged. A parent-state regression fails with the old fork implementation and passes with the fresh process. This establishes the isolation improvement, not that macOS signal 9 is solved.

After backend destruction, active bytes were 6333948 while RSS remained 534970368. This separates live requested bytes from runtime/allocator retained memory, but does not attribute every byte of RSS. Neither the guard nor sanitizer settings were relaxed. A safe production fix is not established.

An independent allocation-churn improvement was identified in the final external-sort cursor: moving the entire decoded record to each output also moved its ordering-key vector, which was then cleared/freed. The next decode allocated another key vector. `takeOutputRow` now moves only the owning row and ordinal; the authenticated ordering keys stay in the cursor's existing fixed workspace. The next decode reuses their array. Ordering validation and the previous-key comparison still execute for every record, and output rows do not borrow cursor storage. The workspace already reserves bounded current/prior records and merge buffers; the existing maximum decoded-record check is retained. A regression checks 100 successive row handoffs, stable key-array storage and independence of an earlier owning result. This removes per-output key-array allocation; it is not a measured macOS RSS fix.

Windows budget traces also show genuine source/result overlap and potentially copying vector growth. For example, Dijkstra's 24576-byte limit encounters source 5855, result/output 14622, relocation upper 7135 and requested backing 160. These cannot safely be made to pass by deleting proxy fees or raising limits. Exact owner lifetimes and actual MSVC heap measurements remain needed before changing that code or its success boundaries. The other native tight-budget failures and the local-versus-parent exception-priority failure are not claimed fixed.

## Saved evidence and exit semantics

`run_ci_evidence.py` wraps the existing portable process-tree/timeout runner. Each invocation retains checkout/event SHA, command, safe diagnostic-option whitelist, start/end times, requested/effective supervisory timeout, raw child exit/signal, bounded output and XML presence/parse state. Early job cancellation can leave the initial `running` record and incomplete XML; those are explicitly not passes. The wrapper never maps a nonzero test exit to success. Optional diagnostic steps keep their original continue-on-error behavior; mandatory unit/stress/sanitizer gates remain mandatory.

The output file retains an 8-MiB prefix and, if necessary, a 1-MiB tail. Console output retains a 1-MiB prefix and 64-KiB tail with truncation notices. Known-budget and PlanCache cases run in separate processes with separate log/XML/status directories. The existing 17 PlanCache cases, 12 Windows budget filters and 6 macOS filters remain discoverable. A new ASan diagnostic group independently runs its 3 previously failed native budget cases and the 3 public-result map admission tests; it cannot replace the full gate. The full sanitizer filter retains all prior suites and adds `ResultPropertyMapAdmissionTest.*`.

Unit/stress pass the existing `--xml-dir` and `--failure-log-dir` options. POSIX CI shards use the same bounded relay, preserving their own raw prefix/tail in `shards/bounded`, even if the enclosing tier times out. Supervisory shard logs/status live outside disposable source/fixture workdirs. Timeout/interrupt paths retain available output before removing those workdirs. Single-process Windows output is retained by its outer wrapper and XML is written to the explicit shard path. Missing/malformed XML is reported as incomplete evidence, never as zero failures.

All three jobs upload `ci-diagnostics-<platform-or-sanitizer>-<attempt>` with `if: always()`, retention 14 days. Evidence excludes database fixtures, profiles and arbitrary environment dumps. The existing Stage10 artifact remains separate. Metadata records actual configured compiler/version, OS/architecture, whitelisted CMake flags, module sizes and SHA256. Abnormal native exits request matching Windows image/PDB copies only when their combined size is at most 512 MiB. Missing/oversized/locked symbols are explicitly reported; one locked file does not discard other metadata. Apple dSYM collection is not implemented, so runtime symbolization and module identity remain important limitations for unresolved Apple addresses.

Commands share an evidence deadline measured from the preparation step: 35 minutes for the 40-minute TSan job, 85 for 90-minute ASan, 355 for the default 360-minute build job. The same deadline applies to dependency installation, build and long test/calibration invocations. It reserves approximately 5 minutes for metadata/upload without arbitrarily giving Conan a separate shorter limit. A command that cannot finish within the remaining supervisory window fails124; it is not skipped as a pass. Actual query timeouts and resource limits are unchanged. Setup/checkout delays, forced cancellation, uninterruptible processes or runner loss can still prevent upload; `always()` is best effort, not a guarantee after the job's hard termination.

## Budget observations

The fixed 512-entry owner registry assigns opaque IDs without exposing addresses or adding fields to production owners. It is active only for explicitly enabled test diagnostics. Entries are retired at owner teardown, including an environment-disable transition, so pointer reuse gets a new ID. Registry lookup/update uses a fixed lock; formatting occurs after that lock is released, and resource-denial formatting is outside the process resource mutex. Capacity exhaustion suppresses diagnostics with a clear marker and does not alter admission.

Materialized, prepaid and hierarchy records expose owner/account IDs, requested/retained/maximum/available/peak counters and refunds. Final owner summaries are labelled `before_member_release`: for example a prepaid grant can still be fully charged until its grant member is destroyed. These logical/admitted byte counters are not malloc/RSS measurements. Detailed events are capped 40 per owner/400 per process; pressure summaries 80, successful summaries 20, truncation notices 20. Omitted counts and registry/summary limits are explicit. Independent per-case processes reset caps for known failures, including sanitizer budget cases, rather than consuming all available traces in the full gate first.

## RSS observations

`ResidentMemoryDiagnostics.hpp` samples before the guarded sort, at rejection before unwinding, and after the test's local backend is destroyed. It never replaces QueryGuard's actual RSS sample or changes its 64-MiB allowance. macOS uses `TASK_VM_INFO` resident/internal/external/reusable/compressed/footprint counters, checks kernel status/count before using revision 1 fields, and reports unsupported APIs explicitly. Field availability was checked against [Apple's XNU task_info header](https://github.com/apple-oss-distributions/xnu/blob/main/osfmk/mach/task_info.h); this is source review, not an SDK build or kernel execution.

Optional weak-import sanitizer interfaces report live/mapped/free bytes and accumulated allocator/quarantine/StackDepot statistics when available. The large statistics path is deliberately not executed before the RSS baseline, avoiding a statistics-only warm-up. Linux emits bounded status categories for local verification. Counters overlap and are sampled at different instants; they must not be added together or substituted for actual RSS. The total process reports are capped 24, with a truncation marker. They contain counts only, no property values or database pages.

## Fork safety review

The crash-test harness forks without exec. A new diagnostic spin lock could otherwise remain inherited as locked by an absent worker. Source `e09a9ef0` registers POSIX at-fork callbacks at test entry, before creating test resources/threads. Preparation synchronizes with registry writers; the parent retains its state, while the child resets the fixed registry, bounded counters and process-qualified opaque ID namespace. The child callback performs no allocation or output. Windows only initializes its process ID namespace; no fork callback is compiled there. No product admission or resource-owner layout changes.

An independent probe reproduces the old inherited-lock hang (child SIGALRM, expected negative exit 10); the initialized probe passes plain, ASan+UBSan and TSan. The unified binary passes 73 focused tests including the worker-held-lock fork regression and real graph crash cases with tracing enabled. These are Linux measurements, not native Windows/macOS certification or whole-database sanitizer runs. Probe source, command/result JSON and logs are in `fork-contracts`.

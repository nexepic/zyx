# Query-owned property retry candidate

The native six-owner, one-property, 3000-byte fixture reproduces nine decodes at a 6000-byte materialization limit on the e514de96 runtime. The synchronous cell candidate transfers completed owning values into private query-charged rows before a later source admission refusal. The normal pressure split retains those rows, so the same six values decode six times. No new backend CACHE retention is used. The limits remain 4096, 6000 and 100000 bytes.

Before adding an explicit resumable-cell capability to the interface, the standard same-tree Debug -O0 -g0 binary passed 1283 relevant tests. The new visitor-exit/snapshot test and six-owner test subsequently passed 2/2. The capability addition and a subsequent atomic reservation handoff rebuilt successfully; the final same-tree binary passed 1284/1284 related tests, including the snapshot/refund case. Source-to-row credit now uses splitOff/absorb on the same budget, not refund followed by re-admission. Failed cache admission restores the transferred reservation. These local operations do not open an uncharged interval in the shared parent account. It requires each emitted cell to be independently authenticated and permits private retention only for the caller's own admission refusal, with no consumer effects until successful completion. Native advertises it; unchanged overlays forward it. Changed overlays, edges, multiple keys and repeated bindings remain on their existing matrix paths and are not claimed solved.

With identical test objects and all other objects held constant, replacing only the runtime translation unit with its e514de96 implementation gives data.read_bytes of 204800/253952/229376 for tight/retry/ample. The candidate gives 204800/229376/229376. Retry saves 24576 data bytes; normal tight/ample reads do not increase in this Linux fixture. This is not a universal physical-IO or throughput result. Logical peaks are 3636/4134/24024, within the unchanged limits; these are not RSS measurements or proof of all allocator domains.

The lifecycle test checks visitor stop, visitor exception, concurrent publication through the same backend while an old snapshot remains active, and a fresh snapshot observing the new value. A one-byte hierarchical account separately checks pre-delivery rejection and complete refund, without assuming an empty STL container allocates. The same 6000-byte local materialization contract is used for the snapshot cases.

An initial version tried to require the shared-account query to succeed at 6000. Both baseline and candidate refused before property reads. A throw interceptor resolved the failing request to NativeReadSession's empty PMR deque<PropertyCacheKey> construction: 5792 bytes held plus a 504-byte deque node exceeded 6000. This startup allocation is separate from retry decoding, and its optimization remains open. The regression does not encode Linux empty-deque behavior as a cross-platform expectation.

Remaining limits: the handoff source estimate is not a general decoded-capacity/RSS contract; multi-key/edge/changed-overlay retry behavior is not covered by this slice. Windows and Apple native validation, final full-suite/stress validation, and the remaining procedure accounting/RSS failures remain outstanding. No push or CI trigger has occurred in this phase.

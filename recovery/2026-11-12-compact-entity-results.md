# Compact physical entity values and bounded result retention

Follow-up to Build #241 (`dc2db2386`) and evidence HEAD `c00a7d4e0`. No push or CI request is authorized.

## Contract and confirmed physical waste

`QueryResult::getRows()` returns a const reference to the complete vector of public unordered maps. `ResultValue::VariantType` and its const-reference accessor are public. Streaming or paging cannot transparently satisfy that same retained-result contract at a lower final footprint. The original 300-row/256 KiB gather therefore cannot be repaired solely by splitting transient source batches under the old representation. The same coarse old-layout floor proves the four-row/2304-byte CSV nested-sort and two-row/1500-byte pagination materialization assertions impossible on that representation (3584 and 1792 bytes respectively, before buckets/proxies/payloads).

Further inspection found a smaller compatible source-level correction: physical `Node` contains a private unused `padding[PADDING_SIZE]`, and physical `Edge` contains a private unused `typeBuffer[TYPE_BUFFER_SIZE]`. Neither array has a reader/writer. The large alternative inflates `ResultValue`, each public hash data node and its separately allocated sentinel. Both entity serializers/deserializers write/read metadata fields individually and never access these arrays; their 256-byte record-slot constants are separate from actual packed bytes.

The correction removes both unused arrays. It preserves all public types, variant alternatives/accessor signatures, value ownership/copy behavior, metadata fields, record-slot constants and serialized field order. It adds no indirection, sharing, borrowed result or new allocation. C++ object sizes change, so C++ consumers must rebuild; this is not a promise of compatibility with previously compiled C++ objects. Opaque driver ABI and serialized formats are unchanged by construction and will be regression-tested.

A standalone compiler comparison using the configured Linux compiler/STL, the old headers from `c00a7d4e0`, and the new headers reports Node 320→152, Edge 320→136, ResultValue 328→160 and result pair 360→192. Both record slots remain 256. The utility statically verifies that the public VariantType remains exactly the same five alternatives. These are Linux measurements, not native Windows measurements. Native one-entry and two-entry inert-layout allocator probes now print actual structural requests and a 300-row final structural floor; the earlier two-entry probe remains available and its per-probe counters reset.

No budget, payload shape, alias independence check, semantic exception or gate was relaxed. New Node/Edge regressions check compact memory, fixed record-slot size and independent packed v2 byte fixtures (Node 86 bytes, Edge 77), including stream and Node buffer roundtrips.

## Bounded publication and quota lifetimes

Non-sorting vector publication now owns a bounded private batch before executing its first operator. The first Project/Filter prefetch occurs in this private phase; the append phase receives an explicit prepared flag so it does not repeat that prefetch. Only tagged byte/quota denials may halve the private batch, after prepared rows unwind. No projected output, DISTINCT set, SKIP/LIMIT counter or published result is replayed. Source semantic errors, lock errors, cancellation and ordinary allocation errors escape. The same snapshot and original hit order remain pinned.

An advisory check leaves space for a projected row frame, its declared binding nodes/alias storage and operator counters before handing a multi-row private batch onward. It uses current parent headroom and compiled structural sizes; actual allocations continue to admit independently. Single-row batches skip that sizing preference and retain their mandatory admission/error behavior.

After a projected row replaces its old cache, a per-row reconcile guard runs only after the temporary projected row has died. It settles grants against still-live row/cache structures instead of retaining obsolete source/scratch grants until the entire batch ends. Vector capacity and every surviving key/value/proxy remain funded. Intermediate strict-owner tests exposed a 144-byte projection request with only 120 bytes of shared account headroom while earlier cache grants remained; the new 300-row regression failed before this settlement and passes after it.

Consumed hit storage is physically destroyed before updating its retained source charge. The remaining empty vector proxy is still charged; initial hit accounting now includes its actual proxy/alignment request rather than capacity alone. A final single row needs no further split source and may release hits before prefetch; larger final batches retain the retry source until private preparation succeeds, then release it before result publication. Sort/TopK paths that may reread hits keep their source.

Two regressions retain complete semantics: a source `domain_error` after single-hit release is propagated once and the same producer can retry cleanly; 300 descending hits with distinct property names return all rows in order under the unchanged 256 KiB QUERY account. Their escaped result stays charged until destruction, then the account/database return to zero. The latter records Linux escaped-account bytes 105332, released hit bytes 4800 and account peak 262104 of 262144. These are admission-account measurements, not RSS or native Windows measurements.

Five denial fixtures needed correction after their previous small inputs genuinely fit the compact representation. No quota or assertion was removed/raised: shortest-path and bare-node denial payloads now exceed their fixed allowance by an independent final pair/string lower bound; their original positive payloads are restored. Metadata denial uses three 2100-byte labels (payload alone exceeds 6000), then restores 1500 for the original 8000-byte positive case. Pagination denial retains six scalar maps under the original 1000-byte limit; its original two-row positive window and 1500-byte limit remain intact. Semantic-error identities and exact messages remain tested before those denial-only data changes. The unfiltered regression found one further denial fixture whose 12000 scalar results now fit the Linux layout: DISTINCT spill cleanup. It retains the original 8 MiB cap and 24000/12000 input/result counts, and uses a 700-character output alias so independent retained key characters alone require 8400000 bytes, above 8388608. It additionally checks actual scratch write calls before validating disk/account refunds and retry; the focused denial and null/order positive cases both pass. No memory allowance is raised.

## Remaining physical-floor constraints

For the prior Windows ABI, removing padding predicts physical Node/Edge sizes 176/160 and ResultValue 184 (not yet natively measured). The one-entry inert map probe will measure rather than assume this. Under that projected layout, a single populated map still needs 640 structural bytes. Four row headers/maps alone need 2880 bytes before keys/metadata, above the CSV fixture's 2304. Two numeric maps plus mandatory vector/column/key proxies and metadata also predict at least 1576, above pagination's 1500. These are model-based residual constraints, not newly observed native outcomes.

The diagnostic now prints one-entry actual allocator requests and retained scalar floors for all three relevant quotas, including observed short-key storage and result metadata. Low-level `LogicalPlanReadRuntime` currently uses a logical retained-row estimate without a resource account and takes the actual heap maximum when an account is supplied; a green unowned test must not be treated as proof of the complete physical bound. This existing mixed-accounting contract is not silently rewritten here. If those two success assertions are required under a complete physical hard cap, the choices remain the existing streaming visitor (retaining the same quota and correct materialization rejection) or a further result-representation change. They are not claimed fixed by the present reduction.
